# 槽位 `#/slots` —— 逐区块规格（DESIGN.md 第 5 章之一）

> 先读完 `DESIGN.md` 全文再读本文件。令牌、共享组件签名、文案原则、写入边界都在 DESIGN.md，这里不重复。
> 规格里写了的元素一个都不能少；没写的细节按同一套令牌补齐，不要自己加区块、加文案。
> 凡是写了 `data-*` 属性、`id`、`aria-label` 的地方，交互检查会用到，**名字和取值不能改**。

本页节奏：`bg-page` 上一张通栏白卡片（槽位表格）；全部停用时表格上方多一条黄色提示条。
本页核心动作：看每个池的占用，停用 / 启用，上下移动调优先级。
本页最重要的区块：L3 槽位表格（含 L4 占用格子），允许写得最长。

**交互**：点击 = `taskFilterStore.applyFromOverview({ status: "queued" })` 后 `navigate("/tasks")`。`aria-label`「公共排队 {n} 个，查看任务」。

**状态 / 响应式**：无。

**文案**：公共排队。

## L2 全部停用提醒 `features/slots/AllDisabledNotice.tsx`

**外层**：`snapshot.pools.length > 0` 且每个池 `enabled` 都是 false 时渲染 `<div data-all-disabled className="overflow-hidden rounded-lg border border-line">`，里面 `<Banner kind="warning">所有池都已停用，没点名的任务派不出去</Banner>`（Banner 自带的下边框在这里去掉：外层已有边框，给 Banner 包一层 `[&>[data-banner]]:border-b-0`，或直接在这里写同样结构不带下边框）。

**文案**：所有池都已停用，没点名的任务派不出去。

## L3 槽位表格 `features/slots/SlotsTable.tsx`（最重要的区块）

**外层**：`<section data-slots-table className="min-w-0 overflow-hidden rounded-lg border border-line bg-panel">`，里面 `<div className="overflow-x-auto">`，表格 `min-w-[1040px] w-full`（shadcn `Table`）。

**元素**：表头一行（`h-10`，`text-12 font-medium text-fg-3`，底边 `border-line`），十列从左到右：

| # | 表头 | 宽 | 单元格内容 |
|---|---|---|---|
| 1 | 优先级 | 64px | `font-mono text-13 text-fg-2`：`pool.priority` |
| 2 | 渠道 · 模型 | 最小 240px | 第 1 行：`font-mono text-13 text-fg-1`「{channel} · {modelName}」，单行省略、`title` 全文；第 2 行：`text-12 text-fg-3`「{label}」+ 空格 + `font-mono`「{id}」；停用时第 1 行后面跟一个小片「已停用」（`ml-2 inline-flex h-[18px] items-center rounded-sm bg-hover px-1.5 text-11 text-fg-2`，标记 `data-disabled-tag`） |
| 3 | 占用 | 最小 220px | `<SlotMeter pool={pool} />`（L4） |
| 4 | 已用 | 88px | `font-mono tabular-nums text-13`：「{running} / {capacity}」；`running > capacity` 时 running 部分 `text-st-failed` |
| 5 | 点名排队 | 88px | `font-mono tabular-nums text-13`：`queued`；为 0 显示「—」（`text-fg-3`） |
| 6 | 24 小时成功率 | 120px | 第 1 行 `font-mono tabular-nums text-13`：`formatPercent(recent.completed, recent.completed + recent.failed) ?? "—"`；第 2 行 `text-11 text-fg-3`：「完成 {completed} · 失败 {failed}」，失败数大于 0 时「失败 {failed}」这一段 `text-st-failed`；两者都为 0 时第 2 行不出现 |
| 7 | 平均耗时 | 96px | `recent.avgRunMs === null ? "—" : <Duration ms={recent.avgRunMs} />` |
| 8 | 今日用量 | 最小 150px | 第 1 行 `font-mono tabular-nums text-13`：`formatTokens(usageToday.totalTokens)`；第 2 行 `text-11 text-fg-3 hidden xl:block`：`<UsageBreakdown usage={usageToday} />`；为 0 时第 1 行「—」、第 2 行不出现 |
| 9 | 启用 | 72px | shadcn `Switch`，`checked={显示用的 enabled}`，`aria-label="启用 {id}"`，`data-pool-toggle={id}` |
| 10 | 顺序 | 88px | 两个 28×28 的图标按钮（shadcn `Button variant="outline" size="icon"`，`h-7 w-7`）：`ChevronUp`（`aria-label="{id} 上移一位"`，`data-move-up={id}`）和 `ChevronDown`（`aria-label="{id} 下移一位"`，`data-move-down={id}`），间距 `gap-1`。第一行的上移、最后一行的下移用 `invisible` 占位（保持对齐，不可聚焦、读屏不读） |

每行：`<tr data-pool-row={id} data-enabled={enabled ? "true" : "false"}>`，高至少 64px，单元格 `px-3 py-3 align-middle`，行间 `border-b border-line`（最后一行没有），悬停 `bg-hover`。停用的行：第 2～8 列文字换成 `text-fg-3`，占用格子不透明度 0.4（L4 负责），开关和顺序按钮保持正常颜色。数字列右对齐（4～8 列 `text-right`）。

**数据**：`snapshot.pools`（顺序就是优先级）。显示用的顺序和启用状态 = 服务端数据叠上「本地覆盖」（见交互）。

**交互**：
- **启用**：开关从关到开 → 直接调 `useSetPoolEnabled().mutate({ poolId, enabled: true })`。
- **停用**：开关从开到关 → 不立即改，先打开 L5 确认框；确认后调 `mutate({ poolId, enabled: false })`；取消则开关保持开。
- **上移 / 下移**：用当前显示顺序算出新顺序（和相邻一行交换），调 `useReorderPools().mutate(newIds)`。
- **请求进行中**：发出请求的那个开关 `disabled` 且 `opacity-60`；有任何顺序请求在进行时，所有上下移动按钮 `disabled`；启停请求不挡顺序按钮，顺序请求也不挡别的开关。
- **本地覆盖**：请求成功后，把返回结果（启停返回改后的池视图，排序返回全部池视图）记成本地覆盖：`enabledOverride: Record<poolId, boolean>`、`orderOverride: string[] | null`；显示时覆盖优先。快照推来的数据和覆盖一致时清掉覆盖（避免成功后、新快照到之前开关闪回旧值）。请求失败：清掉覆盖（页面回到服务端的样子），`queries.ts` 的钩子已经负责弹出失败提示。
- 键盘：开关空格切换；按钮回车触发。

**状态**：
- 快照还没到：表格主体画 4 行骨架（每行 64px，第 2 列 180×14 的 `Skeleton`，第 3 列 200×16，其余列 40×14）。
- 没有任何池（配置不允许，但要画）：`EmptyState message="还没有配置模型池"`。
- 断线：照常显示，开关和按钮 `disabled`（`connection !== "open"` 时）。

**响应式**：表格固定最小宽度 1040px，窄于这个宽度时在卡片内横向滚动（外层 `min-w-0` 已给）。< 1280 时第 8 列的第 2 行隐藏。

**文案**：优先级、渠道 · 模型、占用、已用、点名排队、24 小时成功率、平均耗时、今日用量、启用、顺序、已停用、完成 {n} · 失败 {n}、还没有配置模型池。

## L4 占用格子 `features/slots/SlotMeter.tsx`

**签名**：`{ pool: PoolView }`（区块内部组件，允许接收参数）。

**外层**：`<div data-slot-meter={pool.id} role="group" aria-label="{id} 的占用：已用 {running}，容量 {capacity}" className={pool.enabled ? "flex items-center" : "flex items-center opacity-40"}>`。

**元素**：排布用 `lib/slotMeter.ts`（地基路从第一版搬来的纯函数）：
1. **离散格**（`capacity ≤ 24`）：每格 10×16px（`h-4 w-2.5`）、`rounded-[var(--r-slot)]`、间距 2px（`gap-0.5`）。
   - 被占的格：背景 `projectColorVar(该苦工项目的 colorIndex)`（从 `snapshot.projects` 按 `slot.projectKey` 找；找不到用位置 0）；正在重试的格再叠 `.hatch`；超出容量的格（`running > capacity` 时多出来的那几格）加 `outline outline-1 -outline-offset-1 outline-st-failed`。
   - 空格：`bg-meter-track` 加 `inset` 1px `line-strong` 描边（`ring-1 ring-inset ring-line-strong`）。
   - 格子顺序按 `pool.slots` 的顺序（服务端已按项目成段排好）。
2. **连续分段条**（`capacity > 24`）：宽 220px、高 16px 的 `bg-meter-track` 圆角条，里面按项目分段，每段宽度 = 该项目占用数 ÷ 容量 × 100%，段间 2px 缝，颜色同上；重试的段不画斜纹（段是按项目合并的）。

**交互**：
- 每个被占的格（或每段）用 shadcn `Tooltip`，内容三行：① `ColorDot` + 项目名（`text-12 font-medium text-fg-1`）；② 标题（`text-12 text-fg-1`，最多 280px 宽、单行省略）；③ `text-11 text-fg-3`「{roleLabel} · 」+ `<Duration from={slot.startedAt} />`，正在重试时再加「 · 正在重试」（`text-st-warning`）。连续分段条的提示卡只有两行：项目名、「{n} 个」。
- 被占的格可聚焦：整组只有一个格子在 Tab 序列里（`tabIndex=0`，其余 `-1`），左右方向键在被占的格子间移动焦点，聚焦时同样出提示卡；回车或点击 = `navigate("/tasks/" + slot.workerId)`。每格 `aria-label`「{项目名}，{标题}，{roleLabel}，{已跑时长}」，标记 `data-slot={slot.runId}`，重试的加 `data-retrying`。
- 空格不可聚焦、没有提示卡。

**状态**：`capacity === 0`：画一条 220px 宽的虚线空条（`border border-dashed border-line-strong h-4 rounded-[var(--r-slot)]`），后面跟「已暂停」（`ml-2 text-12 text-fg-3`）。

**文案**：已暂停、正在重试、{n} 个。

## L5 停用确认框 `features/slots/DisablePoolDialog.tsx`

**签名**：`{ pool: PoolView | null; onCancel(): void; onConfirm(): void; pending: boolean; error: string | null }`（由 `SlotsTable` 控制开关，`pool` 为 null 时关闭）。

**外层**：shadcn `AlertDialog`，内容框 `data-disable-dialog`、宽 400px、`bg-overlay rounded-lg`，遮罩 `bg-scrim`。

**元素**：
1. 标题（`AlertDialogTitle`，`text-14 font-semibold`）：「停用 {id}？」
2. 正文（`AlertDialogDescription`，`text-13 text-fg-2`）：按两个数拼：`running > 0` →「还有 {running} 个在跑，会跑完」；`queued > 0` →「点名它的 {queued} 个任务会一直排队到重新启用」；两句都有时用「；」连起来；两个都为 0 时不渲染正文。
3. 出错时正文下面一行 `text-12 text-st-failed`：`{error}`。
4. 按钮行（右对齐，`gap-2`）：「取消」（`variant="outline"`）；「停用」（`bg-st-failed text-on-brand hover:brightness-110`，标记 `data-confirm-disable`）。`pending` 时「停用」按钮前加 `LoaderCircle animate-spin-slow` 14px，两个按钮都 `disabled`，点遮罩和按 Esc 不关闭。

**交互**：点「停用」调 `onConfirm`；成功后由 `SlotsTable` 关闭框；失败时框不关，显示错误。点「取消」、Esc、点遮罩（不在 pending 时）调 `onCancel`。打开时焦点落在「取消」。

**文案**：停用 {id}？、还有 {n} 个在跑，会跑完、点名它的 {n} 个任务会一直排队到重新启用、取消、停用。

## 本页交互检查会找的东西

演示数据的池顺序是 dsf、glmf、qwen27、luna（见 `design/演示数据.md`）；具体数字从演示数据单测取。

| 位置 | 操作 | 断言 |
|---|---|---|
| `?demo=busy#/slots` 的 `[data-pool-row]` | 数一数 | 4 行，依次 dsf、glmf、qwen27、luna |
| `[data-move-up="dsf"]` | 查 | 不可见（`invisible`）；`[data-move-down="luna"]` 同样不可见 |
| `[data-move-down="dsf"]` | 点击 | 等 1 秒后行顺序变成 glmf、dsf、qwen27、luna，第 1 列依次 1、2、3、4 |
| `[data-pool-toggle="glmf"]` | 点击 | 出现 `[data-disable-dialog]`，正文含「还有 {busy 场景 glmf 的在跑数} 个在跑」 |
| `[data-confirm-disable]` | 点击 | 框关闭；`[data-pool-row="glmf"]` 的 `data-enabled` 为 `false`，行内出现 `[data-disabled-tag]` |
| `[data-pool-toggle="glmf"]` | 再点击 | 不弹框，直接变回启用 |
| `[data-slot-meter="dsf"] [data-slot]` | 数一数 | 等于 busy 场景 dsf 的在跑数；其中 `[data-retrying]` 的个数等于 dsf 的重试数 |
| `[data-slot-meter="dsf"] [data-slot]` 第一个 | 聚焦后按回车 | 地址变成 `#/tasks/<那一格的苦工编号>` |
| `[data-shared-queue]` | 读文字 | 含 busy 场景的公共排队数 |
| `?demo=disabled#/slots` | 打开 | 出现 `[data-all-disabled]`；4 行的 `data-enabled` 都是 `false` |
