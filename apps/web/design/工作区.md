# 工作区 —— 页面层规格

> 站点层规格见 `../DESIGN.md`（令牌、共享组件、数据层契约、分路表），本文件只写这一页的逐区域规格。实现会话不得修改本文件。
> 数值一律来自令牌；本文件里写的像素值都能在 `src/styles/tokens.css` 找到对应令牌，找不到的就是本文件特意写死的布局尺寸。

## 0. 页面骨架（地基路）

```text
<TipProvider>
  <div .app>                          高 100vh，纵向弹性布局，overflow hidden，背景 --bg-page
    <AppBar />                        R1，高 --appbar-h
    [Banner offline]                  R2，连接状态为 lost 时出现
    [Banner config]                   R2，snapshot.configError 非空时出现
    <CapacityStrip />                 R3，flex: none；最大高 40vh，超出内部滚动
    <div .main>                       flex: 1；min-height: 0；两栏网格 var(--sidebar-w) minmax(0, 1fr)
      <aside .sidebar>                背景 --bg-panel；右边 1px --line；纵向弹性；min-height: 0
        <ListToolbar />               R4
        <ProjectList />               R5，flex: 1，纵向滚动
      </aside>
      <main .detail id="detail-scroll">   背景 --bg-panel；纵向滚动；这是详情和时间线共用的滚动容器
        <WorkerDetail />              R6、R7，内部渲染 <Timeline />（R8）
      </main>
    </div>
  </div>
</TipProvider>
```

- 启动：`pickDataSource(location.search)` 只创建一次；`subscribeSnapshot` 写入 `snapshotStore`；`selectionStore.selectedId` 变化时调用 `workerStore.open(id)` / `close()`。
- 连接状态为 `lost` 时，`.main` 和容量条区的不透明度 0.6（提示条不变暗）。
- **首次加载**（快照为 null）：容量条区显示骨架（R3 状态）；左栏显示骨架（R5 状态）；右栏空白。
- **一个苦工都没有**（快照已到、`workers` 为空）：`.main` 不分两栏，整块渲染 `<EmptyState message="还没有苦工" command='fleet run "任务"' />`。
- **窄屏**（< 1024px）：`.main` 变单栏；`selectedId` 为 null 时只显示 `.sidebar`，否则只显示 `.detail`（R6 头部出现「返回」按钮）。
- 页面整体不出现横向滚动。

## R1 顶栏 `AppBar`（地基路）

1. **外层**：`<header data-appbar>`，高 `--appbar-h`（40px），左右内边距 `--sp-4`，背景 `--bg-page`，下边 1px `--line`，横向弹性、垂直居中、间距 `--sp-2`。
2. **元素**：
   - 标志：14×14 的内联 SVG，2×2 四个 6×6 方块，间距 2px，圆角 1.5px；左上、右上、左下三块填 `--text-1`，右下一块只描 1px `--text-3` 边（像一条还没占满的容量条）。`aria-hidden`。
   - 产品名「fleet studio」：`--fs-13`，字重 600，`--text-1`，字间距 0.2px。
3. **数据来源**：无。
4. **交互**：无。
5. **状态**：无。
6. **响应式**：不变。
7. **文案**：只有「fleet studio」。右侧不放任何东西。

## R2 提示条 `Banner`（地基路）

- 连接断开：`<Banner kind="offline">连接已断开，正在重连</Banner>`。
- 配置有错：`<Banner kind="config">配置文件有错，正在使用上一份有效配置：{configError}</Banner>`（整行单行省略，`title` 放全文）。
- 两条同时出现时 offline 在上。样式见站点层 4.3。

## R3 容量条 `CapacityStrip`（L1，最重要的区域之一）

### 1. 外层

`<section data-capacity aria-label="模型池容量">`，背景 `--bg-page`，内边距 `--sp-2 --sp-4 --sp-3`，下边 1px `--line`，最大高 40vh、超出纵向滚动。每个池一个 `PoolRow`，顺序同 `snapshot.pools`。

### 2. `PoolRow`

`<div data-pool={pool.id}>`，网格 `grid-template-columns: 176px minmax(0, 1fr) 208px`，列间距 `--sp-5`，上下内边距 10px，`align-items: start`；除第一行外上边 1px `--line`。

**第 1 列 · 池的名字**

- 第 1 行：池编号，等宽，`--fs-13`，字重 600，`--text-1`。
- 第 2 行：池显示名，`--fs-12`，`--text-2`，单行省略。
- 第 3 行：模型名，等宽，`--fs-11`，`--text-3`，单行省略，`title` 为全文。

**第 2 列 · 计量条 + 图例**

- 容量 ≤ 48：`SlotMeter`（见 3）。容量 > 48：`SegmentBar`（见 4）。容量为 0 且没有在跑：画一条高 `--slot-h` 的空轨道（`--meter-track` 底、1px `--line-strong` 虚线内描边、圆角 `--r-slot`），轨道上居中文字「已暂停」`--fs-11` `--text-3`。
- 图例 `PoolLegend`（`data-pool-legend`）：计量条下方 8px，横向弹性换行，行间距 `--sp-1`、项间距 `--sp-3`。每项：`ProjectDot`(8) + 项目名（`--fs-12` `--text-2`，最大宽 160px 单行省略）+ 该项目在这个池的在跑数（等宽 `--fs-12` `--text-1`），三者间距 `--sp-1`。顺序同 `slots` 里项目出现的顺序；只列有在跑苦工的项目；池里一个在跑都没有时不渲染图例。

**第 3 列 · 数字**（左对齐）

- 第 1 行 `data-pool-used`：`{running} / {capacity}`，`--fs-22`，字重 600，`--text-1`，比例数字（不用等宽）。`running > capacity` 时 `running` 用 `--st-failed`，后面跟 `超出 {running − capacity}`（`--fs-11` `--st-failed`，左间距 `--sp-2`）。
- 第 2 行 `data-pool-queued`（`queued > 0` 才出现）：「排队 」+ 数字（等宽 `--text-1`），`--fs-12` `--text-2`。整行包一个 `Tip`，内容逐行列出 `queuedByProject`：`ProjectDot` + 项目名 + 数量。
- 第 3 行 `data-pool-health`（有非零项才出现）：`10 分钟`（`--text-3`）后接非零的各项，用「 · 」（`--text-3`）分隔：`完成 {n}`（数字 `--text-1`）、`失败 {n}`（数字 `--st-failed`）、`重试 {n}`（数字 `--st-warning`）。`--fs-12`，标签 `--text-2`，数字等宽。
- 第 4 行 `data-pool-usage`（`usageToday.totalTokens > 0` 才出现）：`今日 {formatTokens(totalTokens)} tokens`，费用非空再加 ` · {formatCost}`。`--fs-11` `--text-3`。

### 3. `SlotMeter`（离散格子）

- 容器：`<div role="group" data-meter aria-label="{pool.id} 容量 {running}/{capacity}">`，网格 `grid-template-columns: repeat(N, minmax(8px, 28px))`，`N = max(capacity, running)`，间距 `--slot-gap`，高 `--slot-h`，左对齐。
- **占用格**（按 `pool.slots` 顺序，第 i 个）：`<button type="button" data-slot data-worker-id={slot.workerId} data-project={slot.projectKey} data-retrying={slot.retrying ? "true" : "false"}>`。背景 = 该项目色（用 `snapshot.projects` 找 `colorIndex`，找不到用 0）；无边框；圆角 `--r-slot`。
  - 重试中：在底色上叠 `background-image: repeating-linear-gradient(45deg, var(--hatch) 0 2px, transparent 2px 5px)`。
  - 超出容量（`i >= capacity`）：再加 `box-shadow: inset 0 0 0 1px var(--st-failed)`，并带 `data-over="true"`。
  - 悬停、键盘聚焦：`filter: brightness(1.12)`；键盘聚焦另有焦点环。
  - `aria-label`：`{项目名}，{标题}，{角色名}，{工作中 或 重试 N/M}，{时长}`。
  - 点击或回车：`selectionStore.select(slot.workerId)`。
- **空格**（`running ≤ i < capacity`）：`<span data-slot-empty aria-hidden="true">`，背景 `--meter-track`，`box-shadow: inset 0 0 0 1px var(--line-strong)`，圆角 `--r-slot`。
- **键盘**：只有一个占用格 `tabIndex=0`（初始是第一个，之后是最近聚焦的那个），其余 `-1`；左右方向键在占用格之间移动焦点，`Home` / `End` 到首尾。
- **提示卡**：每个占用格包一个 `Tip`，悬停或键盘聚焦时出现（聚焦时 `open` 受控为 true）。内容 `SlotTooltip`（`data-slot-tip`），宽 ≤ 320px：
  - 第 1 行：标题，`--fs-13`，字重 600，`--text-1`，最多 2 行。
  - 第 2 行（上间距 6px）：`ProjectDot`(8) + 项目名（`--fs-12` `--text-1`）+ 「·」（`--text-3`）+ `<MonoPath path={项目路径} max={40} />`（`--fs-11` `--text-2`）。
  - 第 3 行（上间距 `--sp-1`）：角色名（`--fs-12` `--text-2`）+ 「·」+ `<StatusBadge size="sm" status="running" retry={…} />` + 「·」+ `<Duration from={slot.startedAt} />`。
  - 苦工工作目录和项目目录不同时，第 4 行：「工作目录 」（`--fs-11` `--text-3`）+ `<MonoPath path={cwd} max={40} />`。工作目录从 `snapshot.workers` 里按编号取，取不到就不显示这一行。

### 4. `SegmentBar`（容量 > 48 时）

一条高 `--slot-h` 的横向弹性条，段间距 `--slot-gap`。每个在跑的项目一段（顺序同 `slots` 里项目顺序），`flex: 0 0 {count / max(capacity, running) × 100}%`，背景项目色，圆角 `--r-slot`；该项目里重试中的部分画在段的末尾，按比例叠斜纹。剩余容量一段 `flex: 1`，空格样式。每个项目段是 `<button data-segment data-project={key}>`：提示卡内容为项目名 + 「{n} 个在跑」+ 最多 5 个标题（每行标题 + 时长）+ 超出时「还有 {m} 个」；点击选中该项目在这个池里最早开跑的苦工。

### 5. 状态

- 快照为 null：画 2 行骨架：第 1 列两条 `Skeleton`（60%×14、80%×12），第 2 列一条 100%×18，第 3 列一条 80×22。
- 池的 `running` 为 0：只有空格，图例不渲染，数字照常 `0 / 20`。

### 6. 响应式

< 1024px：`PoolRow` 改成单列；第 3 列的四行合成一行横排（间距 `--sp-3`），大数字字号改 `--fs-16`。

### 7. 文案

`排队`、`10 分钟`、`完成`、`失败`、`重试`、`今日`、`tokens`、`超出`、`已暂停`、`个在跑`、`还有`、`工作目录`。不写「容量」「占用」等标签。

## R4 左栏工具条 `ListToolbar`（L2）

1. **外层**：`<div data-list-toolbar>`，高 40px，左右内边距 `--sp-3`，下边 1px `--line`，横向弹性、垂直居中。
2. **元素**：`<FilterChips name="list-filter" ariaLabel="苦工范围" options=[{ value: "active", label: "进行中", count: countActive }, { value: "all", label: "全部", count: countAll }] />`，值绑定 `selectionStore.listFilter`。
3. **数据来源**：`selectors.countActive(snapshot)`（排队中 + 工作中）、`countAll(snapshot)`（快照里全部）。
4. **交互**：切换写回 `setListFilter`。
5. **状态**：快照为 null 时两个计数都不显示。
6. **响应式**：不变。
7. **文案**：「进行中」「全部」。

## R5 项目与苦工列表 `ProjectList`（L2）

### 1. 外层

`<nav data-project-list aria-label="项目与苦工">`，`flex: 1`，纵向滚动，内边距 `--sp-1 --sp-2 --sp-4`。内容是 `selectors.selectProjectGroups(snapshot, listFilter)` 的每一组。

### 2. 项目组 `ProjectGroup`

`<section data-project={project.key}>`，组与组之间上间距 `--sp-1`。

- **组头**：`<button data-project-toggle aria-expanded={open} aria-controls={体的 id}>`，高 32px，左右内边距 `--sp-2`，圆角 `--r-md`，横向弹性、间距 `--sp-2`、垂直居中；悬停 `--bg-hover`。
  - `ChevronRight` 12px `--text-3`，展开时旋转 90°。
  - `ProjectDot`(8)。
  - 项目名：`--fs-13`，字重 500，`--text-1`，`flex: 1` 单行省略；外面包 `Tip`，内容 `<MonoPath path={project.path} max={56} />`。
  - 计数区（等宽 `--fs-12`，项间距 `--sp-2`，为 0 的项不显示）：`CircleDot` 12px `--st-running` + 工作中数；`Clock` 12px `--st-queued` + 排队中数；`CircleX` 12px `--st-failed` + 失败数。每项 `aria-label` 如「工作中 11」。数字颜色 `--text-2`。
- **展开状态**：取 `selectionStore.expanded[key]`；没有记录时，有排队中或工作中苦工的组默认展开，否则收起。点击组头 `toggleProject(key)`。收起时不渲染组体。
- **组体**：`<ul role="list" id=…>`，每个苦工一个 `WorkerRow`。

### 3. 苦工行 `WorkerRow`

`<li><button data-worker-row={worker.id} aria-current={选中 ? "true" : undefined}>`：宽 100%，左对齐，内边距 `6px 8px 6px 28px`（与组头箭头对齐缩进），圆角 `--r-md`，最小高 48px，网格 `grid-template-columns: 16px minmax(0, 1fr) auto`，行间距 2px、列间距 `--sp-2`。

- **第 1 行**：
  - 第 1 格：状态图标 14px（`STATUS_META[status].icon`，颜色同状态；工作中且在重试 → `RotateCw` `--st-warning`；工作中图标旋转，见站点层第 3 章）。
  - 第 2 格：标题，`--fs-13` `--text-1`，单行省略，`title` 为全文。
  - 第 3 格：时长，等宽 `--fs-12` `--text-2`：工作中 `<Duration from={startedAt} />`（实时）；排队中 `<Duration from={queuedAt} />`（`--text-3`）；终态 `<Duration from={startedAt ?? queuedAt} to={endedAt} />`。
- **第 2 行**（占第 2、3 格，`--fs-12`，各部分用「 · 」（`--text-3`）分隔，整行单行省略）：
  1. 状态词：工作中（`--st-running`）；在重试时改为「重试 N/M」（`--st-warning`）；排队中写「排队第 N 位」（`--st-queued`，没有位置写「排队中」）；已完成（`--st-done`）；失败（`--st-failed`）；已取消（`--st-cancelled`）。
  2. 角色名，`--text-2`。
  3. 补充（`--text-3`）：工作中 → `activity`（等宽），为空时写「等待第一条输出」；已完成且 `verdict === "fail"` → 「自评不通过」（`--st-warning`）；失败 → `{FAIL_REASON_LABELS[failReason]}：{errorMessage}`；其余不写。
- **选中**：背景 `--bg-selected`，`box-shadow: inset 2px 0 0 var(--accent)`。
- **悬停**：`--bg-hover`（选中行悬停保持选中底）。
- **点击 / 回车**：`selectionStore.select(worker.id)`。
- **键盘**：列表内上下方向键把焦点移到上一个 / 下一个可见的苦工行（跨组）。
- **选中联动**：`selectedId` 变化时，若该苦工所在组收起则展开；随后把该行 `scrollIntoView({ block: "nearest" })`。

### 4. 状态

- 快照为 null：6 条 `Skeleton`（高 44、圆角 md、宽 100%、间距 `--sp-1`）。
- 筛选为「进行中」且没有任何组：`<EmptyState message="没有进行中的苦工" />`。

### 5. 响应式

< 1024px：列表占满宽度，行样式不变。

### 6. 文案

「等待第一条输出」「自评不通过」「排队第 N 位」「排队中」「重试 N/M」及状态词。

## R6 详情头与元信息（L3）

### 1. 外层 `WorkerDetail`

`<article data-detail={id}>`，内边距 `--sp-5 --sp-6 40px`，内容最大宽 1120px（左对齐）。自上而下：`DetailHeader` → `MetaGrid` → `ReportCard`（有回报时）→ `TaskSection` → `<Timeline />`。

**状态**（优先级从上到下）：

- `selectedId` 为 null：`<EmptyState message="选择左侧的苦工查看详情" />`（占满右栏、居中）。
- `workerStore.status === "loading"`：标题骨架两条（60%×20、40%×16，间距 8）→ 元信息骨架 6 格（每格 40%×10 + 70%×14）→ 5 条 20px 高的时间线骨架。
- `status === "notFound"`：`<EmptyState message="这个苦工已被清理" />`。
- `status === "error"`：`<EmptyState message={"加载失败：" + error} action={{ label: "重试", onClick: 重新 open(id) }} />`。

### 2. `DetailHeader`（`data-detail-header`）

- 窄屏（< 1024px）顶部：返回按钮，高 28px，`ArrowLeft` 14px + 「返回」`--fs-12` `--text-2`，幽灵样式，点击 `select(null)`，下间距 `--sp-2`。
- 第 1 行（横向弹性，两端对齐，`align-items: start`，间距 `--sp-3`）：
  - 标题 `<h1 data-detail-title>`：`--fs-16`，字重 600，`--text-1`，最多 2 行，`title` 为全文。
  - 右侧：苦工编号（等宽 `--fs-12` `--text-3`）+ `<CopyButton text={id} label="复制编号" />`，间距 `--sp-1`，不换行。
- 第 2 行（上间距 6px，横向弹性换行，间距 `--sp-2`，垂直居中）：`<StatusBadge size="md" status retry queuePosition />`；时长（`--fs-13` 等宽 `--text-2`，规则同苦工行第 1 行第 3 格）；`verdict` 非空时 `<VerdictTag />`；`runSeq > 1` 时「第 {runSeq} 次运行」（`--fs-12` `--text-3`）。
- 第 3 行（失败或已取消且有说明时，`data-failure`）：上间距 10px，内边距 `--sp-2 --sp-3`，圆角 `--r-md`，背景失败用 `--st-failed-soft`、已取消用 `--bg-raised`；`--fs-12`：失败原因中文（字重 600 `--text-1`）+「：」+ 说明（`--text-2`，保留换行，最多 4 行，`title` 为全文）。已取消没有失败原因时只写说明。

### 3. `MetaGrid`（`data-meta`）

上间距 `--sp-4`，上下各 1px `--line`，上下内边距 `--sp-3`；网格 `repeat(auto-fill, minmax(168px, 1fr))`，行间距 `--sp-3`、列间距 `--sp-6`。每格：标签（`--fs-11` 字重 500 `--text-3`）+ 值（上间距 2px，`--fs-13` `--text-1`）+ 可选的补充行（`--fs-11` `--text-3`）。

| 标签 | 值 | 补充行 |
|---|---|---|
| 项目 | `ProjectDot`(8) + 项目名（`Tip` 显示项目路径） | — |
| 工作目录 | `<MonoPath path={cwd} max={40} />`（`--fs-12`） | — |
| 角色 | 角色中文名 | 角色编号（等宽） |
| 池与模型 | 池编号 + 「 · 」+ 模型名（等宽 `--fs-12`，单行省略） | 运行时（pi / opencode）；有思考档位时再加「 · 思考 {档位}」 |
| 运行 | 「第 {runSeq} 次」 | 会话编号（等宽，单行省略；没有时不显示） |
| 用量 | `{formatTokens(total)} tokens`，费用非空再加「 · {formatCost}」 | 「输入 {in} · 输出 {out} · 缓存 {cacheRead}」（均用 `formatTokens`） |

### 4. 响应式

< 1024px：内边距改 `--sp-4`；元信息网格最小列宽 140px。

## R7 任务与回报（L3）

### `ReportCard`（`data-report`）

- **出现条件**：苦工状态是终态，且最新一次运行的 `finalText` 非空。
- **外层**：上间距 `--sp-4`，1px `--line` 边框，圆角 `--r-lg`，背景 `--bg-raised`，内边距 14px 16px。
- **头部**：「回报」`--fs-14` 字重 600 `--text-1` + `report.verdict` 非空时 `<VerdictTag />`（左间距 `--sp-2`）+ 右侧（运行不止一次时）「第 {seq} 次运行」`--fs-11` `--text-3`。
- **正文**：
  - `report` 解析成功：`<dl>` 网格 `grid-template-columns: 112px minmax(0, 1fr)`，行间距 10px、列间距 `--sp-3`。每段 `<dt>` 为段名（等宽 `--fs-11` 字重 600 `--text-3` 字间距 0.4px）、`<dd>` 为文字（`--fs-13` `--text-1` 保留换行）。`SELF_REPORT` 和 `VERDICT` 段的文字首词是 pass / fail 时显示 `<VerdictTag />`，后面跟剩余文字。文字恰好是「无」时用 `--text-3`。每段超过 10 行时折叠，末尾「展开全部」/「收起」（`--fs-12` `--accent` 文字按钮）。
  - 解析失败：直接显示 `finalText`（`--fs-13` 保留换行），超过 12 行折叠同上。

### `TaskSection`（`data-task`）

## R8 时间线 `Timeline`（L4，最重要的区域之一）

### 1. 外层

`<section data-timeline aria-label="时间线">`，上间距 `--sp-4`。

- **头部**（`data-timeline-header`）：`position: sticky; top: 0`（滚动容器是 `#detail-scroll`），`z-index: var(--z-sticky)`，背景 `--bg-panel`，上下内边距 10px，下边 1px `--line`，横向弹性、垂直居中、间距 `--sp-3`：「时间线」`--fs-14` 字重 600 `--text-1` + 事件总数（等宽 `--fs-12` `--text-3`）+ 弹性空白 + `<FilterChips name="timeline-filter" ariaLabel="时间线筛选" options=[全部 all、工具 tools、文字 text、异常 issues] />`，计数取 `countTimelineRows`，计数为 0 的选项禁用（「全部」永不禁用）；值绑定 `workerStore.filter`。
- **列表**：`<ol role="log" aria-live={停在底部 ? "polite" : "off"}>`，行由 `filterTimelineRows(buildTimelineRows(events), filter)` 得到。每行 `<li data-timeline-row data-kind={row.kind} data-seq={row.seq}>`。

### 2. 普通行的版式

网格 `grid-template-columns: 64px 16px minmax(0, 1fr) auto`，列间距 10px，上下内边距 6px，`align-items: start`。

- 第 1 列：`formatClock(row.at, now)`，等宽 `--fs-12` `--text-3`。
- 第 2 列：图标 14px（上偏移 3px 与首行文字对齐）。
- 第 3 列：内容。
- 第 4 列：右侧附加信息（可为空）。

### 3. 显示行类型（`lib/timelineView.ts`，地基路照抄）

```ts
export type TimelineRow =
  | { kind: "run"; key: string; seq: number; runSeq: number; at: string; edge: "start"; prompt: string }
  | {
      kind: "run"; key: string; seq: number; runSeq: number; at: string; edge: "end";
      status: RunStatus; failReason: FailReason | null; message: string | null;
    }
  | {
      kind: "tool"; key: string; seq: number; runSeq: number; at: string;
      callId: string; tool: string; summary: string; detail: string | null;
      result: { ok: boolean; preview: string; truncated: boolean; at: string } | null;
      durationMs: number | null;
    }
  | { kind: "text"; key: string; seq: number; runSeq: number; at: string; text: string }
  | { kind: "thinking"; key: string; seq: number; runSeq: number; at: string; text: string }
  | {
      kind: "retry"; key: string; seq: number; runSeq: number; at: string;
      attempt: number; max: number; delayMs: number | null; message: string;
    }
  | { kind: "error"; key: string; seq: number; runSeq: number; at: string; message: string }
  | { kind: "output"; key: string; seq: number; runSeq: number; at: string; stream: "stdout" | "stderr"; text: string };
```

合并规则：`tool_call` 生成一行工具行（`result` 为 null）；之后同一 `runSeq`、同一 `callId` 的 `tool_result` 挂到这一行（`durationMs = result.at − call.at`，为负时 null）；找不到对应调用的结果单独成一行工具行，摘要写「（没有对应的调用）」。`run_start` / `run_end` 生成运行分隔行。`key = String(seq)`。

筛选规则：`all` 全部；`tools` = 运行分隔 + 工具行；`text` = 运行分隔 + 文字 + 思考；`issues` = 运行分隔 + 重试 + 错误 + stderr 输出 + 结果失败的工具行。计数只数非运行分隔行，`all` 数全部非运行分隔行。

### 5. 跟随与「回到最新」

- 滚动容器是 `#detail-scroll`。「停在底部」= `scrollHeight − scrollTop − clientHeight < 48`。
- 新行到来时：停在底部 → 渲染后滚到底；否则累计未读数，显示「回到最新」按钮。
- 「回到最新」（`data-jump-latest`）：粘在时间线底部右侧（`position: sticky; bottom: 16px`，右对齐）；高 28px、左右内边距 `--sp-3`、圆角 `--r-md`、背景 `--accent`、文字 `--on-accent` `--fs-12` 字重 500；内容 `ArrowDown` 12px + 「回到最新 · {n} 条」；点击滚到底并清零。
- 切换苦工时：工作中的苦工在首批事件渲染后滚到底；其他状态停在顶部。

### 6. 状态

- 事件为空：排队中 → `<EmptyState message={"排队第 " + n + " 位"} />`（没有位置写「排队中」）；工作中 → 「等待第一条输出」；终态 → 「没有输出」。
- 行数超过 1000：只渲染最后 1000 行，列表顶部放文字按钮「显示更早的 {n} 条」（`--fs-12` `--accent`），点击后全部渲染。
- `workerStore.status === "loading"`：5 条 20px 骨架。

### 7. 响应式

< 1024px：网格改为 `56px 16px minmax(0, 1fr)`，右侧附加信息换到第 2 行第 3 列。
