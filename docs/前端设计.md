# fleet-studio 前端设计

> **一句话视觉方向：** 控制台式布局（左侧菜单 + 内容区顶栏 + 白色卡片），视觉仍是暗色仪表板。近黑底、发丝线分区、四级灰阶文字，颜色只留给数据（项目色）和状态；唯一的强调色只用在选中和焦点上。浅色主题是同一套语言的纸面版本。
>
> **参考来源：** Linear（侧栏整行选中块、分组标题调暗、靠明暗而不是字号分层）；HashiCorp Nomad（容量条和大号数字分开摆、数字下面跟一行绝对值）；Temporal（重试用斜纹填充而不是加深颜色、时间线里内联 key:value）；Grafana（状态 = 图标 + 彩色状态词，不只是色点）；Vercel 旧版部署页（元信息「上小灰字标签、下数值」的两行网格）；Sub2API 控制台（第二版的布局：左侧菜单、内容区顶栏、统计卡片行、筛选条、「环形图 + 明细表」的图表卡片，用户提供截图）。调研原文见 [参考界面](调研/参考界面.md)、[看板同类产品](调研/看板同类产品.md)。
>
> **对应代码：** `apps/web/` · 令牌文件 `apps/web/src/styles/tokens.css` · 实现规格 `apps/web/DESIGN.md`、`apps/web/design/工作区.md`
>
> **当前状态：** 第一版（单页工作区）已实现并验收；第二版（控制台三页：总览、槽位、任务）规格已定稿、待实现 · 最近更新：2026-09-25

## 1. 方向与取舍

第一轮对同一个工作区页面出了三个视觉方向：

| 方向 | 示意图 | 结论 |
|---|---|---|
| A 暗色仪表板 | [01-方向A-暗色仪表](前端设计/示意图/01-方向A-暗色仪表.png) | **采用**，作为默认视觉语言 |
| B 浅色纸面 | [01-方向B-纸面浅色](前端设计/示意图/01-方向B-纸面浅色.png) | **采用**，作为 A 的浅色主题（两者是同一套语言） |
| C 石墨琥珀 | [01-方向C-石墨琥珀](前端设计/示意图/01-方向C-石墨琥珀.png) | 不采用 |

不采用 C 的理由：琥珀色既表示「工作中」又被涂成项目颜色，容量条上一眼分不清是状态还是归属，违反「状态色和项目色必须分开」；凸起的卡片面板增加了视觉重量，信息密度反而下降。

A、B 的共同点就是本设计的规矩：分区用发丝线不用卡片投影；项目色只出现在容量格和项目色点上；状态永远是「图标 + 彩色状态词」；数字、时间、路径、编号用等宽字体；强调色只给选中和焦点。

第二版改成控制台布局，按用户给的 Sub2API 截图排版，对总览页出了两版配色：

| 方向 | 示意图 | 结论 |
|---|---|---|
| A 克制 | [02-控制台-总览-A克制](前端设计/示意图/02-控制台-总览-A克制.png) | **采用**：沿用本文件的令牌，颜色只给数据和状态，强调色只给选中 |
| B 参考配色 | [02-控制台-总览-B参考配色](前端设计/示意图/02-控制台-总览-B参考配色.png) | 不采用 |

不采用 B 的理由：每张卡片一个彩色图标块，颜色不再只表示数据和状态，放到暗色底上更花。A 选定后铺开的其余页面：[槽位](前端设计/示意图/03-控制台-槽位-A.png)、[任务](前端设计/示意图/04-控制台-任务-A.png)、[任务详情](前端设计/示意图/05-控制台-任务详情-A.png)；任务两张只作大致参考，细节以本文件和页面规格为准。

示意图只定调性，里面的文案和数字是模型编的，不是规格。

## 2. 信息结构

第二版是控制台三页，页面和区块见 [页面清单](页面清单.md)：

| 页面 | 回答的问题 |
|---|---|
| 总览 | 现在忙不忙（实时卡片）；选定时间段里用了多少 token、派了多少活、花了多久；token 花在哪些模型 / 渠道 / 项目 / 角色上，怎么随时间变化；哪个项目派活最多 |
| 槽位 | 每个「渠道 · 模型」被谁占着、排了几个、最近顺不顺；派活先用谁（顺序）、哪个停用了 |
| 任务 | 所有任务的列表（默认进行中）；点开一个看它的任务书、实时过程和回报 |

第一版工作区的四个区域在第二版的去向：顶栏 → 左侧菜单和内容区顶栏；容量条 → 槽位页表格里的占用格子；左栏项目与苦工列表 → 任务页表格（按项目筛选）；右栏苦工详情 → 任务页右侧详情，内容不变。下表是第一版的原始结构，详情部分仍然适用：

| 区域 | 回答的问题 |
|---|---|
| 顶栏 | 这是哪个服务、连接是否正常（只在断开时说话） |
| 容量条（每个池一行） | 容量被谁占了多少、还有几个在排队、通道最近健康吗、今天用了多少 token |
| 左栏：项目与苦工列表 | 每个项目有几个苦工、各在干什么、谁失败了 |
| 右栏：苦工详情 | 这个苦工是谁、收到了什么任务、做到哪一步了、最后交回了什么 |

**故意不做：** 除槽位启停和排序外的任何写操作（派活、取消、改容量）；聊天或收发；原始输出查看器（时间线已经收录了非事件格式的原始输出行）；页面副标题和说明文字；主题切换按钮（跟随系统）；卡片上的彩色图标块。

### 3.2 状态色（固定，和项目色分开）

每个状态都配图标和中文状态词，颜色从不单独表达含义。以下文字色在 `--bg-panel`、`--bg-raised`、`--bg-selected` 上对比度全部 ≥ 4.5。

| 令牌 | 暗色 | 浅色 | 状态词 | 图标（lucide） |
|---|---|---|---|---|
| `--st-queued` | `#A3A3AB` | `#55544F` | 排队中 | `Clock` |
| `--st-running` | `#6EA8FE` | `#2563D6` | 工作中 | `LoaderCircle`（慢速旋转） |
| `--st-done` | `#4CC38A` | `#13773A` | 已完成 | `CircleCheck` |
| `--st-failed` | `#FF7070` | `#C62F2F` | 失败 | `CircleX` |
| `--st-cancelled` | `#8B8B94` | `#696862` | 已取消 | `CircleSlash` |
| `--st-warning` | `#F2B544` | `#8C5A00` | 重试中 N/M、自评不通过 | `RotateCw`、`TriangleAlert` |

| 0 | `--proj-0` | `#3987E5` | `#2A78D6` |
| 1 | `--proj-1` | `#D95926` | `#EB6834` |
| 2 | `--proj-2` | `#199E70` | `#1BAF7A` |
| 3 | `--proj-3` | `#C98500` | `#EDA100` |
| 4 | `--proj-4` | `#D55181` | `#E87BA4` |
| 5 | `--proj-5` | `#008300` | `#008300` |

项目色只画在容量格、项目色点、图例色点上；**文字永远用文字色**。同时活跃的项目超过 8 个时颜色会重复，身份靠名字区分（图例、提示卡、列表都写名字）。核心层的配色位置数随之改为 8（`PROJECT_PALETTE_SIZE`）。

### 3.5 间距、圆角、阴影、层级

- 间距阶梯（4px 基准）：`--sp-1` 4px、`--sp-2` 8px、`--sp-3` 12px、`--sp-4` 16px、`--sp-5` 20px、`--sp-6` 24px、`--sp-8` 32px。
- 圆角：`--r-slot` 3px（容量格）、`--r-sm` 4px（小片、徽标）、`--r-md` 6px（行、按钮）、`--r-lg` 8px（卡片、提示卡）。
- 阴影：只有悬浮提示卡有：暗 `0 8px 24px rgba(0,0,0,0.55), 0 0 0 1px #2A2B30`；浅 `0 8px 24px rgba(20,20,18,0.12), 0 0 0 1px #E6E5E0`。其余一律无阴影。
- 层级：`--z-sticky` 10（时间线顶部筛选条）、`--z-banner` 20（断线提示条）、`--z-tooltip` 30。

### 3.6 动效

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--dur-fast` | 120ms | 悬停底色、按压 |
| `--dur-base` | 160ms | 折叠展开、筛选切换 |
| `--ease` | `cubic-bezier(0.2, 0, 0, 1)` | 全部过渡 |

- 不做入场动画、不做数字滚动、不做闪烁高亮。
- 唯一的循环动画：工作中图标每 1.2 秒转一圈；以及新事件到来时时间线不动画。
- `prefers-reduced-motion: reduce` 时关闭旋转，工作中图标换成静态实心圆点。

| 令牌 | 暗色 | 浅色 | 用在哪 |
|---|---|---|---|
| `--series-0` ～ `--series-7` | 同 `--proj-0` ～ `--proj-7` | 同 `--proj-0` ～ `--proj-7` | 图表系列色，顺序和项目色一致 |

## 4. 布局与响应式

第二版控制台：

| 宽度 | 结构 |
|---|---|
| ≥ 1280px | 左侧菜单 220px；总览卡片一行 4 张；「token 分布」和「任务次数分布」并排两列，「token 趋势」占满一行；任务页打开详情时，表格收窄到 36%（只剩状态和标题），详情占 64% |
| 1024–1279px | 同上 |
| 800–1023px | 左侧菜单自动收起到 64px；总览卡片一行 2 张；图表卡片全部单列；任务详情整屏盖住表格，顶上出现「返回」 |
| < 800px | 同上，卡片一行 2 张；槽位表格和任务表格在卡片内部横向滚动 |

- 左侧菜单固定不随内容滚动；内容区自己纵向滚动；顶栏固定在内容区顶上。
- 槽位页的占用格子沿用下面第一版的格子画法（≤ 48 画离散格，> 48 画连续分段条）。

第一版工作区（第二版中容量条和左右栏已拆进槽位页和任务页，下表留作详情区的依据）：

| 宽度 | 结构 |
|---|---|
| ≥ 1280px | 顶栏 44px；容量条区（每池一行）；下方两栏：左栏 340px，右栏占满其余 |
| 1024–1279px | 同上，左栏 300px |
| < 1024px | 单栏：列表占满宽度；选中苦工后详情整屏替换列表，顶部出现「返回」按钮；容量条的数字区换到格子下方 |

- 页面整体不出现横向滚动；左右栏各自纵向滚动；容量条区不滚动（池多于 4 个时容量条区最大高度 40vh，内部滚动）。
- 容量 ≤ 48 时画成离散格子（每格宽度 = 可用宽度均分，限制在 8～28px，高 18px，间距 2px）；容量 > 48 时改画成连续分段条（每段宽度按占用比例，段间 2px 缝），悬浮逐段。

## 6. 空态、加载态、错误态

统一画法：区域中央一段 `--text-2` 的短句，最多再跟一行等宽的命令或路径；不配插图、不配大图标。

| 场景 | 画法 |
|---|---|
| 首次加载（还没收到快照） | 容量条画成整条 `--meter-track` 骨架；左栏 6 条骨架行（高 44px，`--bg-hover` 底，圆角 `--r-md`）；右栏空白 |
| 一个苦工都没有 | 左栏和右栏合成一块居中：「还没有苦工」，下一行等宽 `fleet run "任务"` |
| 没有选中苦工 | 右栏居中：「选择左侧的苦工查看详情」 |
| 苦工被清理或不存在 | 右栏居中：「这个苦工已被清理」 |
| 详情加载中 | 右栏头部保留标题骨架（2 条），时间线区 5 条骨架行 |
| 详情加载失败 | 右栏居中：「加载失败：<错误说明>」+ 文字按钮「重试」 |
| 时间线还没有事件 | 排队中：「排队第 N 位」；工作中：「等待第一条输出」 |
| 连接断开 | 顶栏下方一条 32px 的提示条（`--st-warning` 左侧图标 + `--text-1` 文字）：「连接已断开，正在重连」；页面内容保留、整体不透明度 0.6；重连成功后提示条消失 |
| 配置文件有错 | 容量条区上方一条同样样式的提示条：「配置文件有错，正在使用上一份有效配置：<说明>」 |
| 总览首次加载 | 实时卡片和统计卡片的大数字换成骨架块；图表卡片内部画一块 `--bg-hover` 的骨架 |
| 所选时间段没有任务 | 统计卡片显示 0；三张图表卡片合成一块居中：「这段时间没有任务」 |
| 任务表格为空 | 表格区居中：没有任何任务时「还没有任务」，下一行等宽 `fleet run "任务"`；筛选后为空时「没有符合条件的任务」+ 文字按钮「清除筛选」 |
| 所有池都停用 | 槽位表格上方一条 `--st-warning` 提示条：「所有池都已停用，没点名的任务派不出去」 |
| 连不上服务（首次打开就连不上） | 整个内容区居中：「连不上 fleet 服务」，下一行等宽 `fleet daemon start` |
| 长文本 | 标题单行省略、悬停看全文；路径中间省略（保留开头和结尾，中间用「…」）；时间线正文最多 8 行，超出折叠为「展开全部」 |

## 7. 无障碍底线

- 正文对比度 ≥ 4.5:1（第 3 节已逐个核实）；图形元素（容量格、色点）≥ 3:1（深色主题全部满足，浅色主题靠文字标注兜底）。
- 键盘可达：Tab 顺序为 容量条 → 左栏 → 右栏；容量条每个池是一个组合，组合内用左右方向键在格子之间移动，聚焦的格子显示与悬停相同的提示卡；左栏列表内上下方向键移动，回车选中，项目行回车或空格展开收起。
- 状态从不只靠颜色：状态词 + 图标；重试格有斜纹；项目身份有名字。
- 容量格和提示卡有完整的无障碍名称，例如「wiki-forge，类目配置校验，实现，工作中 3 分 12 秒」。
- 第二版：左侧菜单是 `nav`，当前页 `aria-current="page"`，收起后每项保留 `aria-label`；启用开关是 `role="switch"` 并带 `aria-checked`，名称如「启用 dsf」；上移下移按钮名称如「dsf 上移一位」；环形图旁的明细表就是它的文字版，折线图附一张视觉隐藏的数据表。
- 时间线是 `role="log"` 且 `aria-live="polite"`，但只在用户停留在底部时播报新事件。

## 8. 文案

遵循全局界面文案守则：删掉不影响理解的字就不要写。全部中文，状态词和标签统一如下，不许同义词混用：

- 状态：排队中、工作中、已完成、失败、已取消；附加标记：重试 N/M、排队第 N 位、自评不通过。
- 容量区：`18 / 20`、`排队 4`、`10 分钟 完成 12 · 失败 1`（为 0 的项不写）、`今日 1.6M tokens`（有费用再加「 · $0.05」）、`输入 1.1M · 输出 480.4K · 缓存 672.6K`（和苦工详情的用量写法一致）。
- 元信息标签：项目、工作目录、角色、池与模型、运行、用量。
- 区块标题：任务、回报、时间线。筛选：全部、工具、文字、异常；左栏：进行中、全部。
- 第二版菜单：总览、槽位、任务。
- 总览：实时卡片「槽位占用」「工作中」「排队中」「重试中」；时间档位「今日」「近 7 天」「近 30 天」「全部」「自选」；统计卡片「token 用量」「任务次数」「总耗时」「平均耗时」，补充行「今日 21.4M」；图表卡片「token 分布」「任务次数分布」「token 趋势」；维度「模型」「渠道」「项目」「角色」；合并项「其他」。
- 槽位：顶栏右侧「公共排队 3」（为 0 时不显示）；表头「优先级」「渠道 · 模型」「占用」「已用」「点名排队」「24 小时成功率」「平均耗时」「今日用量」「启用」「顺序」；停用标记「已停用」；确认框标题「停用 dsf？」、正文「还有 3 个在跑，会跑完；点名它的 2 个任务会一直排队到重新启用」（为 0 的半句不写）。
- 任务：表头「标题」「项目」「角色」「池」「状态」「用量」「耗时」「开始时间」；状态筛选「进行中」「排队中」「工作中」「已完成」「失败」「已取消」「全部」；按钮「清除筛选」「复制编号」。
- 时长：45秒、3分12秒、1时05分。时间：`12:03:04`，非今天加日期 `09-22 12:03`。

## 9. 落地方式

- **令牌：** `apps/web/src/styles/tokens.css` 用 CSS 变量定义全部令牌：`:root` 放暗色值；`@media (prefers-color-scheme: light)` 里的 `:root` 放浅色值。组件样式只能引用变量，门禁 `scripts/check-tokens.mjs` 会拦截写死的色值。
- **第二版（shadcn/ui + Tailwind 4）：** 令牌文件不变，仍是唯一的取值来源。
  - Tailwind 主题把令牌映射成类名：`bg-page`、`bg-panel`、`text-1`、`text-2`、`text-3`、`border-line`、`accent`、`st-*`、`proj-*`、`series-*`，字号、间距、圆角同理。
  - shadcn/ui 组件读的那组变量（背景、前景、卡片、弹出层、主色、弱化色、边框、输入框、焦点环、图表色、侧栏色）一律定义成本项目令牌的别名，组件不用逐个改就是本设计的样子。例如主色 = `--accent`，边框 = `--line`，卡片 = `--bg-panel`，图表色 1～8 = `--series-0`～`--series-7`。
  - 深浅主题仍然跟随系统，Tailwind 的 `dark:` 写法按系统设置生效，不做切换按钮。
  - shadcn/ui 的组件源码放在 `apps/web/src/components/ui/`，只通过令牌和变体调整外观，不在组件里写死颜色；业务组件放在 `features/` 下。
  - 门禁同时检查 Tailwind 类名：禁止方括号里直接写色值，禁止使用 Tailwind 自带调色板（例如 `bg-blue-500`）。
  - CSS Modules 随第一版组件一起退役，不两套混用。
- **样式组织：** 全局基础样式在 `apps/web/src/styles/base.css`；第一版组件样式用 CSS Modules，与组件同目录；第二版改用 Tailwind 类名（见下一条）。
- **实现规格：** 站点层 [apps/web/DESIGN.md](../apps/web/DESIGN.md)，页面层 [apps/web/design/工作区.md](../apps/web/design/工作区.md)。
- **实现模块：** 第一版 [界面层 · 工作区看板](模块设计/界面层-工作区看板.md)；第二版 [控制台框架](模块设计/界面层-控制台框架.md)、[总览](模块设计/界面层-总览.md)、[槽位](模块设计/界面层-槽位.md)、[任务](模块设计/界面层-任务.md)。
