### 第 4 段：我们没想到但对个人调度看板有用的功能

1. **Runway（余额续航天数）+ 健康灯**：用 `余额 / 近 24h 消耗` 直接算"还能跑几天"，并给出 Healthy / Low balance（<3 天）/ Balance depleted 三档色点——个人站最想知道的就是"还能撑多久"，比只看余额直观（`web/src/features/dashboard/components/overview/summary-cards.tsx:262-351`；`hooks/use-dashboard-config.tsx:90-134`）
2. **会话粘性（Session affinity）+ 绑定策略**：把同一会话固定到同一渠道以减少缓存击穿，并可选"换渠道后后续请求跟随"或解除绑定——自建/多上游混跑时能显著提高缓存命中，省真金白银（`request-policies/routing-section.tsx:177-299`）
3. **Auto 分组链 + 跨分组重试**：token 侧定义有序分组队列，系统自上而下尝试，失败可跨组重试——个人站"免费额度先用完再切付费"这类策略可以完全自动化（`web/src/features/system-settings/models/group-ratio-form.tsx:341-370`；`features/keys/components/auto-group-order-editor.tsx:97-202`；`api-keys-mutate-drawer.tsx:455-498`）
4. **多 Key 轮询 + 单 Key 自动禁用/恢复 + 批量清理**：一个渠道挂多把 Key，Random/Polling 轮询，失败 Key 自动跳过，可看 Disabled Reason/Disabled Time 并一键 Delete Auto-Disabled——个人站常靠多账号拼额度，这是最实用的运维动作（`channels/components/dialogs/multi-key-manage-dialog.tsx:242-474`）
5. **渠道一致性修复（Repair Channel Consistency）**：从所有渠道配置重建路由索引（含 models/groups/priority/weight），并提示重建期间路由可能短暂不完整——手动改过优先级/模型后"改了不生效"类问题一把修好（`channels/components/channels-primary-buttons.tsx:262-330`）
6. **自动禁用规则可配到状态码区间 + 失败关键字**：`401, 403, 429, 500-599` 这类区间表达式 + 关键字匹配，比只看 HTTP 码精准，能抓住"返回 200 但内容报错"的软失败（`request-policies/channel-health-section.tsx:492-583`）
7. **渠道自建推理监控（Running/Waiting requests、Mean queue time、Auto refresh 5s）**：能直接看到自家 vLLM/SGLang 的排队情况与 KV cache 峰值——"苦工调度站"如果自己也跑推理，这是最贴近队列的视图（`channels/components/dialogs/inference-status-dialog.tsx:134-405`）
8. **根诊断（Root Diagnostics）：Upstream Task ID / Node Name / Plugin Generation**：任务详情里保留上游任务 ID 和执行节点名——多机部署时定位"这条任务跑在哪台、上游单号是多少"，排障省大量时间（`usage-logs/components/dialogs/task-details-dialog.tsx:228-259`）
9. **日志详情里的 Retry Chain 与 Request Conversion**：直接看到一次请求在哪些渠道间重试过、请求体被怎么改写——调路由策略时不用再猜（`usage-logs/components/dialogs/details-dialog.tsx:687-754`）
10. **多机实例面板（Instances）**：列 Instance / Status / Role / CPU / Memory / Storage / Version / Runtime / Started / Last Seen，可 Configure NODE_NAME、Delete stale instance——多实例调度站的"哪些苦工还活着"一览（`web/src/features/system-info/components/system-instances-panel.tsx:246-477`）
11. **公开排行榜的 Period 档位与涨跌（Trending up/down）**：Today / Week / Month / Year + Market Share（按模型作者聚合 token）+ LLM Leaderboard + Pulse——低成本获取"最近什么模型在涨"，对选型/换上游有参考价值（`web/src/features/rankings/components/rankings-hero.tsx:25-31`、`market-share-section.tsx:220-259`、`pulse-section.tsx:47-68`、`models-section.tsx:173-222`）
12. **首字延迟 FRT / 吞吐的逐条展示**：日志 Timing 列对消费与错误记录展示 Duration，流式请求额外给 First token 与吞吐——比看聚合平均延迟更能发现"个别请求很慢"（`usage-logs/components/timing-metrics-cell.tsx:84-124`）
13. **日志维护（Log Maintenance）带进度清理 + 记录配额使用量开关**：可"Clean history logs"（按时间戳清理，显示清理进度与释放文件数），并可整体关掉消费日志写入——个人站省磁盘最直接的两个旋钮（`system-settings/maintenance/log-settings-section.tsx:344-412`）
14. **运维维护动作：Clear disk cache / Reset stats / Force GC / Clean log files**：一键释放磁盘缓存、清零性能计数器、手动触发 Go GC——低配 VPS 上跑调度站很实用（文档 https://docs.newapi.pro/zh/docs/guide/feature-guide/admin/performance ）

### 2. 渠道 / 模型 / 队列管理页可做的操作

- **网关增删改**：Create Gateway / Edit（Settings）/ Delete Gateway（https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/）
- **Workers AI 计费模式**：Standard billing / Unified billing 切换（https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/）
- **Require provider credentials**：开启后禁止回落到 Cloudflare 托管凭证，缺凭证返回 400（https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/ ；https://developers.cloudflare.com/ai-gateway/changelog/）
- **Retry Requests 开关**：toggle + Retry count（最多 5）+ Delay（0.1–60 秒）+ Backoff（Constant / Linear / Exponential）（https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/）
- **Provider Keys（BYOK）**：Provider Keys → Add API Key，选 provider、填 key 与描述；支持查看按 provider 分组、最后使用时间、状态（active / expired / invalid）（https://developers.cloudflare.com/ai-gateway/configuration/bring-your-own-keys/）
- **Key 轮换与删除**：edit 现有条目替换 key、Delete 删除；同一 provider 可存多把 key，用 alias 区分（默认 default），请求时用 `cf-aig-byok-alias` 指定（https://developers.cloudflare.com/ai-gateway/configuration/bring-your-own-keys/）
- **Custom Providers 管理**：Dashboard 的 Custom Providers 页可 Add Custom Provider / Edit / Delete，字段含 name、slug、base_url；API 侧有 `enable: true/false` 开关（https://developers.cloudflare.com/ai-gateway/configuration/custom-providers/）
- **Dynamic Routes**：可视化编辑器建路由，节点含 Start / Conditional(if-else) / Percentage(概率分流) / Model / Rate Limit / Budget Limit / End（https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/）
- **路由版本与回滚**：每次修改产生新 draft，Save 存版本、Deploy 生效，可从 Versions 回滚（https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/）
- **模型节点级 timeout / retries**：JSON 配置里每个 model 节点可设 `timeout`（ms）与 `retries`（https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/json-configuration/）
- **失败切换（fallback）**：model 节点有 success / fallback 两个出口；Universal endpoint 的 fallback 数组可无限追加，响应头 `cf-aig-step` 标明第几步成功（https://developers.cloudflare.com/ai-gateway/configuration/fallbacks/）
- **Rate limiting 开关**：Settings 里 enable Rate-limiting，可调 rate、time period、fixed/sliding（https://developers.cloudflare.com/ai-gateway/features/rate-limiting/）
- **Spend limits**：Settings > Spend limits，每个网关最多 20 条规则；维度支持 provider / model / metadata key，模式分 Split by value 与 Filter by value；超限默认 429，也可配合 Dynamic Route 降级到便宜模型（https://developers.cloudflare.com/ai-gateway/features/spend-limits/）
- **Caching 开关**：Settings 里 Enable Cache Responses + 默认 TTL（https://developers.cloudflare.com/ai-gateway/features/caching/）
- **DLP 策略管理**：Add Policy、每条策略独立 enable/disable toggle、Edit、Save；Action 选 Flag / Block，Check 选 Request / Response / Both（https://developers.cloudflare.com/ai-gateway/features/dlp/set-up-dlp/ ；https://developers.cloudflare.com/ai-gateway/features/dlp/）
- **Guardrails 配置**：Settings 内开关 Guardrails、Evaluation scope（prompt / response / both）、Hazard categories 逐类设 Flag / Ignore / Block（S1–S13，另 P1 prompt injection）（https://developers.cloudflare.com/ai-gateway/features/guardrails/ ；https://developers.cloudflare.com/ai-gateway/changelog/）
- **Workers Logpush 开关**：dashboard settings 可 toggle on/off，按网关配置，需上传公钥后建 Logpush job 选 AI Gateway dataset（https://developers.cloudflare.com/ai-gateway/observability/logging/logpush/）
- **OTEL exporter 配置**：Settings 里可加一个或多个 exporter（URL、Headers、Authorization secret、Content type json/protobuf）（https://developers.cloudflare.com/ai-gateway/observability/otel-integration/）
- **未查到**：provider/model 的「测试连通」按钮；渠道/模型的优先级排序或权重字段；模型级启用/停用开关（只有 custom provider 的 `enable` 与 DLP policy 的 toggle 有明确开关）。

### 4. 我们没想到、但对个人调度看板有用的功能

- **预估成本（cost estimation）**：按 token 数×模型定价估算每条请求花费，可按模型/渠道看花费趋势（https://developers.cloudflare.com/ai-gateway/observability/costs/）。对我们有用：我们只看 token 和耗时，没有「这条苦工烧了多少钱」；加上单价表就能给槽位排序做成本维度。
- **自定义成本覆盖**：`cf-aig-custom-cost` 支持 per_token_in / per_token_out / per_cache_read_token / per_cache_write_token，且日志里用下划线标出（https://developers.cloudflare.com/ai-gateway/configuration/custom-costs/）。对我们有用：本地渠道有包月/免费额度/不同倍率，用「自定义单价」比统一按 token 计价更真实。
- **缓存命中率指标**：Analytics 有 Cached Responses 百分比指标，日志有 cached 布尔，User Insights 有 Cache hit rate（https://developers.cloudflare.com/ai-gateway/observability/analytics/ ；https://developers.cloudflare.com/ai-gateway/observability/user-insights/）。对我们有用：槽位卡片现在只有占用/成功率/用量，加一列缓存命中能解释「为什么这个槽位这么快/这么省」。
- **逐请求跳过缓存 / 自定义缓存键**：`cf-aig-skip-cache`、`cf-aig-cache-key`、`cf-aig-cache-ttl`（https://developers.cloudflare.com/ai-gateway/features/caching/）。对我们有用：重跑同一个任务时可强制不走缓存，避免「看起来成功其实是缓存」。
- **Errors 单独作为一级指标**：Analytics 把 Errors 与 Requests 并列，日志 Status 区分 successful/cached/failed（https://developers.cloudflare.com/ai-gateway/observability/analytics/ ；https://developers.cloudflare.com/ai-gateway/evaluations/add-human-feedback/）。对我们有用：失败率要和缓存命中分开算，否则成功率会被缓存稀释。
- **人类反馈（thumbs up/down）**：Logs tab 每条可点赞/点踩，Evaluation 的 Human feedback 指标=点赞百分比（https://developers.cloudflare.com/ai-gateway/evaluations/add-human-feedback/）。对我们有用：任务页现在只有状态，没有「这次结果好不好」，反馈能变成按模型/角色的质量排名。
- **任务分类 + 模型适配度**：Log classification 自动把流量分成 debugging / code planning / code Q&A / text drafting / coding，并把模型判成 Overkill / Appropriate / Underpowered（https://developers.cloudflare.com/ai-gateway/observability/log-classification/）。对我们有用：这正是槽位页缺的「这个模型对这个任务是杀鸡用牛刀还是不够用」，可以直接指导派活优先级。
- **按任务的成本对比**：Tasks by model 图可按 token 或花费看分类分布（https://developers.cloudflare.com/ai-gateway/observability/log-classification/）。对我们有用：总览的排名可以再加「按任务类型的花费排名」。
- **按用户/身份归因与覆盖率**：custom metadata 或 Cloudflare Access 注入 `cf.user_id`，User Insights 给出 Identity coverage（https://developers.cloudflare.com/ai-gateway/observability/custom-metadata/ ；https://developers.cloudflare.com/ai-gateway/observability/user-insights/）。对我们有用：我们的「角色/项目」维度可以照搬，并且显示「有多少任务没打标签」。
- **自定义元数据（每请求最多 5 条）**：字符串/数字/布尔，可在日志里搜索筛选，且会作为 OTEL span 属性导出（https://developers.cloudflare.com/ai-gateway/observability/custom-metadata/ ；https://developers.cloudflare.com/ai-gateway/observability/otel-integration/）。对我们有用：project/role/task_id 直接塞元数据，就不用改表结构。
- **异常用量检测**：按用户 p95 session cost 建滚动基线，超自身 2 倍且超组织 p99 才告警（https://developers.cloudflare.com/ai-gateway/observability/user-insights/）。对我们有用：某个渠道突然狂跑（比如 key 泄漏或死循环重试）能自动冒出来，而不是等看总耗时。
- **降级步骤可观测**：`cf-aig-step` 响应头标明是第几个 fallback 成功；日志有 `step` 字段（https://developers.cloudflare.com/ai-gateway/configuration/fallbacks/ ；https://developers.cloudflare.com/api/resources/ai_gateway/subresources/logs/methods/list/）。对我们有用：槽位页可以显示「这个任务其实是降级到备用渠道完成的」，否则成功率虚高。
- **按值分桶的预算（Split by value）**：Spend limits 可为每个 agent_id 单独开预算桶，或只过滤某个值（https://developers.cloudflare.com/ai-gateway/features/spend-limits/）。对我们有用：可以给每个槽位/角色单独设日预算，超额自动停派。
- **固定 vs 滑动限流**：rate limiting 支持 fixed / sliding，并有 429 语义（https://developers.cloudflare.com/ai-gateway/features/rate-limiting/）。对我们有用：渠道有「每分钟 N 次」的硬限额时，滑动窗口比固定窗口更贴近真实配额。
- **路由版本化 + 一键回滚**：每次改路由产生 draft，Deploy 生效，Versions 里可回滚（https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/）。对我们有用：槽位排序/派活规则改动后能一键退回上一版，比手工调回来安全。
- **概率分流（A/B）**：Percentage 节点把流量按比例分到最多 5 个出口（https://developers.cloudflare.com/ai-gateway/features/dynamic-routing/json-configuration/）。对我们有用：想试新渠道时可以先给它 10% 任务，观察成功率再放大。
- **不存 payload 只存元数据**：`cf-aig-collect-log-payload: false` 保留 token/模型/状态/成本/耗时，但不落 prompt 与 response（https://developers.cloudflare.com/ai-gateway/observability/logging/）。对我们有用：任务详情页想看「过程」时可以分层——指标永久留，正文可选择性丢弃。
- **导出与外部追踪**：Workers Logpush 加密导出到 R2 等对象存储；OTEL 导出 span 并支持 `cf-aig-otel-trace-id` / `cf-aig-otel-parent-span-id` 做 trace 串联（https://developers.cloudflare.com/ai-gateway/observability/logging/logpush/ ；https://developers.cloudflare.com/ai-gateway/observability/otel-integration/）。对我们有用：任务详情里的「过程」可以直接接 trace 视图，不用自己发明父子关系。
- **日志保留策略与自动清理**：Legacy Logs 可开 Automatic Log Deletion，触达上限删最旧；或按筛选手动 Delete logs；存储上限 Free 10 万条/账号、Paid 1000 万条/网关、单条 10MB（https://developers.cloudflare.com/ai-gateway/observability/logging/legacy-logs/ ；https://developers.cloudflare.com/ai-gateway/reference/limits/）。对我们有用：本机 SQLite 一定会涨，需要有保留窗口和「按条件清理」。
- **免费文本搜索日志元数据**：Logs API 的 `search` 参数对日志元数据做全文搜索（https://developers.cloudflare.com/api/resources/ai_gateway/subresources/logs/methods/list/）。对我们有用：任务页搜索可以直接做成全文，而不是只按 ID 精确匹配。
- **配置变更审计**：Audit logs 记录网关创建/删除/更新等配置变更，所有套餐免费且默认开启（https://developers.cloudflare.com/ai-gateway/reference/audit-logs/）。对我们有用：槽位启停/排序这类操作值得留一条变更记录，方便回答「谁把这条渠道关了」。
- **BYOK 密钥健康度**：密钥列表显示 last used 与状态（active/expired/invalid），支持轮换与多别名（https://developers.cloudflare.com/ai-gateway/configuration/bring-your-own-keys/）。对我们有用：槽位页除了「占用/成功率」还应显示「这个 key 上次用是什么时候」，能提前发现僵尸渠道。
- **余额卡片与自动充值**：Credits Available 卡片 + Setup auto top-up（阈值 + 充值额）（https://developers.cloudflare.com/ai-gateway/features/unified-billing/）。对我们有用：如果我们的渠道也是预充值配额，槽位页需要「剩余额度」和「低于阈值提醒」。
- **每个网关的日志开关与按请求覆盖**：网关级 Logs 设置 + `cf-aig-collect-log` 逐请求覆盖（https://developers.cloudflare.com/ai-gateway/observability/logging/）。对我们有用：可以让某些高频低价值任务不记日志，省本地存储。

## 四、我们没想到但对「个人用调度看板」有用的

1. **部署标记（Deploy markers）**：`Sidekiq::Deploy.mark!` 在指标图上打一条 `Deploy` 竖线，性能回退能直接对到某次部署（`lib/sidekiq/deploy.rb:18,33`；`web/views/metrics.html.erb:33`）——为什么有用：个人改配置/换模型往往没记录时间点，事后看到曲线变差无从归因，一条标记就够。
2. **「没有 worker」警告**：`uiConfig.showWorkers` 默认开，队列没暂停却没有消费者时队列卡上直接报 `No workers`，tooltip「Nothing is consuming this queue」（`ui-config.md`；`messages.json` QUEUE.WORKERS.*；`packages/ui/src/components/WorkersBadge/WorkersBadge.tsx:24-43`）——为什么有用：任务一直堆但没人消费是自建调度站最常见的静默故障，比看队列长度快得多。
3. **逐进程 Quiet / Stop**：Busy 页可对单个进程 Quiet（不再领新活、跑完当前）或 Stop，也可全局（`web/views/busy.html.erb`）——为什么有用：重启 worker 前先排水，不会打断正在跑的长任务。
4. **可迭代任务进度（cursor / exec / rt）**：长任务把游标、已执行次数、已耗时直接显示在 Busy 表和任务详情里（`web/views/busy.html.erb:147-149`；`web/views/_job_info.html.erb`）——为什么有用：批处理型 AI 任务最需要的「跑到第几了」不用自己再写一张表。
5. **延迟百分位 + 队列年龄**：p50/p95/p99 分 run/wait，加 queueAge，而不是只看平均值（`packages/ui/src/pages/MetricsHistoryPage/latencySeries.ts`）——为什么有用：平均值会被大量快任务稀释，p95 才能暴露真正的卡顿。
6. **指标存储用量面板**：能看指标占了多少 Redis 内存、分钟/小时/天三层各占多少、逐队列明细，并能 Trim 到某时间点或整体 Clear（`HistoryStorageModal.tsx:53-134`）——为什么有用：本机跑的调度站最容易遇到「Redis 被指标撑满」，需要一键回收。
7. **全局设置项**：轮询间隔（可关闭）、每页条数、默认打开哪个详情 tab、JSON 折叠深度、操作二次确认开关、主题跟随系统（`SettingsModal.tsx:57-212`；`useSettings.ts:13-40`）——为什么有用：个人用的看板最烦「别人的默认值」，这些都是零成本就能让人顺手的旋钮。
8. **可分享的状态过滤 URL**：`?status=` 直接编码当前过滤，配合侧栏搜索（`⌘K`）驱动主区（`StatusMenu.tsx:7-16`；`exploring-the-dashboard.md`）——为什么有用：收藏几个「只看失败」「只看排队」的链接，比每次手点快。
