# 界面调研:同类监控/编排面板参考

调研目的:给"本地多苦工 agent 看板"(顶部容量条 + 左栏项目/苦工列表 + 右侧只读详情时间线)找真实可参考的界面设计。以下每一节只写**亲眼在截图里看到的东西**,截图本地存放在 `.scratch/refs/`,看不到完整页面的地方会明确注明"只看到局部"。

调研中尝试但**看不到真实界面、已从建议里剔除**的产品:Conductor(conductor.build 首页只找到作曲家头像图和背景插画,没找到看板截图)、Sculptor(imbue.com 域名在当前网络环境下连不上,GitHub 仓库 README 也没有配图)。

## 1. Inngest(Runs + Trace,最贴近我们的右侧时间线)

看的页面:[Inngest Traces 文档](https://www.inngest.com/docs/platform/monitor/traces)(截图 `.scratch/refs/inngest-1-trace-overview.webp`、`inngest-2-run-detail.webp`)

- **版面分区**:最左是一条只放图标、不放文字的窄侧栏(目测占页面宽度 3% 左右);往右是主内容——顶部是筛选条(搜索框、时间范围、状态、App 下拉、"13 runs" 计数、列设置);点某一条 run 后,详情**直接在该行下方展开**,分成左右两栏:左边"运行信息卡 + 时间线"占大约55%,右边"Input/Output JSON 面板"占大约45%,中间有可拖拽的分隔条。
- **状态表达**:圆点(绿色）+ 文字状态词("Completed"),就放在大标题正上方一行,不单独做徽章。
- **时间线呈现**:典型瀑布图/甘特图。顶部一条时间刻度尺(0ms、403ms...到总耗时),下面每个 step 一行,可展开出子行(比如"charge-card"展开后能看到"Inngest 排队耗时"和"你的服务器实际执行耗时"两条子条,方便区分"卡在哪一侧")。条形颜色:纯绿色实心 = 正常执行段,浅灰色 = 排队等待段,绿色斜纹填充 = 另一种等待态。选中的行整体高亮蓝底。
- **容量/占用**:没有,这个页面不涉及。
- **字体**:标题和标签是常规无衬线粗体;时间戳、Run ID、JSON 内容用等宽字体。JSON 有行号和语法高亮(键是白色,字符串是绿色,数字是橙色)。
- **间距**:偏紧凑,字段两两一组紧贴,组之间空一行,不铺张。
- **用色**:背景接近纯黑;绿色是唯一的"成功/强调"色;蓝色仅用在选中态和链接;其余全是灰阶文字分层。
- **深浅色**:深色。
- **刻意没做的事**:没有任何阴影卡片、没有装饰性图形,颜色只服务于状态判断,不做美化。

## 2. Temporal(Event History 时间线,信息密度最高的参考)

看的页面:[Temporal changelog——Updated Event History Timeline View](https://temporal.io/changelog/updated-event-history-timeline-view-is-now-available)(截图 `.scratch/refs/temporal-1-timeline.png`)

- **版面分区**:最左是纯图标竖栏(无文字,底部有主题切换和版本号"2.30.0");主区上方是 Input/Result 两栏卡片;下方"Event History"占满剩余宽度,是全页的重点。
- **状态表达**:这张截图里状态主要靠时间线条形的颜色/填充图案表达,而不是单独的文字徽章。
- **时间线呈现**(全场最密的一张):
  - 顶部有一条**整体缩略图**——把全部事件压缩成密密麻麻的竖线条,一眼看出事件在整个时间范围里的分布疏密。
  - 下面是"泳道":每种 Activity 一行,深绿实色条 = 正常执行一次;橙红色斜纹密集填充条 = 同一个 activity 反复重试(用纹理密度直接表达"这里卡住在反复重试",不用文字堆砌)。
  - 底部时间刻度尺(5s、10s...1m37s),两端有完整时间戳竖排。
  - 事件类型筛选做成一排彩色勾选框(Activity/Child Workflow/Local Activity/Signal/Timer/Update/Other),外加一个"Pending and Failed Only"总开关。
  - 事件列表每行:图标 + 加粗类型名 + 内联 key:value(值用高亮色块包住,比如 `Activity Type: activity.retry-on-failure`);重试计数用红色小胶囊"5 / 15";行右侧有分组事件 ID 数字簇和耗时。
  - 视图有 All / Compact / JSON 三态切换,还有排序、播放暂停、下载、分页(每页数量可调)。
- **容量/占用**:无。
- **字体**:ID、时间、事件类型值用等宽字体;标签用无衬线。
- **间距**:很密,但靠颜色分区撑住可读性。
- **用色**:纯黑背景,蓝紫做选中/主题色,绿=成功,橙红=重试或异常。
- **深浅色**:深色。
- **刻意没做的事**:没用 emoji,没有额外解释文字,复杂状态全靠颜色+填充纹理+分组数字表达。

## 3. Buildkite(Pipelines / Builds,浅色 SaaS 范本)

看的页面:[Buildkite Dashboard Walkthrough](https://buildkite.com/docs/pipelines/dashboard-walkthrough)(截图 `.scratch/refs/buildkite-1~4`)

- **版面分区**:顶部横向导航(Pipelines/Builds/Clusters/Test Suites/Packages/Settings);列表页是纵向堆叠的"流卡片"而不是表格,每张卡片横向分三段:左边 emoji 图标+名称+一句话描述,中间是构建历史的"心电图"柱状图,右边是三列统计数字(Speed/Reliability/Builds per week)。build 详情页顶部是名称+描述+操作按钮,下面构建记录按分支分组(灰色可折叠分组头)。
- **状态表达**:绿色圆勾 = 通过,配文字"Passed in 7m";失败预期是红色(本次截图未直接看到失败态,不做推断)。
- **时间线/日志呈现**:构建行内联"step 芯片"——图标 + 勾选 + 名称,部分带完成度计数(如"Lint all the things 6/6"),鼠标悬浮在步骤区会弹出"Hide steps"提示。
- **容量/占用怎么画**:没有容量条,但用**柱状历史图**表达"最近这些构建跑得快不快、稳不稳"(柱高 = 耗时,颜色 = 通过/失败),这是它替代"状态趋势"的手法。
- **字体**:系统级无衬线;commit hash、数字用等宽。
- **间距**:偏宽松,卡片间留白大,不追求塞满一屏。
- **用色**:白底为主,绿/红是仅有的两个状态色,emoji 图标给每个 pipeline 一点彩色识别度。
- **深浅色**:浅色。
- **刻意没做的事**:没有做成密集表格,构建列表选择了"卡片+图表"的仪表盘感,信息密度主动做了克制。

## 4. HashiCorp Nomad(资源占用条,是我们顶部容量条最直接的参考)

看的页面:[Nomad Web UI 教程](https://developer.hashicorp.com/nomad/tutorials/archive/web-ui-cluster-info)(截图 `.scratch/refs/nomad-1~3`)

- **版面分区**:顶部绿色品牌横条(Logo + 文档链接),次级绿条放 Region 下拉和页面标题;左侧纯文字侧栏分两组(WORKLOAD:命名空间下拉+Jobs;CLUSTER:Clients/Servers,选中项是**蓝色文字+蓝色左边框**);右边是主表格区。
- **容量/占用怎么画**(重点参考):"Resource Utilization" 卡片里 CPU 和 Memory 各是独立的子卡片,并排放置。每个子卡片 = 上面一张时间序列面积图(蓝色渐变填充给 CPU,红色渐变给 Memory)+ 下面**单独一条水平容量条**(彩色填充 vs 灰色轨道)+ 条右侧一个大字百分比("33%"、"76%")+ 条下面一行绝对数值("4406 MHz / 13200 MHz reserved")。趋势图和容量条是分开的两个组件,不是一个东西。
- **状态表达**:同一个产品里两种表达方式并存——Clients 列表用**纯文字变色**(蓝色 draining、橙色 ineligible、默认黑色 initializing/ready)加一个橙色警告三角前缀标记异常行;Allocations 列表则改用**小色块图标(红/绿方块) + 文字**(failed/complete)。
- **字体**:无衬线为主,表格数字没有刻意等宽。
- **间距**:表格行距适中,资源卡片内部留白充足,数字够大。
- **用色**:绿色品牌色只用在顶部横条;蓝色代表 CPU/正常,红色代表 Memory(不是失败,是配色分工),橙色是警告。
- **深浅色**:浅色。
- **刻意没做的事**:没把 CPU/Memory 塞进一张图抢着看;表格里没有到处放进度条,容量条只在专门的资源卡片里出现一次,不重复。

## 5. Claude Squad + Vibe Kanban(AI 苦工编排类,和我们最像的产品类别)

### Claude Squad
看的素材:[GitHub 仓库 README](https://github.com/smtg-ai/claude-squad) 内嵌截图(`.scratch/refs/claudesquad-1-screenshot.png`,取自仓库 `assets/screenshot.png`)

- **版面分区**:整体是终端应用套上一层 macOS 窗口外框(红黄绿三色按钮)。左边"Instances"竖直列表占比不到 1/4 宽度;右边分 Preview/Diff 两个标签页,标签下方是代码区,最下面是一个命令输入框和全局快捷键提示条。
- **状态表达**:每条 instance 前面只有一个纯色圆点(看到的是绿色),不写状态文字,靠颜色和位置判断。
- **时间线/日志呈现**:代码 diff 是**字符级**高亮(不是整行标红/标绿,是行内具体改动的词组才上色块),标题栏紧跟一个 `+18 -4` 式的绿红数字统计。下方还有一段 AI 生成的自然语言变更摘要(要点列表)。
- **字体**:全篇等宽字体(终端应用本色)。
- **间距**:行高紧凑,符合终端习惯。
- **用色**:深色背景,绿/红做增删对比色,蓝紫做选中边框。
- **深浅色**:深色。
- **刻意没做的事**:状态不写字,只给一个色点;没有时间戳堆砌。
- **额外可参考的小细节**:最底部有一条全局按键提示条,用"`n new · d kill · ↵/o open · s submit PR · c checkout | tab switch tab · q quit`"这种"键位+动作,用点和竖线分隔"的写法,一行说完所有快捷键。

### Vibe Kanban
看的素材:[官网首页](https://vibekanban.com/) 的产品截图(`.scratch/refs/vibekanban-1~3`)。**注意**:这几张图是官网营销页里裁切、旋转、加了投影的卡片局部,不是完整页面截图,看不到整体导航栏长什么样,只能看组件内部设计。

- 看到的看板列:列头是"圆点(颜色区分列,如 To Do 白圈、In Progress 蓝圆)+ 列名",卡片内是编号+标题+描述+彩色标签胶囊(项目分类)+ 负责 agent 的图标 + 负责人头像。
- 看到的"agent 活动流"卡片(这个和我们右侧时间线的诉求很接近):一句自然语言意图说明,下面是逐条带图标前缀的折叠动作记录(例如"Read 7 Files"、"Explored auth middleware + token storage"、"Found expiry handling missing in 2 places"),中间插入一个可点开的文件改动条("`TS auth/oauth.ts +18 -4`"),再下面是一个"3 To-dos"清单块,每条 todo 前面是勾选/转圈/时钟三种图标分别代表完成/进行中/等待。最底部是模型选择下拉+附件/语音图标+橙色发送按钮。
- 字体偏圆润的无衬线,配色是米白底+黑字+橙色点缀,风格比其它几个"极客范"产品更柔和。

## 6. Grafana(告警状态表达,三种模式都有真实截图)

看的页面:[Grafana Alerting 文档](https://grafana.com/docs/grafana/latest/alerting/monitor-status/view-alert-state/)(截图 `.scratch/refs/grafana-1~3`)

- **状态表达**(看到三种并存的写法):
  1. 面板标题旁一个"心形"图标,破碎/红色 = 告警中;
  2. 列表卡片:图标(火焰 = Firing)+ 彩色状态词("FIRING" 红色、"INACTIVE" 绿色)+ 次要行给出持续时长或实例数("FIRING for 1h 33m 4s"、"4 instances, 4 hidden by filters");
  3. 详情页大标题旁一个纯色圆点 + 状态词("Firing"),配套的筛选是一排分段按钮(Normal/Alerting/Pending/NoData/Error),当前有数据的那个按钮上带数字徽章。
- **时间线呈现**:告警对应的时间序列折线图上,阈值穿越点用竖直虚线(黄色/红色)+ 底部小三角标出,点击可以展开一张"ALERTING + 精确时间戳"的深色提示卡,里面是一行等宽格式的 `label=value` 详情和编辑/删除图标。
- **标签怎么画**(值得借鉴的细节):标签统一用**两段式胶囊**——左边深色的 label 段("severity"),右边彩色的 value 段("low",绿色底),同一行可以并排好几个标签胶囊(severity:low、team:frontend），扫视效率比纯文字标签高。
- **字体**:标签用无衬线,label=value 详情用等宽。
- **用色**:绿=正常,红/粉=告警,黄=阈值/pending;标签胶囊的颜色是分类色,不代表状态,和状态色系分开。
- **深浅色**:文档示例是深色主题。
- **刻意没做的事**:胶囊没有渐变、没有阴影,纯色块+清楚留白。

## 7. Linear(侧栏密度与字体,官方设计博客真实截图)

看的页面:[How we redesigned the Linear UI](https://linear.app/now/how-we-redesigned-the-linear-ui)(截图 `.scratch/refs/linear-1-sidebar.png`、`linear-2-full.png`,官方设计团队自己annotate 过的原图)

- **版面分区**:侧栏本身看起来占整体窗口宽度不到 20%(按常见 1440px 窗口折算大约 220~260px)。结构从上到下:工作区名+切换箭头+搜索+撰写按钮(圆角方形,常态透明,悬浮/激活才有浅色底)→ "Inbox"(带未读数字徽章)、"My issues" 两个一级项 → 分组头"Workspace"(暗灰色小字+下拉箭头)→ Views/Roadmaps/Teams → 分组头"Favorites" → 收藏项(图标带各自颜色) → 分组头"Your teams" → 团队下再嵌套 Issues/Active/Backlog 等二级项,整体继续调暗、缩进加深。
- **状态/选中表达**:当前选中项("Mobile App")是**整行浅灰圆角高亮块**,不是边框线,官方博客原话是"让不重要的部分退后,重要的部分才有视觉权重"。
- **字体**:官方博客原文提到这次改版新增了"Inter Display"字体用在标题上,正文是常规无衬线;同一层级内字号统一,层级的主次靠**明暗对比**而不是字号大小区分。
- **间距**:行高不算特别紧凑,图标和文字对齐工整;分组之间空得开,组内挨得紧。
- **用色**:背景接近纯黑;只有一个蓝紫色作为强调色(用在选中态图标着色、按钮上);剩下全靠 4~5 级灰阶做层次。
- **深浅色**:深色(官方博客原文也提到这次改版专门做了"更深的暗色模式")。
- **刻意没做的事**:放弃了"左边框竖线"这种选中标记方式,改成整行色块;分组标题特意调暗,不跟内容抢注意力。
- 另外看到一张项目动态/评论页(`linear-2-full.png`):状态用"图标+颜色文字+人名+日期"一行表达("✔ On track by yann Mar 4"),进度用"里程碑名 + 百分比前后对比"("Private Beta · 90% → 98%"),这种"变化前→变化后"的写法比单纯一个进度条多了时间维度的信息。

## 9. Vercel(仅作日志行密度参考,截图是历史旧版界面)

看的页面:[Vercel Dashboard Redesign 博客](https://vercel.com/blog/dashboard-redesign)里嵌入的历史截图(`.scratch/refs/vercel-1~3`)

## 对我们的建议

1. **顶部容量条的悬浮提示卡,主次关系照 Nomad 资源卡的顺序来**:大字号放最想让人一眼看到的数字(比如槍位占用"14/20"),下面配小字细节(项目目录、标题、已运行时长),不要让细节文字比数字还抢眼。(借鉴 Nomad)
2. **右侧活动时间线做成瀑布图/甘特图,而不是纯文字日志往下滚**:每个工具调用(读文件/跑命令/改文件)在时间轴上画成一条有宽度的色块,支持展开子步骤看更细的耗时构成。(借鉴 Inngest、Temporal)
3. **"反复重试"或"长时间卡住"这类状态,用填充纹理(斜纹)区分,不是靠加深颜色**:一眼能看出"这一段在正常跑"和"这一段在反复重试",不用额外读文字。(借鉴 Temporal)
4. **时间线要有 All / Compact 两种密度切换 + 按事件类型的复选筛选**:苦工跑起来事件量会很大,压缩视图和按类型(读文件/跑命令/改文件/报错)筛选应该是一开始就做的基础能力,不是后补的高级功能。(借鉴 Temporal)
5. **工具调用行用"图标+一句话摘要",文件改动单独给一条 diff 统计条**:参照 Vibe Kanban 的"Read 7 Files"、"Explored auth middleware + token storage"这种一行摘要写法,改动的文件用`文件名 +18 -4`的独立小条,不要把改动细节写进摘要文字里。(借鉴 Vibe Kanban)
6. **计划/待办类的展示用"勾选、转圈、时钟"三态图标**(完成/进行中/等待),Vibe Kanban 和 Claude Squad 都用了这个模式,适合我们展示苦工任务分解后的执行进度。(借鉴 Vibe Kanban、Claude Squad)
7. **结束后的结构化回报卡片,可以做成竖直状态时间线**:关键节点(开始→结束,或者分几个阶段)用圆点+竖线连接,每段配一个耗时,不需要长篇大论,一张卡讲清楚"发生了什么、花了多久"就够。(借鉴 Trigger.dev)
8. **左栏苦工状态用"图标+彩色状态词",而不是只给一个纯色点**:参照 Grafana 列表(火焰图标+红字"FIRING"、勾选图标+绿字"INACTIVE"),文字状态词比纯色点更快读,对色觉不敏感的人也更友好,正好对应我们"排队中/工作中/已完成/失败/已取消"五种状态。(借鉴 Grafana)
9. **左栏选中态用整行圆角高亮块,分组标题主动调暗**:Linear 最新改版放弃了左边框竖线,改成整行浅色块;项目分组标题(相当于我们的"工作目录"分组)可以比苦工标题暗一档,层级靠明暗对比,不靠字号大小。(借鉴 Linear)
10. **项目/角色这类标签用两段式彩色胶囊(深色文字段+彩色数值段)**:参照 Grafana 的 `severity:low`、`team:frontend` 标签胶囊,在密集列表里比纯色文字标签更容易扫视区分归属。(借鉴 Grafana)
11. **容量条上的"排队数量"单独用小字标在条形旁边,不要和槍位占用的色块挤在一起**:参照 Grafana 列表行"主状态词+次要行给数字"的分层写法(如"FIRING for 1h 33m 4s"下面再跟一行"4 instances, 4 hidden by filters"),排队数应该是那个"次要行"角色。(借鉴 Grafana)
12. **苦工元信息(项目/角色/耗时/退出状态)用"上小灰字标签、下大号深色数值"的两行式网格铺开**:这个排版手法本身和产品新旧无关,截图虽是 Vercel 的历史旧版界面,但网格排布方式仍然值得直接照搬。(借鉴 Vercel,注:该截图为 2019 年历史版本,不代表 Vercel 当前设计)
