# 界面层 · 控制台框架

> 模块定位：看板的地基——技术栈、令牌映射、共享组件、窗口栏与侧栏、工作区、路由、搜索弹窗、数据层（数据源、查询钩子、仓库、纯函数）、演示数据、验收脚本 · 对应代码：`apps/web/src/{app,components,api,state,lib,hooks,styles}/`、`apps/web/src/api/demo/`、`scripts/ui/`、`scripts/check-tokens.mjs` · 所属里程碑：[M6 第二版控制台看板](../roadmap.md#m6)、[M7 第三版界面](../roadmap.md#m7) · 状态：第三版已实现，待用户确认 · 最近更新：2026-09-29
>
> 视觉与交互规范：[前端设计](../前端设计.md)（第三版）；实现规格：[站点层 DESIGN.md](../../apps/web/DESIGN.md)、[骨架](../../apps/web/design/骨架.md)、[演示数据](../../apps/web/design/演示数据.md)。各页模块：[任务](界面层-任务.md)（看板、列表、详情）、[槽位](界面层-槽位.md)、[总览](界面层-总览.md)。

## 1. 职责与边界

- **管：** 全站共用的一切——依赖和构建配置、设计令牌到 Tailwind 类名的映射、shadcn/ui 组件源码、业务共享组件、窗口栏、侧栏（桌面常驻与窄屏抽屉）、工作区面板、提示条、连不上服务的整页提示、搜索弹窗与 Ctrl K、哈希路由、数据源接口与真实实现、TanStack Query 钩子、全局仓库、纯函数、演示数据与演示数据源、写死颜色的门禁、截图与交互检查脚本。
- **不管：** 各页的区块（各页模块负责）；任何业务规则（统计口径、调度都在服务端和核心层算好）。

## 2. 结构与数据流

```text
main.tsx ─▶ pickDataSource(?demo=…) ─▶ initNow、initWorkerStore（渲染前就绑定数据源）
        ─▶ QueryClientProvider + DataSourceContext + RouterProvider(createHashRouter) + Toaster
AppShell（浅灰窗口）
  ├─ WindowBar（38px）：侧栏开关 · 居中的「搜索任务」入口 · 槽位占用「槽位 23/40 · 排队 7」
  ├─ AppSidebar（240px）：≥1024 常驻（开关存本地存储）；<1024 只有左侧抽屉
  │     产品标记 → 任务 / 槽位 / 总览（当前项整行浅灰）→「项目」分组（点项目 = 重置筛选 + 只看这个项目）
  ├─ 工作区面板（近白、1px 细线、圆角 6）
  │     ShellBanners（断线、配置出错）→ ConnectionGate → <Outlet />（各页：ViewBar → FilterBar → data-page-body）
  ├─ SearchDialog（searchStore.open；Ctrl K / ⌘K 切换）
  └─ 挂载时：订阅快照流 → snapshotStore；useLiveInvalidation
数据：
  快照流（SSE）──▶ snapshotStore ──▶ 看板、侧栏计数、窗口栏占用、实时指标、槽位表格
  普通请求（TanStack Query）：统计 / 任务列表（无限加载）/ 项目 / 搜索 / 启停 / 排序
  快照里「有任务开始或结束」──▶ 节流失效：统计 5 秒、任务 2 秒、项目 30 秒
```

- 令牌：`styles/tokens.css`（唯一出现色值的文件，浅色默认、系统深色时换值）→ `styles/globals.css` 的 `@theme inline` 映射成 `bg-window`、`bg-panel`、`bg-column`、`bg-card`、`bg-selected`、`text-fg-1～3`、`text-status-*`、`text-12～16`、`rounded-sm/md/lg`、`shadow-card/panel/overlay` 等类名，并把 shadcn 期望的语义名接到本项目令牌上；全站 lucide 图标描边统一 1.7。
- 共享组件（`components/`）：状态图标（Linear 式五种内联图形）、状态词、标签、项目标签、视图栏、筛选栏、视图切换、面板、指标条、按键提示，加上沿用第二版的色点、时长、路径、复制按钮、空态、错误态、提示条、分段切换、时间范围、维度切换、图例、用量拆分、回报结论。
- 仓库（`state/`）：快照、单任务详情、当前时刻、总览筛选、任务筛选（默认「全部」），第三版新增侧栏开关、最后停在看板还是列表、看板展开的列、卡片显示哪些信息、搜索弹窗开关，以及按项目 key 查名字和色位的钩子。
- 纯函数（`lib/`）：第三版新增看板分列与排序、卡片进度小片、搜索匹配与合并；筛选小标签改成按视图出、文字直接给最终形态。

## 3. 关键决策

| 决策 | 理由 |
|---|---|
| 第三版视觉完全由令牌换掉，组件结构不动 | 第二版已经做到「只通过令牌控制外观」，换一套令牌加少量组件就换了一身；数据层和交互照旧 |
| 选中态用半透明浅灰（`bg-selected`），强调色只留给焦点、开关、链接、主按钮 | 设计提炼规定「只对当前入口施加一整行浅灰」；强调色退到最少 |
| 悬停和选中用半透明色 | 同一个令牌在浅灰窗口和近白面板上都自然变深一点 |
| 状态图标自绘，不用 lucide | Linear 式的虚线圈、半填充圈、实心勾一眼能分；lucide 没有半填充圈 |
| 窄屏侧栏用抽屉，不再收成图标栏 | 设计提炼有「手机侧栏」；240px 常驻在窄屏太挤 |
| 侧栏点项目 = 重置其他筛选 + 设项目 | 跟 Linear 切团队一样，避免带着上一个项目的搜索词进来 |
| 任务筛选默认「全部」 | 进行中的由看板承担，列表查历史 |
| 数据源在渲染前就交给时钟和详情仓库 | React 先跑子组件的副作用：直接打开详情链接时，详情会比外壳先去订阅；第二版就有这个隐患（以前的检查只改地址不刷新，没暴露） |
| 搜索先查快照再补接口结果 | 快照里的立刻出；编号前缀只能在快照里匹配（接口只搜标题） |
| 门禁拦停用的字号字重和旧类名 | 字重只许 400 / 500、字号只许 12～16 四档，防止旧写法混回来 |
| 路由用 `createHashRouter`，首页改成 `#/tasks` | 服务端静态托管；第二版的 `#/overview`、`#/slots`、`#/tasks/<编号>` 和第一版的 `#/w/<编号>` 都还能打开 |

## 5. 验证方式

- 纯函数和演示数据单测：`pnpm exec vitest run apps/web`。
