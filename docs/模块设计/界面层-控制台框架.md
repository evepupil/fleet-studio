## 1. 职责与边界

- **管：** 全站共用的一切——依赖和构建配置、设计令牌到 Tailwind 类名的映射、shadcn/ui 组件源码、业务共享组件、左侧菜单、顶栏、提示条、连不上服务的整页提示、哈希路由、数据源接口与真实实现、TanStack Query 钩子、全局仓库、纯函数、演示数据与演示数据源、写死颜色的门禁、截图与交互检查脚本。
- **不管：** 三个页面的区块（各页模块负责）；任何业务规则（统计口径、调度都在服务端和核心层算好）。

## 2. 结构与数据流

```text
main.tsx ─▶ QueryClientProvider + DataSourceContext(pickDataSource) + RouterProvider(createHashRouter)
AppShell
  ├─ 挂载时：initNow、initWorkerStore（绑定数据源）、订阅快照流 → snapshotStore；useLiveInvalidation
  ├─ AppSidebar（三项菜单，收起状态存本地存储；< 1024 强制收起）
  ├─ ShellBanners（断线、配置出错）
  └─ ConnectionGate（第一次就没连上时整页提示）→ <Outlet />（各页：PageHeader + 自己的滚动区）
数据：
  快照流（SSE）──▶ snapshotStore ──▶ 实时卡片、槽位表格、进行中任务的实时刷新
  普通请求（TanStack Query）：统计 / 任务列表（无限加载）/ 项目 / 启停 / 排序
  快照里「有任务开始或结束」（activitySignature 变化）──▶ 节流失效：统计 5 秒、任务 2 秒、项目 30 秒
```

- 数据源两种实现：真实（`liveSource`，SSE + fetch，写请求带首页 meta 里的看板令牌）和演示（`?demo=busy|empty|failure|offline|disabled`，固定当前时刻，统计用核心层 `computeStats` 现算，任务查询用内存里的同语义实现）。
- 令牌：`styles/tokens.css`（唯一出现色值的文件）→ `styles/globals.css` 的 `@theme inline` 映射成 `bg-panel`、`text-fg-2`、`border-line` 等类名，并把 shadcn 期望的语义名（background、primary、accent……）接到本项目令牌上；全站边框默认色是 `--line`。

## 3. 关键决策

| 决策 | 理由 |
|---|---|
| 组件库用 shadcn/ui（源码进仓库），样式 Tailwind 4 | 用户拍板标准化；它底层正是原先选的 Radix、lucide、Recharts、react-day-picker；外观全由令牌控制 |
| shadcn 的 accent 语义映射到悬停底，本项目的强调蓝叫 brand | 两套命名撞名；shadcn 组件里的 accent 本来就是悬停底 |
| 阴影在主题里全部清零，只留弹出层 | 前端设计规定卡片无投影 |
| 路由用 `createHashRouter` | 服务端静态托管、刷新不需要服务端路由；第一版 `#/w/<编号>` 重定向到 `#/tasks/<编号>` |
| 筛选条件放内存仓库、不进网址 | 用户明确不要把筛选记进网址 |
| 快照仍走 zustand，普通请求走 TanStack Query | 快照是推送流；统计和列表是拉取，需要缓存、节流重拉和无限加载 |
| 演示数据用固定种子生成 30 天历史 | 截图和交互检查每次结果一致；数字写成单测 |
| 自选日期维护独立草稿，第二次点击日期才提交 | 日历默认第一次点击就给出同日起止，直接提交会阻止用户选择完整范围；取消时丢弃草稿 |
| 已选自选日期允许重复打开 | 下拉的自选项作为打开日历的操作；分段控件提供 `onReselect` 回调供时间控件使用 |

## 4. 当前实现

- 地基一路（luna）搭完依赖、令牌映射、20 个 shadcn 组件、17 个业务共享组件、骨架、数据层和 59 个纯函数单测；跑满 90 分钟被结束后续接补了三处后加的规格（时间段标签格式、任务的渠道和模型筛选、「其他」的配色）。
- 演示数据一路（dsf）：在跑一批 42 个苦工、30 天历史 764 个、五个场景、演示数据源；52 个单测把所有交互检查要用的数字固定下来。
- 主控验收时修了一处：任务详情的仓库没有绑定数据源（第一版在 App 里绑，第二版骨架漏了），在 AppShell 里补上。
- 截图验收发现并修掉：全站边框是近黑色（Tailwind 4 的边框默认色，补了基础层）、统计卡片内容没有顶端对齐。
- 时间控件每次打开日历时按窗口宽度决定显示一月或两月，初始月份取已选范围或当前日期；当前日期跟随数据源，演示场景也能稳定复验。下拉关闭时若正在打开日历，保留日历焦点；单日范围、倒序点击、取消和再次修改均使用同一套行为。
- 验收脚本：`scripts/ui/shoot.mjs`（80 张：五种场景，四档宽度，两种主题）、`scripts/ui/probe.mjs`（52 条交互断言）、`scripts/ui/probe-task-filters.mjs`（筛选专项）。下拉操作共用 `scripts/ui/interactions.mjs`，检查菜单可见、选项可点击后发送真实鼠标输入，避免直接调用 `click()` 漏掉菜单位于屏幕外的问题。

## 5. 验证方式

- 纯函数和演示数据单测：`pnpm exec vitest run apps/web`（15 个文件）。
- 门禁：`pnpm check`（含扩展后的写死颜色检查：拦截色值、方括号色值、Tailwind 自带调色板）。
- 截图：`pnpm --filter @fleet/web build` 后 `node scripts/ui/shoot.mjs <标签>`，看 `.fleet/shots/<标签>/`；交互：`node scripts/ui/probe.mjs`。
- 筛选回归：构建后运行 `node scripts/ui/probe-task-filters.mjs`；包含任务页完整筛选交互、800px 宽与深色主题，以及总览自选日期重复打开。截图在 `.fleet/shots/task-filters-current/`。
