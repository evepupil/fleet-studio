# 测试支撑 · 假苦工

> 模块定位：两个假的运行时脚本，按剧本吐出和 pi、opencode 一样格式的输出，让集成测试和看板演示不依赖真实模型 · 对应代码：`packages/testkit/` · 所属里程碑：[M1 闸门服务与 fleet 命令](../roadmap.md#m1) · 状态：已完成 · 最近更新：2026-09-23

## 1. 职责与边界

- **管：** `fake-pi.mjs`、`fake-opencode.mjs` 两个脚本；给测试用的辅助函数。
- **不管：** 生产代码不得依赖本包。

## 2. 结构

| 文件 | 内容 |
|---|---|
| `packages/testkit/bin/fake-pi.mjs` | 假 pi（纯 JavaScript，Node 直接运行，不经过编译） |
| `packages/testkit/bin/fake-opencode.mjs` | 假 opencode |
| `packages/testkit/bin/scenario.mjs` | 两个脚本共用：从任务文字里读剧本、延时、写轨迹 |
| `packages/testkit/src/index.ts` | `fakePiCommand()`、`fakeOpencodeCommand()`、`scenarioPrompt()`、`readTrace()`、`maxConcurrency()` |

## 3. 规格

### 3.1 剧本怎么指定

任务文字里写标记，例如 `[[scenario:success]] [[delay:200]] 其余任务文字`：

| 标记 | 含义 | 缺省 |
|---|---|---|
| `[[scenario:<名字>]]` | 剧本 | `success` |
| `[[delay:<毫秒>]]` | 相邻两个输出事件之间的间隔 | 20 |
| `[[tools:<次数>]]` | 成功剧本里调用几次工具 | 1 |
| `[[exit:<码>]]` | `crash` 剧本的退出码 | 3 |

剧本：

| 名字 | 假 pi 的行为 | 假 opencode 的行为 |
|---|---|---|
| `success` | 会话行 → 若干轮工具调用和结果 → 最后一条带回报的助手文字（`stopReason: "stop"`；回报是固定格式的五段 SUMMARY / FILES / VERIFY / SELF_REPORT: pass / BLOCKED，任务文字去掉标记后非空时改用那段文字）→ `agent_end` → `agent_settled`，退出码 0 | `step_start` → 工具事件 → 文字 → `step_finish`（reason `stop`，带用量），退出码 0 |
| `model-error` | 助手消息 `stopReason: "error"`、`errorMessage: "404: model not found"` → `agent_end` → `agent_settled`，退出码 0 | 只输出一行 `error` 事件，退出码 1 |
| `retry-storm` | 无限循环：失败的助手消息 + `auto_retry_start`，永不退出 | 不支持（等同 `hang`） |
| `no-key` | stdout 只有会话行；stderr 打印 `No API key found for mcgrox.`；退出码 1 | stderr 打印一行错误，退出码 1 |
| `hang` | 输出会话行后永久等待（不退出、不再输出） | 输出 `step_start` 后永久等待 |
| `crash` | 输出一部分事件后以 `[[exit]]` 退出，末尾没有收尾事件 | 同左 |
| `spawn-child-hang` | 拉起一个会睡眠的子进程，然后自己也永久等待（测结束进程树） | 同左 |

事件格式照调研报告和 `packages/core/test/fixtures/` 里的真实样本逐字段模仿：假 pi 的会话编号取 `--session-id`，助手消息带 `usage`（例如 input 100、output 20）；假 opencode 每行带 `type`、`timestamp`、`sessionID`（首次运行生成 `ses_fake<随机>`，续接时沿用 `--session` 传入的值）。

### 3.2 必须模仿的真实行为

- **stdin**：启动后如果 `process.stdin.isTTY` 为假，先把 stdin 读到结束再继续（真实 pi / opencode 就是这样，所以 stdin 没关闭时假苦工也会卡住，能测出进程托管有没有把 stdin 设成 `ignore`）。
- **参数**：假 pi 按真实 pi 的方式取任务：`-p` 后面紧跟的那个参数；有 `@<文件>` 参数时把文件内容读进来拼在任务前面。假 opencode 取最后一个位置参数为任务，`-f <文件>` 读附件。两者都不校验其余参数，但要把收到的完整参数数组写进轨迹。
- **输出方式**：每个事件一行 JSON 写到 stdout，逐行写（不要攒到最后一次性写）。

### 3.3 轨迹文件

环境变量 `FLEET_FAKE_TRACE` 指向一个文件时，每个假苦工进程在开始和结束时各追加一行 JSON：`{"event":"start"|"end","pid":…,"at":<毫秒>,"runtime":"pi"|"opencode","args":[…],"cwd":"…"}`（`end` 行不需要 `args`）。被强制结束的进程写不出 `end` 行，这是预期的。

### 3.4 `src/index.ts`

| 导出 | 作用 |
|---|---|
| `fakePiCommand(): string[]` | `[process.execPath, fake-pi.mjs 的绝对路径]`，直接写进配置的 `runtimes.pi.command` |
| `fakeOpencodeCommand(): string[]` | 同上 |
| `scenarioPrompt(name, options?): string` | 拼出带标记的任务文字，`options` 可带 `delayMs`、`tools`、`exitCode`、`text` |
| `readTrace(file): TraceEntry[]` | 读轨迹文件 |
| `maxConcurrency(entries): number` | 按 start / end 时间算出同时在跑的最大个数（没有 end 的按「一直在跑」算） |

## 4. 验证方式

`packages/testkit/test/` 下：每个剧本各跑一次两个脚本（真实子进程，`stdio` 第一项为 `"ignore"`），检查输出行格式、退出码、轨迹；再测一次 stdin 不关闭时会卡住（1 秒内不退出，测完结束它）；`maxConcurrency` 纯测。
