# 界面层 · 工作区看板

> 模块定位：只读看板，把快照和苦工时间线画出来 · 对应代码：`apps/web/` · 所属里程碑：[M2 工作区看板](../roadmap.md#m2) · 状态：已完成 · 最近更新：2026-09-23
>
> 视觉与交互规范：[前端设计](../前端设计.md)（令牌、状态画法、无障碍）；实现规格：[站点层](../../apps/web/DESIGN.md)、[页面层](../../apps/web/design/工作区.md)。

## 1. 职责与边界

- **管：** 连接服务的两路 SSE、维护页面状态、渲染容量条、项目与苦工列表、苦工详情和时间线；演示数据源（给截图验收和离线查看用）。
- **不管：** 任何写操作；任何业务规则（快照里已经算好的东西不在前端重算，例如排队位置、池健康、今日用量）。
- 只依赖 `@fleet/core` 的类型和少量纯函数（状态中文名、失败原因中文名、接口路径）。

## 2. 结构与数据流

```text
main.tsx ─▶ App
  数据源（真实 / 演示）
    ├─ 全局快照流 /api/stream ──▶ snapshotStore（快照、连接状态）
    └─ 选中苦工时 /api/workers/:id + /api/workers/:id/stream?after=<seq> ──▶ workerStore（详情、时间线）
  selectionStore：选中编号（与地址栏 #/w/<编号> 同步）、展开的项目（本地存储）、左栏筛选
  视图：AppBar · Banner · CapacityStrip · ProjectList · WorkerDetail
```

- 数据源是一个接口（`DataSource`），真实实现走 `EventSource` 和 `fetch`，演示实现从内置数据生成同样的快照和事件。地址栏带 `?demo=<场景>` 时用演示实现，场景有 `busy`、`empty`、`failure`、`offline`。
- 断线重连：`EventSource` 出错后按 1、2、4、8、10 秒退避重连；重连成功后全局流会重新推完整快照，单苦工流带上已收到的最大 `seq` 续传。
- 时长每秒刷新：全页只有一个 1 秒定时器，所有时长组件订阅它。

## 3. 关键决策

| 决策 | 理由 |
|---|---|
| 服务端推完整快照，前端整块替换 | 快照在 100 个苦工时只有几十 KB；前端不做增量合并，最不容易错 |
| 选中状态放地址栏 | 刷新、复制链接后仍停在同一个苦工 |
| 演示数据源进正式构建 | 截图验收和状态验收需要固定、可复现的数据；只通过地址参数开启，界面上没有入口 |
| 不用路由库 | 只有一个页面，地址栏只存一个苦工编号 |
| 列表不做虚拟滚动 | 快照最多 300 个苦工，直接渲染可接受；时间线超过 1000 条时只渲染最近 1000 条，顶部给「显示更早的」 |

## 4. 当前实现

- 地基（数据源、状态、14 个共享组件、页面骨架）一路，容量条、左栏、详情、时间线四路并行，全部按 `apps/web/DESIGN.md` 和 `apps/web/design/工作区.md` 转录；纯函数 55 个单测。
- 验收：演示数据四个场景 × 四档宽度 × 深浅两种主题共 18 张截图，无横向溢出；交互检查 19 项全部通过（`scripts/ui/probe.mjs`）；再接真实服务和假苦工，确认容量条、项目列表、时间线随实时推送更新，工作中的苦工自动滚到底。
- 验收中修过的问题：宽屏下容量数字被推到最右（改为紧跟最宽的计量条并上下对齐）；任务摘要显示成 Markdown 标题符号；切换到已结束的苦工时详情没回到顶部；直接打开带苦工编号的链接时所在项目组不展开。
- 演示数据里没有的两种画法在真实服务上补验：容量 60 的池按项目画连续分段条，容量 0 的池画虚线轨道和「已暂停」。

## 5. 验证方式

- 纯函数单测（`apps/web/src/lib/*.test.ts`）：时长与时间格式、路径中间省略、状态映射、时间线显示行的合并与过滤、演示数据的一致性（快照里的计数和苦工列表对得上）。
- 界面不写单测（全局规范）；用截图和交互探针验收：演示数据四个场景在 1440、1280、1024、800 四档宽度截图，深浅两种主题；探针检查展开项目、选中苦工、容量格键盘导航出提示卡、时间线筛选、跟随滚动与「回到最新」。
- 最后接真实服务和假苦工再截一轮。
