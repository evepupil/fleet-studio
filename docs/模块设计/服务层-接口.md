# 服务层 · 接口

> 模块定位：HTTP 接口、SSE 推送、来源与令牌校验、托管看板静态文件 · 对应代码：`packages/daemon/src/http/` · 所属里程碑：[M1 闸门服务与 fleet 命令](../roadmap.md#m1)、[M5 第二版底座](../roadmap.md#m5) · 状态：已完成（第二版已实现）· 最近更新：2026-09-26

## 1. 职责与边界

- **管：** 把 HTTP 请求翻译成对 `FleetService` 的调用、把结果和错误翻译回 HTTP；两路 SSE；安全校验；静态文件。
- **不管：** 任何业务逻辑。接口层只认 `packages/daemon/src/engine/service.ts` 里的 `FleetService` 契约，测试时用假服务。

## 2. 结构

| 文件 | 内容 |
|---|---|
| `http/createApp.ts` | `createHttpApp({ service, token, getPort, webDistDir, logger }): Hono` |
| `http/startServer.ts` | `startHttpServer(app, port): Promise<{ port: number; close(): Promise<void> }>`，只监听 `127.0.0.1`；`port` 为 0 时用系统分配的端口 |
| `http/guards.ts` | 主机名、来源、令牌、内容类型四道校验 |
| `http/errors.ts` | 错误码 → HTTP 状态码；zod 校验失败 → 中文说明 |
| `http/sse.ts` | SSE 写出工具：事件、心跳、节流 |
| `http/routes/*.ts` | 按资源分文件：`health`、`snapshot`、`workers`、`wait`、`pools`、`roles`、`shutdown` |
| `http/static.ts` | 看板静态文件 |
| `http/index.ts` | 汇总导出 |

## 3. 规格

### 3.1 路由

路径常量一律取 `@fleet/core` 的 `API_PATHS`。请求参数一律用 `@fleet/core` 里的 zod 模式校验。

| 方法 | 路径 | 令牌 | 行为 |
|---|---|---|---|
| GET | `/api/health` | 否 | `service.health()` |
| GET | `/api/snapshot` | 否 | `service.snapshot()` |
| GET | `/api/stream` | 否 | SSE，见 3.3 |
| GET | `/api/workers` | 否 | 查询参数按 `listWorkersQuerySchema`；`service.listWorkers` |
| POST | `/api/workers` | 是 | 请求体按 `submitRequestSchema`；返回 201 和 `SubmitResponse` |
| GET | `/api/workers/:id` | 否 | `WorkerDetail`，不存在 404 |
| GET | `/api/workers/:id/timeline` | 否 | 查询参数按 `timelineQuerySchema`；不存在 404 |
| GET | `/api/workers/:id/stream` | 否 | SSE，见 3.3 |
| POST | `/api/workers/:id/messages` | 是 | 请求体按 `sendRequestSchema`；返回 `{ worker }` |
| POST | `/api/workers/:id/cancel` | 是 | 无请求体；返回 `{ worker }` |
| GET | `/api/wait` | 否 | 查询参数按 `waitQuerySchema`；挂起等待，客户端断开时中止（把请求的中止信号传给 `service.wait`） |
| GET | `/api/pools` | 否 | `service.pools()` |
| PATCH | `/api/pools/:id` | 是 | 请求体按 `poolPatchSchema`；返回 `PoolView` |
| GET | `/api/roles` | 否 | `service.roles()` |
| POST | `/api/shutdown` | 是 | 返回 `{ ok: true }` 后调用 `service.requestShutdown()` |
| GET | 其他非 `/api/` 路径 | 否 | 看板静态文件，见 3.5 |
| 任意 | 其他 `/api/` 路径 | — | 404 `not_found` |

### 3.2 安全校验（按顺序，全部路由生效）

1. **主机名**：`Host` 请求头必须是 `127.0.0.1:<端口>` 或 `localhost:<端口>`（端口取实际监听端口），否则 403 `forbidden_origin`。防 DNS 重绑定。
2. **来源**：带 `Origin` 请求头时必须是 `http://127.0.0.1:<端口>` 或 `http://localhost:<端口>`，否则 403 `forbidden_origin`。防网页跨站调用。
3. **令牌**：表格里标「是」的路由必须带 `x-fleet-token` 且等于启动时生成的令牌（用定长比较），否则 401 `unauthorized`。
4. **内容类型**：带请求体的 POST / PATCH 必须是 `application/json`，否则 400 `invalid_request`。请求体上限 1MB，超过 400。

### 3.3 SSE

通用：`Content-Type: text/event-stream`，禁止缓存；每 15 秒发一行 `: ping` 心跳；客户端断开时取消订阅、清理定时器。

关停服务时，先停止接受新连接，再关闭存量 HTTP 连接（包括 SSE 和挂起等待），让流的中止清理正常执行。关停接口已等响应真正发送完才触发此流程。单独调用 Node 的 `server.close()` 会一直等待浏览器断开 SSE，造成端口停止监听但旧服务进程、数据库与内存仍驻留；当前 HTTP/1 服务同时调用 `closeAllConnections()` 结束这些连接，浏览器按既有重连逻辑接入新服务。

- **全局 `/api/stream`**：连上立刻发一条 `event: snapshot`（数据是完整快照 JSON）。之后订阅服务事件，收到 `snapshot` 类事件时节流：距上次发送不到 300 毫秒就等到满 300 毫秒再发一次最新快照（尾随发送，不丢最后一次变化）。
- **单苦工 `/api/workers/:id/stream?after=<seq>`**：苦工不存在返回 404（不开流）。连上先发 `event: worker`（完整详情），再把 `seq > after` 的历史事件按每批最多 500 条用 `event: timeline` 发完；之后订阅服务事件：该苦工的 `timeline` 事件原样转发（去掉 seq 不大于已发送最大 seq 的，防重复）；该苦工的 `worker` 事件节流 500 毫秒后发送最新详情。

### 3.4 错误

| 错误码 | 状态码 |
|---|---|
| `invalid_request` | 400 |
| `unauthorized` | 401 |
| `forbidden_origin` | 403 |
| `not_found` | 404 |
| `conflict`、`illegal_transition` | 409 |
| `runtime_unavailable` | 422 |
| `config_invalid`、`internal` | 500 |

响应体一律 `ApiErrorBody`。zod 校验失败的说明写成「请求参数不对：<字段>：<原因>；…」。非 `FleetError` 的异常一律 500 `internal`，说明「服务内部错误」，详细堆栈只写日志。

### 3.5 看板静态文件

- `webDistDir` 指向 `apps/web/dist`。请求路径映射到这个目录下的文件，存在就返回（按扩展名给 `Content-Type`；`assets/` 下的文件加长期缓存，`index.html` 禁止缓存）；不存在就返回 `index.html`（单页应用回退）。
- 路径里出现 `..` 或解析后跑出目录之外，一律 404。
- `index.html` 不存在时返回 200 纯文本「看板还没有构建，请在 fleet-studio 目录运行 pnpm build」。

## 4. 验证方式

`packages/daemon/test/http/` 下用假服务（实现 `FleetService`，记录收到的调用）起真实 HTTP 服务（端口 0）测：

- 每个路由的成功路径、参数校验失败、苦工不存在。
- 安全：错误的 `Host`、错误的 `Origin`、缺令牌、错令牌、非 JSON 内容类型、超大请求体。
- 错误码到状态码的映射。
- SSE：全局流首条是快照；连续触发 10 次变化，300 毫秒内最多发一次且最后一次一定发出；单苦工流先发详情再补历史，之后的增量不重复；客户端断开后服务端取消订阅。
- 停服：`test/app/shutdownStreams.test.ts` 保持真实看板 SSE 连接，再停止完整服务，验证无需客户端主动断开就能完成关停并删除自己的运行信息。该场景修复前稳定无法完成关停，修复后通过。
- 等待接口：客户端提前断开时服务收到中止信号。
- 静态文件：存在的文件、单页回退、`..` 越界、没有构建产物时的提示。

## 第二版（M5）：统计、任务、项目、启停和排序接口，看板令牌

> 所属里程碑：[M5](../roadmap.md#m5) · 依据：[技术设计 8.6](../技术设计.md#86-看板的写权限)、[架构设计 2.3](../架构设计.md#23-改设置路径第二版) · 服务契约见 `packages/daemon/src/engine/service.ts`，请求校验见 `packages/core/src/api/requests.ts`，路径见 `packages/core/src/api/paths.ts`（均由主控写好）

### 1. 新路由

| 方法 | 路径 | 令牌 | 说明 |
|---|---|---|---|
| GET | `/api/stats` | 否 | 查询参数按 `statsQuerySchema` 校验（不合法 400 `invalid_request`，消息取第一条问题），调 `service.stats` |
| GET | `/api/tasks` | 否 | 按 `tasksQuerySchema` 校验，调 `service.tasks` |
| GET | `/api/projects` | 否 | 调 `service.projects` |
| PUT | `/api/pools/:id/enabled` | 命令行令牌**或**看板令牌 | 请求体按 `poolEnabledRequestSchema`；调 `service.setPoolEnabled`；返回 `PoolView` |
| PUT | `/api/pools/order` | 命令行令牌**或**看板令牌 | 请求体按 `poolOrderRequestSchema`；调 `service.reorderPools`；返回 `PoolView[]` |

`/api/pools/order` 必须在 `/api/pools/:id` 系列之前注册，免得被当成编号为 `order` 的池。PUT 和 POST / PATCH 一样检查内容类型和请求体大小。

### 2. 看板令牌

- `startDaemon` 在生成命令行令牌的同时生成看板令牌（同样 `randomBytes(24).toString("hex")`），只放在内存里，**不写进** `daemon.json`；通过 `createHttpApp` 的依赖传给接口层（`dashboardToken`）。
- `static.ts`：返回 `index.html` 时（包括回退到 index.html 的情况），在 `</head>` 前插入 `<meta name="fleet-dashboard-token" content="<看板令牌>">`（名字取 `DASHBOARD_TOKEN_META`）；找不到 `</head>` 就插到文件开头。只改 index.html，其余静态文件原样。index.html 继续 `no-store`。
- `guards.ts`：现有 `requireToken` 改名为 `requireCliToken`（只认命令行令牌）；新增 `requireCliOrDashboardToken`（两个令牌任一匹配即可，都用定长比较）。只有第 1 节表里两个 PUT 路由挂后者；派活、续接、取消、改容量、关服务仍挂前者——看板令牌调用它们一律 401。
- 主机名和来源检查不变，仍然全局生效。

### 3. 错误码

`http/errors.ts` 的状态码映射加上 `pool_disabled → 409`。

### 4. 验证

`packages/daemon/test/http/`（用 `startTestServer` + 假服务，假服务补上五个新方法的默认实现）：

- 三个 GET 路由把查询参数正确交给服务，非法参数 400（如 `range=custom` 缺日期、`dimension=foo`、`limit=0`）。
- 两个 PUT 路由：不带令牌 401；命令行令牌 200；看板令牌 200；请求体错误 400；服务抛 `conflict` 时 409、抛 `not_found` 时 404。
- 看板令牌调 `POST /api/workers`、`PATCH /api/pools/:id`、`POST /api/shutdown` 都是 401。
- `GET /` 和随便一个前端路由返回的 HTML 里带 meta 且值等于看板令牌；`assets/` 下的文件原样返回；令牌不出现在 `daemon.json`（在 `startDaemon` 的测试里断言）。
- `pool_disabled` 映射成 409。
