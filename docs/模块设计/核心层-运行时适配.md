# 核心层 · 运行时适配

> 模块定位：把「用哪个运行时干活」的全部差异收进适配器：怎么拼启动参数、怎么读懂事件流、怎么判断事件流里的结局 · 对应代码：`packages/core/src/runtimes/` · 所属里程碑：[M0 工程骨架与领域核心](../roadmap.md#m0) · 状态：进行中 · 最近更新：2026-09-23

## 1. 职责与边界

- **管：** pi 和 opencode 两个适配器：`displayModel`、`buildLaunch`、`createReducer`；按运行时编号取适配器。
- **不管：** 找可执行文件、写文件、拉进程、读文件（进程托管的事）；进程退出后的最终结局（`resolveRunOutcome` 的事）。
- 事实依据：[pi 运行时调研](../调研/pi-运行时.md)、[opencode 运行时调研](../调研/opencode-运行时.md)。

## 2. 结构

| 文件 | 内容 | 谁写 |
|---|---|---|
| `types.ts` | 契约：`RuntimeAdapter`、`StreamReducer`、`RunProgress`、`BuildLaunchInput`、`LaunchSpec`、`ARGV_PROMPT_MAX_CHARS` | 主控（已完成） |
| `text.ts` | 共用小工具：`truncateText`、`oneLine`、`tailLines`、`joinFilePath`、`guardLeadingDash` | 主控（已完成） |

两个适配器目录内部的辅助函数不从目录 `index.ts` 导出，避免汇总入口重名。

## 3. 两个运行时共同的规则

- **解析器永不抛异常。** 包括时间戳：数值超出日期范围时按没有时间戳处理。 每一行先尝试 `JSON.parse`；不是 JSON、或解析结果不是带字符串 `type` 字段的对象，就产出一条 `output` 事件（`stream` 照传，文字截到 `TEXT_EVENT_MAX`），并把这一行记进「原始输出尾巴」。空行忽略。处理某一行时内部出错，产出一条 `error` 事件「解析事件出错：<原因>」后继续。
- **原始输出尾巴** `plainOutputTail`：只收非 JSON 的非空行，保留最后 5 行、总长 500 字符（用 `tailLines`）；从没出现过就是 null。
- **认识但不展示的事件类型**（见下文各表）不产出事件；**完全不认识的类型**也不产出事件，不算错误。
- **时间 `at`：** 事件行自带可用时间戳时用它（转成 ISO），否则用调用方传入的 `at`。`lastEventAt` 跟随每一行有效输出更新。
- **工具调用摘要 `summary`：** 按参数里第一个存在的字段取值压成一行（`oneLine`，160 字符）；字段优先级见各运行时。都没有就用参数 JSON 压成一行。`detail` = 参数的格式化 JSON（两空格缩进），截到 `TOOL_DETAIL_MAX`；参数是空对象时为 null。
- **最近活动 `activity`：** 每遇到一次工具调用，更新为 `<工具名> · <摘要>`。
- **工具结果预览：** 截到 `TOOL_RESULT_PREVIEW_MAX`，`truncated` 如实标记。
- **用量：** 数字字段不是有限数就按 0；费用字段不是有限数就保持原值（初值 null）。

## 4. pi 适配器

### 4.1 `displayModel(pool)`

`pool.runtimes.pi` 存在时返回 `<provider>/<model>`，否则 null。

### 4.2 `buildLaunch(input)`

池没有 pi 模型 → 抛 `FleetError("runtime_unavailable", "池 <id> 没有为 pi 指定模型")`。参数按顺序：

```text
--mode json
--provider <pool.runtimes.pi.provider> --model <pool.runtimes.pi.model>
--session-id <sessionRef>            （sessionRef 为 null 时抛 FleetError("invalid_request", ...)，pi 总要有会话编号）
--name <title>
--no-approve
--thinking <thinking>                （thinking 非 null 时）
--append-system-prompt <role.pi.appendSystemPrompt>   （有时）
--tools <逗号连接>                   （role.pi.tools 非空时）
--exclude-tools <逗号连接>           （role.pi.excludeTools 非空时）
-p <消息>                             （放在最后，消息整段是一个参数）
```

消息：

- 任务正文不超过 `ARGV_PROMPT_MAX_CHARS`：消息 = `guardLeadingDash(prompt)`，`files` 为空。
- 超过：正文写进 `joinFilePath(runDir, "task.md")`（放进 `files`）；参数末尾改为 `-p "请完整阅读并执行上面文件里的任务说明。" @<task.md 路径>`。依据：pi 会把 `@文件` 的内容包成 `<file>` 块拼在消息前面。

不传 `--session`（模糊匹配跨项目会弹交互确认卡死）；不传 `--no-context-files`（苦工需要读项目的 AGENTS.md / CLAUDE.md）。续接时参数形状完全一样，只是消息换成追加指令。

### 4.3 事件对照（`--mode json` 的 stdout）

| 事件 | 处理 |
|---|---|
| `session` | `sessionRef = id` |
| `agent_start` | 阶段从「starting」进入「working」（「retrying」保持） |
| `message_end`，`message.role === "assistant"` | 见 4.4 |
| `message_end`，`message.role === "toolResult"` | 产出 `tool_result`：`callId = toolCallId`，`tool = toolName`，`ok = !isError`，预览 = `content` 里所有 `type === "text"` 项的 `text` 拼接 |
| `auto_retry_start` | 产出 `retry`：`attempt` = 当前连续失败次数，`max = PI_MAX_CONSECUTIVE_FAILURES`，`delayMs`，`message = errorMessage`（缺省「未知错误」） |
| `agent_settled` | 进入 4.5 收尾 |
| `compaction_end` 且带 `errorMessage` | 产出 `error`：「上下文压缩失败：<errorMessage>」 |
| `message_start`、`message_update`、`turn_start`、`turn_end`、`agent_end`、`auto_retry_end`、`tool_execution_*`、`entry_appended`、`compaction_start`、`model_change`、`thinking_level_change` | 不产出事件 |

### 4.4 助手消息（`message_end` 且 `role === "assistant"`）

1. 有 `provider` 和 `model` 时，`model = <provider>/<model>`。
2. 用量累加：`input → inputTokens`，`output → outputTokens`，`cacheRead → cacheReadTokens`，`cacheWrite → cacheWriteTokens`，`totalTokens → totalTokens`（缺省按前四项之和），`cost.total → costUsd`。
3. 按 `content` 顺序产出：`text`（去掉首尾空白后非空）→ `text` 事件；`thinking`（取 `thinking` 字段，非空）→ `thinking` 事件；`toolCall` → `tool_call` 事件（`callId = id`，`tool = name`，参数 `arguments`）。
4. `stopReason === "error"`：连续失败次数加一；产出 `error` 事件（`errorMessage`，缺省「未知错误」）；`retry = { attempt: 连续失败次数, max: PI_MAX_CONSECUTIVE_FAILURES, message }`；阶段「retrying」。连续失败次数达到 `PI_MAX_CONSECUTIVE_FAILURES = 8`：结局 = 失败 `model_error`，说明「通道连续 8 次请求失败：<最后一次错误>」，阶段「ended」。依据：通道持续报错时 pi 会无限重试，每轮 4 次请求，8 次约等于两整轮、四十秒左右。
5. 其他 `stopReason`：连续失败次数清零，`retry = null`，阶段「working」；这条消息有文字内容时，`finalText` = 它所有文字项用两个换行连接。
6. 记下最后一个 `stopReason` 和最后一次 `errorMessage`。

工具摘要字段优先级：`path`、`file_path`、`command`、`query`、`url`、`pattern`。

### 4.5 暂定结局与收尾

**`agent_settled` 不是终点。** 真实抓包（通道持续报错时的 `s06`）里，同一个 pi 进程发出了 11 次 `agent_settled`、21 次 `agent_start`：重试用完后 pi 会重新开一轮。所以：

1. 收到 `agent_settled`：按最后一个 `stopReason` 定**暂定结局**：`error` → 失败 `model_error`（说明 = 最后一次错误）；`aborted` → 失败 `runtime_error`「模型调用被中止」；其余 → 已完成。阶段**不变**（仍是「working」或「retrying」），因为进程可能继续。
2. 之后又出现成功的助手消息（`stopReason` 不是 `error`）：暂定的失败结局清空为 null，等下一次 `agent_settled` 重新判定。
3. 连续失败达到 `PI_MAX_CONSECUTIVE_FAILURES`（4.4 第 4 条）：结局 = 失败 `model_error`，阶段「ended」。这是 pi 适配器里**唯一**进入「ended」的途径，之后结局不再改变；调度引擎看到「ended」后 10 秒进程仍在就结束它。
4. 最终结局以进程退出时的最后一次暂定结局为准，由 `resolveRunOutcome` 合并退出信息判定。

## 5. opencode 适配器

### 5.1 `displayModel(pool)`

`pool.runtimes.opencode` 存在时返回它的 `model`，否则 null。

### 5.2 `buildLaunch(input)`

池没有 opencode 模型 → 抛 `FleetError("runtime_unavailable", ...)`。参数按顺序：

```text
run --format json --auto
--dir <cwd>
-m <pool.runtimes.opencode.model>
--variant <variant>                  （池配置有 variant 时）
--agent <role.opencode.agent>        （有时）
--title <title>                      （只在首次运行，续接不传）
--session <sessionRef>               （续接时；续接却没有 sessionRef 抛 FleetError("invalid_request", "会话还没建立，无法续接")）
-f <task.md 路径>                     （正文走文件时；-f 是数组参数，必须紧跟一个开关参数，否则会把后面的任务正文也吞成附件）
--thinking                            （让思考内容出现在事件流里；同时终结 -f 的数组）
<消息>                                （最后，一个参数）
```

消息组成：没有 `--agent` 且 `rolePromptText` 非 null 时，全文 = `rolePromptText` + `"\n\n---\n\n"` + `prompt`；否则全文 = `prompt`。全文不超过 `ARGV_PROMPT_MAX_CHARS` 时消息 = `guardLeadingDash(全文)`；超过时全文写进 `joinFilePath(runDir, "task.md")`，消息 = 「请完整阅读并执行附件文件里的任务说明。」。

opencode 不认 `thinking` 档位，`input.thinking` 忽略。

### 5.3 事件对照

每行都带 `type`、`timestamp`（毫秒）、`sessionID`。`sessionRef` 取第一次出现的 `sessionID`；`at` 取 `timestamp`。

| 事件 | 处理 |
|---|---|
| `step_start` | 本步文字清空；阶段「working」 |
| `text` | `part.text` 非空 → `text` 事件，并记进本步文字 |
| `reasoning` | `part.text` 非空 → `thinking` 事件 |
| `tool_use` | 先产出 `tool_call`（`callId = part.callID ?? part.id`，`tool = part.tool`，参数 `part.state.input`），紧接着产出 `tool_result`（`ok = part.state.status === "completed"`；预览 = `state.output` 是字符串就用它，否则 `state.error` 的文字，都没有就空字符串） |
| `step_finish` | 用量累加：`tokens.input → inputTokens`、`tokens.output → outputTokens`、`tokens.cache.read → cacheReadTokens`、`tokens.cache.write → cacheWriteTokens`、`tokens.total → totalTokens`、`cost → costUsd`。本步有文字 → `finalText` = 本步文字用两个换行连接。`part.reason === "stop"` 且结局未定 → 结局 = 已完成（暂定） |
| `error` | 说明 = `error.data.message ?? error.message ?? error.name ?? error 的 JSON`；产出 `error` 事件；结局 = 失败 `model_error`（覆盖暂定的已完成） |

opencode 没有收尾事件，阶段永远不会进入「ended」，最终靠进程退出由 `resolveRunOutcome` 判定。

工具摘要字段优先级：`filePath`、`path`、`command`、`pattern`、`query`、`url`、`description`。

## 6. 验证方式

- 夹具放在 `packages/core/test/fixtures/pi/`、`packages/core/test/fixtures/opencode/`，从 `.scratch/samples/` 里挑可信样本复制过去（两份调研报告和样本目录的 README 标明了哪些可信），文件名保留来源。夹具里不得出现任何密钥。
- 调研时通道故障，pi 缺一份干净的成功流。pi 路先实测一次极小任务抓真实成功流；通道仍不通就按调研报告第 3 节和 `s09` 会话文件手工合成一份，文件名带 `synthetic`，并在测试里注明。
- 每个适配器至少覆盖：参数顺序与各可选项、长任务走文件、以 `-` / `@` 开头的任务、续接参数；每种事件类型的产出；用量累加；结局判定（成功、失败、pi 连续失败放弃、opencode 暂定完成被错误覆盖）；非 JSON 行、坏 JSON、未知类型、空行；真实样本逐行喂入后的最终进展。
