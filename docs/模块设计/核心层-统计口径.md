## 1. 职责与边界

- **管：** 把服务层查出来的「运行事实」和「任务事实」按所选时间范围、分段、维度汇总成 `StatsResponse`；时间范围怎么换算；分段怎么对齐本地时间；前 8 名和「其他」怎么合并。
- **不管：** 查库（服务层按第 3 节的口径查好事实传进来）；配色表的读写（服务层通过 `labels.seriesColor` 回调提供）；读系统时区（调用方传 `TimeZone`）。

## 3. 规格

### 3.1 本地时间（`localTime.ts`）

本地时刻 = UTC 毫秒 + `tz.offsetMinutes(utcMs) × 60000`。所有对齐都在「本地时刻」上算，再换回 UTC 毫秒。偏移随时刻变化（夏令时）时，以对齐后那个时刻的偏移为准（换回 UTC 时用 `utc = local − offset(local − offset(候选))` 迭代一次即可）。

| 导出 | 规则 |
|---|---|
| `startOfLocalDay(utcMs, tz): number` | 这个时刻所在本地日期的零点（UTC 毫秒） |
| `startOfLocalHour(utcMs, tz): number` | 所在本地整点 |
| `startOfLocalWeek(utcMs, tz): number` | 所在本地周的周一零点 |
| `localDateToUtcMs(date: string, tz): number` | `YYYY-MM-DD` 那天本地零点（UTC 毫秒）；格式不对抛 `FleetError("invalid_request", "日期格式应为 YYYY-MM-DD：<date>")` |

### 3.2 时间范围（`range.ts`）

`resolveRange(range: RangeRequest, nowMs, tz): ResolvedRange`：

| kind | fromMs | toMs |
|---|---|---|
| today | 今天本地零点 | nowMs |
| 7d | 今天本地零点往前 6 天（含今天共 7 天） | nowMs |
| 30d | 今天本地零点往前 29 天 | nowMs |
| all | null | nowMs |
| custom | `from` 日期本地零点 | min(`to` 日期次日本地零点, nowMs) |

custom 缺 from 或 to 抛 `FleetError("invalid_request", "自选日期要同时给出 from 和 to")`。往前 N 天用「本地日期减 N 天再取零点」算，不要用减 N×24 小时（跨夏令时会错一小时）。

`chooseGranularity(kind, fromMs, toMs): StatsGranularity`：`today` 恒为 `hour`；其余看跨度 `toMs − fromMs`：≤ 2 天为 `hour`，≤ 90 天为 `day`，更长为 `week`。

### 3.3 分段（`buckets.ts`）

`buildBuckets(fromMs, toMs, granularity, tz): number[]`：从 `fromMs` 所在分段的起点开始（整点 / 本地零点 / 本地周一零点），逐段往后，直到起点 ≥ toMs 为止，返回各段起点（UTC 毫秒，升序）。`fromMs ≥ toMs` 时返回空数组。天和周的下一段用「本地日期加 1 天 / 7 天再取零点」算。

`bucketIndexOf(ms, buckets): number`：最后一个起点 ≤ ms 的下标；早于第一个起点返回 −1。用二分。

### 3.4 前 N 名（`topN.ts`）

`mergeTopN<T>(items: readonly T[], n, weight: (item) => number, merge: (rest: readonly T[]) => T): T[]`：按 weight 从大到小排序（相同时保持原顺序），数量 ≤ n 时原样返回排序结果；超过时返回前 n 个再加 `merge(其余)`。

### 3.5 汇总（`computeStats.ts`）

`computeStats(input: ComputeStatsInput): StatsResponse`，步骤：

1. **范围：** `resolved = resolveRange(input.range, nowMs, tz)`。kind 为 all 时，起点取「所有 RunFact 的 startedAt 和所有 WorkerFact 的 createdAt 中最早的那个」，没有任何事实时起点为 null。
2. **粒度与分段：** 起点为 null 时 `granularity` 按 `chooseGranularity(kind, nowMs, nowMs)` 取（today → hour，其余 → hour，反正没有分段），`buckets` 为空；否则 `granularity = chooseGranularity(kind, 起点, toMs)`，`buckets = buildBuckets(起点, toMs, granularity, tz)`。响应里的 `range.from` 为起点对齐到第一个分段起点后的 ISO（没有分段时为 null；custom、today、7d、30d 的起点本身已对齐），`range.to` 为 `toMs` 的 ISO。
3. **筛选：**
   - 范围内的运行：`startedAt` 在 [起点, toMs) 之内（all 且起点为 null 时没有）。
   - 范围内的任务：`createdAt` 在 [起点, toMs) 之内。
   - 今天：同样的两条，起点换成今天本地零点、终点换成 nowMs。
4. **单次运行的毫秒数：** `runMs ?? max(0, nowMs − startedAt)`。
5. **一组统计数 `StatsTotals`：** `usage` = 运行用量逐项相加（费用规则同 `addUsage`：全是 null 才是 null）；`tasks` = 范围内任务数；`runMs` = 运行毫秒数之和；`avgRunMs` = runMs ÷「范围内运行涉及的不同任务数」，四舍五入成整数，分母为 0 时为 null。`total` 用所选范围，`today` 用今天。
6. **维度取值：** 运行通过 `workerId` 找到任务事实；按 dimension 取分组键：model → `modelName`，channel → `channel`，project → `projectKey`，role → `role`。键为 null（数据不一致）时归到键 `"unknown"`、显示名「未知」、配色位置 7。找不到任务事实的运行跳过。
7. **token 分布 `tokenShare`：** 按分组键汇总范围内运行：`tokens` = totalTokens 之和，`runMs` = 毫秒数之和，`tasks` = 不同任务数。`mergeTopN(…, STATS_TOP_N, tokens, 合并成「其他」)`：「其他」的 key 为空字符串、label 为「其他」、colorIndex 为 null、isOther 为 true，tasks / tokens / runMs 为其余各项之和（tasks 直接相加，不去重）。
8. **任务次数分布 `tasksByProject`：** 按项目汇总：`tasks` = 范围内**创建**的任务数；`tokens`、`runMs` = 该项目范围内运行的合计。只有 tasks > 0 或 tokens > 0 的项目出现。按 tasks 取前 8，其余合并「其他」。
9. **趋势 `tokenTrend`：** 线的集合和顺序与 `tokenShare` 完全相同（同样的前 8 名 + 「其他」）；每条线的 `points` 长度等于 `buckets` 长度，第 i 个数 = 该组在第 i 段开跑的运行的 totalTokens 之和（「其他」这条是所有非前 8 名的合计）。
10. **显示名和配色：** project → `labels.projectName.get(key) ?? key`、`labels.projectColor.get(key) ?? 0`；role → `labels.roleLabel.get(key) ?? key`、`labels.seriesColor("role", key)`；model、channel → 显示名就是键本身，配色 `labels.seriesColor(dimension, key)`。`tasksByProject` 用项目的名字和项目色。

## 4. 验证

`packages/core/test/stats/` 下每个文件一份测试，时区一律用固定偏移 `+480`（东八区）和一个会变的假时区（某个时刻前 +60、之后 +120）：

- localTime：零点、整点、周一零点在东八区的换算；跨夏令时那天的零点；日期格式错误。
- range：五个档位的起止；7d 包含今天共 7 个本地日期；custom 的 to 是今天时终点为 nowMs；custom 缺参数报错。
- chooseGranularity：today、1 天、2 天整、2 天多 1 毫秒、90 天、91 天。
- buckets：按小时 / 天 / 周对齐；起点落在段中间时第一段从段起点开始；空范围；`bucketIndexOf` 的边界（正好等于起点、早于第一段、晚于最后一段）。
- mergeTopN：不足 n、正好 n、超过 n、权重相同保持原顺序。
- computeStats：构造 3 个项目、10 个模型、若干运行（含一个还在跑的、一个跨天的），逐项核对 total、today、tokenShare（第 9、10 名合成「其他」且 tasks 相加）、tasksByProject、tokenTrend 每段的数、平均耗时分母只数有运行的任务；all 且没有任何数据时 buckets 为空、range.from 为 null；维度为 project 时配色取项目色，为 model 时调用了 seriesColor。
