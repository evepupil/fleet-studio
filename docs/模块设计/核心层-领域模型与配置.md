# 核心层 · 领域模型与配置

> 模块定位：全项目共用的名词、数据形状、配置结构与接口契约 · 对应代码：`packages/core/src/{domain,config,projects,api}/` · 所属里程碑：[M0 工程骨架与领域核心](../roadmap.md#m0) · 状态：进行中 · 最近更新：2026-09-23

## 1. 职责与边界

- **管：** 状态、失败原因、记录（项目 / 苦工 / 运行）、时间线事件、回报结构、错误类型、中文标签；配置文件的结构、默认值、校验与查询；项目路径归一化与配色位置；接口请求与响应的形状。
- **不管：** 任何 IO（读文件、读环境变量、取当前时间、生成随机数都由调用方传入）；不 import 任何 `node:` 模块，浏览器里也能用。

## 2. 结构

| 目录 / 文件 | 内容 | 谁写 |
|---|---|---|
| `domain/status.ts` `usage.ts` `records.ts` `timeline.ts` `report.ts` `errors.ts` `labels.ts` | 契约：名词和数据形状 | 主控（已完成） |
| `domain/ids.ts` | 编号生成与解析 | 实现路 |
| `config/schema.ts` | 契约：配置结构（zod） | 主控（已完成） |
| `config/defaults.ts` `parse.ts` `lookup.ts` | 默认配置、解析、查询与路径展开 | 实现路 |
| `projects/path.ts` `color.ts` | 项目路径归一化、配色位置 | 实现路 |
| `api/dto.ts` `requests.ts` `paths.ts` | 契约：接口响应、请求校验、路径常量 | 主控（已完成） |

每个目录的 `index.ts` 只做汇总导出，由负责该目录的一路维护。跨目录导出的名字不能重复。

## 3. 契约要点

- 运行状态五种：`queued` 排队中、`running` 工作中、`completed` 已完成、`failed` 失败、`cancelled` 已取消。后三个是终态。
- 失败原因八种，见 `domain/status.ts` 注释。
- 苦工的状态 = 最新一次运行的状态。续接新建运行，旧运行不变。
- 时间一律 ISO 8601 UTC 字符串。
- 时间线事件的 `seq` 在整个苦工内从 0 连续递增；解析器只产出不带 `seq`、`runSeq` 的草稿（`TimelineDraft`）。

### 4.3 `config/parse.ts`

- `type ConfigParseResult = { ok: true; config: FleetConfig } | { ok: false; issues: string[] }`
- `parseConfig(input: unknown): ConfigParseResult`：用 `fleetConfigSchema.safeParse`；失败时每个问题格式化成 `<路径>: <消息>`，路径用点号连接（例如 `pools.0.capacity: ...`），根路径写成 `(根)`。
- `parseConfigText(text: string): ConfigParseResult`：先 `JSON.parse`，失败返回 `{ ok: false, issues: ["配置文件不是合法的 JSON：<原始错误消息>"] }`，成功再交给 `parseConfig`。
- `DEFAULT_CONFIG` 经 `parseConfig` 必须成功（写测试）。

### 4.4 `config/lookup.ts`

| 导出 | 规则 |
|---|---|
| `findPool(config, id): PoolConfig \| null` | 按编号找 |
| `findRole(config, id): RoleConfig \| null` | 按编号找 |
| `resolveRunTimeoutMs(config, pool, overrideMin?: number): number` | `(overrideMin ?? pool.runTimeoutMin ?? config.defaults.runTimeoutMin) × 60000` |
| `resolveQueueTimeoutMs(config, pool, overrideMin?: number \| null): number \| null` | `overrideMin` 为 `undefined` 时取 `pool.queueTimeoutMin ?? config.defaults.queueTimeoutMin`；最终值为 null 返回 null，否则 × 60000 |
| `interface PathEnv { home: string; builtinRoot: string }` | 展开路径需要的环境，由调用方提供 |
| `expandPath(path: string, env: PathEnv): string` | 见下 |
| `expandRolePaths(role: RoleConfig, env: PathEnv): RoleConfig` | 返回新对象，展开 `pi.appendSystemPrompt` 和 `opencode.promptFile`，其余原样 |
| `opencodePromptPath(role: RoleConfig): string \| null` | 有 `opencode.agent` 返回 null；否则 `opencode.promptFile ?? pi.appendSystemPrompt ?? null` |
| `applyPoolPatch(config: FleetConfig, poolId: string, patch: PoolPatch): FleetConfig` | 返回新配置，只改该池的 `capacity` / `perProjectCap`（patch 里是 `undefined` 的字段不改）；池不存在抛 `FleetError("not_found", "池不存在：<id>")`；不修改入参 |

`expandPath` 规则：

1. 等于 `~`，或以 `~/`、`~\` 开头：替换成 `env.home` 拼上剩余部分。
2. 以 `builtin:` 开头：替换成 `env.builtinRoot` 拼上剩余部分。
3. 其他原样返回。
4. 拼接时分隔符跟随 `env.home` / `env.builtinRoot` 的风格：含 `\` 就用 `\`，否则用 `/`；剩余部分里的 `/` 和 `\` 统一换成该分隔符；不产生重复分隔符。

例：`home = "C:\Users\zhoutao"`，`"~/.pi/agent/roles/worker.md"` → `"C:\Users\zhoutao\.pi\agent\roles\worker.md"`。

### 4.5 `projects/path.ts`

浏览器安全，只用字符串操作。`type PathPlatform = "win32" | "posix"`。

`normalizeProjectPath(input: string, platform: PathPlatform): string`

- 先去掉首尾空白。
- **win32：**
  - `/c/code/x` 这种 Git Bash 写法（`/` + 单个字母 + `/` 或结尾）转成 `C:\code\x`。
  - 所有 `/` 换成 `\`；合并连续的 `\`（开头的 `\\` UNC 前缀保留）。
  - 按段处理 `.` 和 `..`（不会越过盘符根）。
  - 盘符转大写；去掉末尾分隔符，但盘符根保留成 `C:\`。
  - 不是绝对路径（没有盘符、也不是 UNC）抛 `FleetError("invalid_request", "项目目录必须是绝对路径：<input>")`。
- **posix：** 合并连续 `/`，处理 `.` 和 `..`，去掉末尾 `/`（根目录保留 `/`）；不以 `/` 开头抛同样的错误。

| 导出 | 规则 |
|---|---|
| `projectKeyOf(normalizedPath, platform): string` | win32 转小写；posix 原样 |
| `projectNameOf(normalizedPath): string` | 最后一段；盘符根返回 `C:`；posix 根返回 `/` |

### 4.6 `projects/color.ts`

- `PROJECT_PALETTE_SIZE = 8`（与前端设计定稿的 8 个分类色一致）
- `pickColorIndex(taken: readonly number[], seed: string, paletteSize = PROJECT_PALETTE_SIZE): number`：返回 [0, paletteSize) 里不在 `taken` 中的最小值；全被占用时返回 `seed` 的 FNV-1a 32 位哈希对 `paletteSize` 取模（同一个 seed 永远同一个结果）。

## 5. 验证方式

`packages/core/test/` 下按文件对应写单测，至少覆盖：

- ids：格式、只用字母表字符、注入固定随机源时结果确定、`parseRunId` 的非法输入（无点号、序号 0、负数、小数、非数字）。
- config：`DEFAULT_CONFIG` 能通过；缺默认池、池编号重复、容量越界、池不给任何运行时模型、JSON 语法错都能报出带路径的问题；默认值被补齐。
- lookup：两个超时的优先级（单次覆盖 > 池 > 全局，排队超时单次传 null 表示不限时）；`expandPath` 的 `~`、`builtin:`、混合斜杠、不处理的普通路径；`applyPoolPatch` 不改入参、池不存在报错。
- path：Git Bash 写法、正反斜杠混用、`..`、盘符大小写、末尾分隔符、盘符根、UNC、相对路径报错、posix 各情况；`projectKeyOf` 大小写。
- color：最小空位、全占满时哈希稳定。
