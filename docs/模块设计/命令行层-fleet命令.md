# 命令行层 · fleet 命令

> 模块定位：主会话派活、等结果、续接、取消、看容量的命令行入口；服务没起来时自动拉起 · 对应代码：`packages/cli/` · 所属里程碑：[M1 闸门服务与 fleet 命令](../roadmap.md#m1)（派活规范切换在 [M3](../roadmap.md#m3)）· 状态：已完成 · 最近更新：2026-09-23

## 1. 职责与边界

- **管：** 解析命令行、找到或拉起服务、调接口、把结果排成人和模型都好读的文字、按约定给出退出码。
- **不管：** 任何业务规则。只通过 HTTP 和服务对话，请求和响应类型取自 `@fleet/core`。

## 2. 结构

| 文件 | 内容 |
|---|---|
| `src/main.ts` | 入口：分发子命令，统一处理错误和退出码 |
| `src/args.ts` | 基于 `node:util` 的 `parseArgs` 的小封装 |
| `src/home.ts` | 数据目录：`--home` > 环境变量 `FLEET_HOME` > `~/.fleet-studio` |
| `src/daemon/discover.ts` | 读 `daemon.json`、探活、按需拉起服务 |
| `src/client.ts` | HTTP 客户端：自动带令牌、解析 `ApiErrorBody` |
| `src/project.ts` | 推断苦工归属的项目目录 |
| `src/prompt.ts` | 读任务正文：参数 / `--prompt-file` / 标准输入 |
| `src/format/*.ts` | 时长、时间、状态行、表格、回报、时间线的文字排版 |
| `src/commands/*.ts` | 每个子命令一个文件 |

## 3. 规格

### 3.1 通用约定

- 全部输出中文。每个子命令支持 `--json`（原样输出接口返回的 JSON，便于程序处理）和 `--help`。
- **退出码：** 0 成功；1 业务失败（有苦工失败或被取消、接口返回错误）；2 等待超时（还有苦工没结束）；3 用法错误或连不上服务。
- 连不上服务时的提示要给出下一步，例如「服务启动失败，日志在 <路径>」。

### 3.2 找到服务 `ensureDaemon(home)`

1. 读 `<home>/daemon.json`（字段：`pid`、`port`、`token`、`startedAt`、`version`），有就请求 `/api/health`（1 秒超时），通了直接用。
2. 否则拉起服务：`spawn(process.execPath, [<daemon 入口>, "--home", home], { detached: true, windowsHide: true, stdio: "ignore" })` 后 `unref()`。daemon 入口 = 本文件所在 `packages/cli/dist` 往上找到仓库里的 `packages/daemon/dist/main.js`。
3. 每 200 毫秒重试一次读文件加探活，最多 8 秒；超时退出码 3，提示看 `<home>/daemon.log`。
4. `fleet daemon stop` 和 `status` 不触发自动拉起。

### 3.3 推断项目目录

`--project` > 环境变量 `FLEET_PROJECT` > 从工作目录往上找第一个含 `.git` 的目录 > 工作目录本身。工作目录默认 `process.cwd()`，可用 `--cwd` 改。两者都转成绝对路径后发给服务（服务负责归一化）。

### 3.4 子命令

**`fleet run [任务] [选项]`** —— 派一个苦工。

- 任务正文三选一：位置参数（多个位置参数用空格连起来）、`--prompt-file <文件>`、`-`（从标准输入读到结束）。都没有就报用法错误。
- 选项：`--project`、`--cwd`、`--pool`、`--runtime pi|opencode`、`--role`、`--title`、`--thinking <档位>`、`--timeout <分钟>`、`--queue-timeout <分钟|none>`、`--wait`（派完接着等，行为同 `fleet wait` 单个编号）、`--json`。
- 输出：第一行只有苦工编号（方便脚本取用），第二行是状态行（见 3.5）。

**`fleet wait <编号...> [--any] [--timeout <秒>] [--brief] [--json]`**

- 循环请求 `/api/wait`（每次最多挂 60 秒）直到条件满足或到达总超时。总超时默认 540 秒，0 表示一直等。
- 每个结束的苦工输出：状态行；失败时一行失败原因和说明；不带 `--brief` 时再输出最新一次运行的回报原文。
- 退出码：都已完成 0；有失败或已取消 1；超时 2。

**`fleet ps [--all] [--project <目录>] [--json]`** —— 默认只列当前项目的苦工，`--all` 列全部。表格列：编号、状态（排队中带「第 N 位」，重试中带「重试 N/M」，回报不通过带「自评不通过」）、角色、池、时长、标题、最近活动。进行中的在前，最近结束的在后。

**`fleet show <编号> [--json]`** —— 标题、状态、项目目录、工作目录、角色、运行时与模型、每次运行的状态与时长、用量与费用、最新回报（按段落排版）。

**`fleet log <编号> [--tail <条数>] [--json]`** —— 时间线逐条一行：`时:分:秒  图标  内容`。工具调用写「工具 · 摘要」，工具结果只写成功与否和前 120 个字，文字和思考压成一行截到 200 字，重试写「重试 N/M：原因」。每次运行开头打一行分隔。

**`fleet send <编号> [追加指令] [--prompt-file <文件>] [-] [--timeout <分钟>] [--wait]`** —— 续接。正文读取规则同 `run`。

**`fleet cancel <编号...>`** —— 逐个取消，逐行输出结果。

**`fleet pools [--json]`** —— 每个池一行：编号、显示名、已用/容量、排队数、单项目上限、最近 10 分钟完成 / 失败 / 重试中。

**`fleet pool set <编号> [--capacity <数>] [--per-project <数|none>]`** —— 调整容量，写回配置文件。

**`fleet roles [--json]`** —— 角色编号、中文名、说明。

**`fleet daemon start|stop|status|restart`** —— `stop` 调 `/api/shutdown` 并等到端口不再响应；`status` 输出进程号、端口、启动时间、数据目录、版本。

**`fleet open`** —— 用系统默认浏览器打开看板（Windows 用 `rundll32 url.dll,FileProtocolHandler <地址>`，不经过 shell 拼命令）。

### 3.5 排版

- 状态行：`<编号>  <状态>  <池>/<角色>  <时长>  <标题>`，例如 `w7k2mq  工作中  dsf/实现  3分12秒  类目配置校验`。
- 时长：不足 1 分钟「45秒」，不足 1 小时「3分12秒」，否则「1时05分」。
- 时间：本地时区 `HH:mm:ss`；不是今天的加日期 `MM-DD HH:mm`。
- 表格按显示宽度对齐（中文算 2 个宽度），标题超长截断加省略号。

## 4. 验证方式

`packages/cli/test/` 下：

- 纯函数：参数解析、项目推断（用临时目录造 `.git`）、正文读取的三种来源、各种排版（中文宽度对齐、时长边界、回报排版）。
- 命令：起一个桩 HTTP 服务（模拟接口响应），加一个写好 `daemon.json` 的临时数据目录，逐个子命令检查请求内容（路径、令牌、请求体）、输出和退出码；`wait` 的多轮等待与超时；服务不可达且拉起失败时的退出码 3。
