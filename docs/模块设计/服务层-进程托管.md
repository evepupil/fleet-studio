# 服务层 · 进程托管

> 模块定位：找到运行时可执行文件、补齐环境变量、分离启动苦工、增量读输出、判断存活、结束进程树 · 对应代码：`packages/daemon/src/process/` · 所属里程碑：[M1 闸门服务与 fleet 命令](../roadmap.md#m1) · 状态：已完成 · 最近更新：2026-09-23

## 1. 职责与边界

- **管：** 和操作系统打交道的全部动作。
- **不管：** 启动参数怎么拼（运行时适配器）、什么时候启动和结束（调度引擎）、输出是什么意思（解析器）。
- 事实依据：[pi 运行时调研](../调研/pi-运行时.md) 第 1、2、6、7 节；[opencode 运行时调研](../调研/opencode-运行时.md) 第 1、5、6 节。

## 3. 规格

### 3.1 找可执行文件 `createRuntimeResolver({ getConfig, npmGlobalRoot? })`

优先用配置 `runtimes.<运行时>.command`：`executable = command[0]`，`prefixArgs = command.slice(1)`，`image = executable 的小写文件名`。没配时自动探测，结果缓存到 `invalidate()` 为止：

1. **npm 全局目录**：先试 `%APPDATA%\npm\node_modules`（Windows）；不存在再执行一次 `npm root -g`（Windows 下 npm 是 `.cmd`，用 `cmd.exe /d /s /c "npm root -g"` 执行，这条命令不含任何外部输入）。可注入 `npmGlobalRoot` 方便测试。
2. **pi**：读 `<全局目录>/@earendil-works/pi-coding-agent/package.json` 的 `bin.pi`（可能是字符串或对象），拼出入口脚本。`executable = process.execPath`，`prefixArgs = [入口脚本]`，`image = "node.exe"`（非 Windows 取 `node`）。
3. **opencode**：读 `<全局目录>/opencode-ai/package.json` 的 `bin.opencode`，拼出可执行文件。`prefixArgs = []`，`image = 该文件的小写文件名`。
4. 入口文件不存在 → 抛 `FleetError("runtime_unavailable", "找不到 <运行时>：<尝试过的路径>")`。

**绝不 spawn `.cmd`、`.ps1` 外壳**，调研实测它们会把多行任务截断在第一个换行处。

### 3.2 环境变量

- `readRegistryEnvironment()`：仅 Windows。执行 `reg query HKCU\Environment` 和 `reg query "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment"`，用 `parseRegQueryOutput` 解析 `REG_SZ` / `REG_EXPAND_SZ` 行，`REG_EXPAND_SZ` 的值用 `expandEnvReferences` 展开 `%NAME%`。用户级覆盖系统级。非 Windows 返回空对象。读失败返回空对象并记日志，不抛异常。
- `mergeWorkerEnv(base, registry)`：以当前进程环境为底，注册表里有、当前环境没有的变量补进去；Windows 下变量名比较不区分大小写；`Path` / `PATH` 不从注册表补（当前进程的 PATH 已经包含它们，重复拼接会越来越长）。
- **任何日志、错误信息里都不准出现变量的值**，最多写变量名。
- `workerEnv()` 缓存结果 60 秒，之后下次调用重新读注册表（用户新设了密钥不用重启服务）。

### 3.3 分离启动 `spawnWorker(request)`

1. 检查 `cwd` 存在且是目录，否则抛 `FleetError("invalid_request", "工作目录不存在：<cwd>")`。
2. 为 `files` 里每个文件建好父目录并写入（UTF-8）。
3. 为 stdout / stderr 文件建好父目录，以追加方式打开得到文件描述符。
4. `spawn(executable, [...prefixArgs, ...args], { cwd, env, detached: true, windowsHide: true, stdio: ["ignore", outFd, errFd] })`。**stdin 必须是 `"ignore"`**：两个运行时在 stdin 不关闭时都会永久卡住。不用 `shell`。
5. 立刻 `child.unref()`，并在父进程里关闭两个文件描述符（子进程已经继承）。
6. 监听 `error`：启动阶段出错（例如可执行文件不存在）→ 抛 `FleetError("runtime_unavailable", "启动失败：<原因>")`。拿到 `pid` 才算启动成功。
7. `onExit` 包装 `child.on("exit")`，把 `code`、`signal` 交给监听者；监听者在进程已退出后才注册时也要能收到（缓存退出信息）。

分离启动的用意：服务重启、崩溃都不会连带杀死苦工，重启后可以接管。

### 3.4 结束进程树 `killTree(pid)`

- Windows：`taskkill /PID <pid> /T /F`（`execFile`，不经过 shell）。输出里「没有找到进程」一类的失败视为成功（进程已经没了）。
- 其他平台：先 `process.kill(-pid, "SIGKILL")`（分离启动的进程是进程组组长），失败再 `process.kill(pid, "SIGKILL")`，`ESRCH` 视为成功。

### 3.5 存活判断 `isProcessAlive(pid, image)`

- Windows：`tasklist /FI "PID eq <pid>" /FO CSV /NH`（`execFile`），用 `parseTasklistCsv` 解析出映像名；没有这一行 → 不活；`image` 非 null 时映像名不一致（不区分大小写）→ 视为不活（进程号已被系统复用）。
- 其他平台：`process.kill(pid, 0)` 不抛异常即活；不核对映像名。

### 3.6 增量读输出 `createOutputTailer(filePath, startOffset = 0)`

- `readNew()`：文件不存在返回空数组；否则从当前偏移读到文件末尾，用 `StringDecoder("utf8")` 解码（多字节字符跨读取边界时不能乱码），与上次残留拼接后按 `\n` 切行，每行去掉末尾 `\r`，最后一段不完整的留到下次。单次最多读 4MB，剩下的下次再读。
- `flush()`：返回残留的最后半行（去掉 `\r`），没有返回 null；调用后残留清空。
- 文件被截短（大小小于偏移）时从头重新读。

### 3.7 组装 `createProcessHost({ getConfig, logger })`

把以上各项装进 `ProcessHost` 接口，`invalidate()` 同时清掉可执行文件缓存和环境变量缓存。

## 4. 验证方式

`packages/daemon/test/process/` 下：

- 解析函数纯测：`parseRegQueryOutput`（含 `REG_EXPAND_SZ`、值里带空格、空值）、`expandEnvReferences`（存在与不存在的变量）、`mergeWorkerEnv`（大小写、PATH 不补）、`parseTasklistCsv`（有进程、无进程的「信息：没有运行的任务」提示）。
- 可执行文件探测：用临时目录伪造一个 npm 全局目录（`package.json` 的 `bin` 分别是字符串和对象两种写法）；配置里写死 `command` 时优先用配置；找不到时报中文错误。
- 分离启动（真实进程）：用 `process.execPath` 跑一个临时脚本，验证多行、带引号、带中文的参数原样到达；stdin 是关闭的（脚本读 stdin 立刻得到结束）；stdout / stderr 分别写进文件；退出码能拿到；工作目录不存在时报错。
- 结束进程树：启动一个会再拉起子进程、然后睡眠的脚本，`killTree` 之后父子进程都不在了（用 `isProcessAlive` 确认）。
- 增量读：分几次追加内容（含 CRLF、跨读取边界的中文、末尾半行），逐次读出的行正确；`flush` 取到最后半行；文件被截短后从头读。
