# 核心层 · 快照汇总

> 模块定位：把存储里的项目、苦工、运行记录算成看板和命令行要显示的样子；解析回报；把多次运行拼成一条时间线 · 对应代码：`packages/core/src/{snapshot,report}/` · 所属里程碑：[M0 工程骨架与领域核心](../roadmap.md#m0)、[M5 第二版底座](../roadmap.md#m5) · 状态：已完成（第二版已实现）· 最近更新：2026-09-25

## 1. 职责与边界

- **管：** 快照（容量条每格属于谁、各项目各状态几个、今日用量、池健康）、苦工摘要与详情、回报解析、时间线拼接。纯函数。
- **不管：** 从哪里查出这些记录、挑哪些记录喂进来（调度引擎按本文第 3.1 节的口径去查）；排队位置怎么算（调用方用 `queuePositions` 算好传进来）。

## 3. 规格

### 3.1 `buildSnapshot(input: SnapshotInput): Snapshot`

```ts
interface SnapshotInput {
  version: string;
  now: string;
  /** 本地时区今天零点（ISO），由调用方算好 */
  dayStart: string;
  config: FleetConfig;
  configError: string | null;
  projects: readonly ProjectRecord[];
  /** 下面 runs 涉及的全部苦工 */
  workers: readonly WorkerRecord[];
  /** 调用方查询口径：所有非终态运行 + 结束时间晚于 min(dayStart, now − snapshotWindowHours, now − 10 分钟) 的运行
      + 上述运行所属苦工的其余运行 */
  runs: readonly RunRecord[];
  /** 排队中的运行在池内的预计放行位置 */
  queuePositions: ReadonlyMap<string, number>;
}
```

**挑苦工：** 最新一次运行非终态，或最新一次运行的 `endedAt` 在 `now − snapshotWindowHours` 之后。超过 300 个时，非终态的全部保留，剩下名额给终态里结束最晚的。输出按 `createdAt` 倒序（相同再按 `id`）。

**苦工摘要 `buildWorkerSummary(worker, runs, config, queuePositions)`**（`runs` 是该苦工的全部运行）：

- 最新运行 = `seq === worker.latestRunSeq` 的那次；找不到就取 `seq` 最大的。一次运行都没有时视为数据不一致，按排队中处理，时间字段取 `worker.createdAt`。
- 状态、失败原因、错误说明、`queuedAt`、`startedAt`、`endedAt`、`retry`、`activity`、`lastActivityAt` 取自最新运行；`runSeq` = 最新运行的 `seq`。
- `roleLabel` 取配置里角色的 `label`，找不到就用角色编号。
- `verdict` = `parseReport(最新运行.finalText)?.verdict ?? null`。
- `usage` = 全部运行用量之和（`addUsage`）。
- `queuePosition`：排队中时取 `queuePositions.get(最新运行.id) ?? null`，其他状态 null。

**运行视图 `buildRunView(run)`：** 字段照抄；`report = run.finalText ? parseReport(run.finalText) : null`。

**苦工详情 `buildWorkerDetail(worker, runs, project, config, queuePositions)`：** `summary` 同上；`projectPath = project.path`；`runs` 按 `seq` 升序。

**池视图 `buildPoolViews`**，按配置里池的顺序，每个池：

- `model` = `poolDisplayModel(pool)`：有 pi 模型时 `<provider>/<model>`，否则 opencode 的 `model`。
- `running` / `queued`：该池（按苦工的 `poolId`）状态为工作中 / 排队中的运行数。
- `slots`：该池工作中的运行各一格。项目排序：在跑数多的在前；并列时该项目最早 `startedAt` 早的在前；再并列 `projectKey` 字典序。项目内按 `startedAt` 升序，再按 `runId`。`retrying = run.retry !== null`。
- `queuedByProject`：该池排队数按项目统计；顺序先按 `slots` 里的项目顺序，其余项目按各自最早 `queuedAt`。
- `health`：`windowMinutes = 10`；`completed` / `failed` = 该池内 `endedAt` 落在 (now − 10 分钟, now] 的已完成 / 失败运行数（已取消不算）；`retrying` = 该池工作中且 `retry` 非 null 的运行数。
- `usageToday`：该池内 `startedAt ≥ dayStart` 的运行用量之和。

**项目视图 `buildProjectViews`**，只包含快照里有苦工的项目：

- `counts`：快照苦工按摘要状态计数，五种状态都要有键（没有的为 0）。
- `usageToday`：该项目全部输入运行中 `startedAt ≥ dayStart` 的用量之和。
- `lastActivityAt`：快照苦工里 `lastActivityAt ?? endedAt ?? startedAt ?? queuedAt` 的最大值。
- 排序：有工作中苦工的项目在前；再按 `lastActivityAt` 倒序；再按 `name`。
- 找不到项目记录时就地补一个：`path = key`，`name` 取最后一段，`colorIndex = 0`。

**其余字段：** `roles` 来自配置（`id`、`label`、`description`）；`serverTime = now`；`version`、`configError` 照抄。

### 3.2 `parseReport(text: string): ParsedReport | null`

苦工收尾的回报长这样（段名是大写英文加下划线，后跟冒号）：

```text
SUMMARY: 一段话……
FILES:
- a.ts 改了什么
VERIFY: pnpm test，12 个通过
SELF_REPORT: pass
BLOCKED: 无
```

- 行首匹配 `^([A-Z][A-Z_]{1,31}):\s?(.*)$` 的行开启新段，冒号后面的内容是该段第一行；后续不匹配的行追加到当前段；第一个段名之前的文字丢弃。
- 允许段名前有 Markdown 装饰：`**SUMMARY**:`、`**SUMMARY:**`、`## SUMMARY:`、`- SUMMARY:` 都要认。
- **只有段名的标题行也要认**（真实模型常这样写，2026-09-24 端到端验收发现）：一行里只有段名、带 Markdown 装饰（`**FINDINGS**`、`__FINDINGS__`、`## FINDINGS`、`### FINDINGS`）或带结尾冒号（`FINDINGS:`），没有别的文字时，开启新段，该段内容从下一行开始。既没有装饰也没有冒号的单独大写词（例如一行只有 `OK`）不算段名，按正文处理，避免把正文误切成段。
- 每段文字去掉首尾空白，保留内部换行。
- `verdict`：优先看 `VERDICT` 段，其次 `SELF_REPORT` 段；取文字的第一个词，忽略大小写，`pass` → `"pass"`，`fail` → `"fail"`，其他 → null。
- 一个段都没认出来返回 null。

### 3.3 `assembleTimeline(runs: readonly RunDrafts[]): TimelineEvent[]`

```ts
interface RunDrafts {
  run: RunRecord;
  /** 这次运行解析出的草稿事件，按产生顺序 */
  drafts: readonly TimelineDraft[];
}
```

按 `run.seq` 升序处理每次运行：先插一条 `run_start`（`at = startedAt ?? queuedAt`，`prompt = run.prompt`）；再依次放入草稿；运行已是终态时补一条 `run_end`（`at = endedAt ?? 最后一条草稿的 at ?? startedAt ?? queuedAt`，`status`、`failReason`、`message = errorMessage`）。所有事件的 `runSeq = run.seq`，`seq` 从 0 连续编号。

## 4. 验证方式

`packages/core/test/snapshot/`、`packages/core/test/report/` 下单测，至少覆盖：

- 挑苦工：窗口内外、非终态永远保留、超过 300 个时的取舍、排序。
- 摘要：最新运行的选择、找不到最新运行的兜底、用量累加（含费用 null）、角色名兜底、排队位置只在排队中给出、verdict 来自回报。
- 池视图：分段排序规则、排队按项目拆分的顺序、健康窗口边界（恰好 10 分钟前结束的不算）、取消不算失败、今日用量按池。
- 项目视图：五种状态键齐全、排序规则、缺项目记录时的兜底。
- 回报：标准格式、各种 Markdown 装饰、多行段落、没有任何段、`VERDICT` 优先于 `SELF_REPORT`、`PASS`/`Fail.`/`pass（附说明）` 这类写法。
- 时间线：多次运行拼接、`seq` 连续、非终态运行不补 `run_end`、`run_end` 的时间兜底。

## 第二版（M5）：优先级、启停、公共排队、实时卡片

> 所属里程碑：[M5](../roadmap.md#m5) · 依据：[功能清单](../功能清单.md) 3.1～3.4、5.1～5.12、7.11 · 契约见 `packages/core/src/api/dto.ts`（主控已改）

### 输入变化

`SnapshotInput` 不加字段。`queuePositions` 由服务层用新的 `queuePositions` 算好传入（公共排队的运行也在里面）。苦工记录的 `poolId` 可能为 null（没点名、还没被放行过），这类苦工的运行只可能是排队中。

### 池视图 `buildPoolViews`

在第一版基础上：

| 字段 | 取值 |
|---|---|
| `priority` | 在 `config.pools` 里的下标 + 1 |
| `enabled` | 池配置的 `enabled` |
| `channel`、`modelName`、`model` | `poolChannelModel(pool)`（省略 runtime，pi 优先）；`model` 取它的 `display`，和第一版 `poolDisplayModel` 结果一致 |
| `running`、`slots` | 不变：`worker.poolId === pool.id` 且状态为工作中的运行 |
| `queued`、`queuedByProject` | 只数 `worker.poolId === pool.id` 的排队运行（点名的和续接的）；公共排队不算 |
| `health` | 不变（最近 10 分钟） |
| `recent` | `windowHours: 24`；`completed`、`failed` = 这个池里 `endedAt` 落在 (now − 24 小时, now] 的已完成、失败运行数（取消不算）；`avgRunMs` = 这些已完成和失败运行的 `runMs` 平均（`runMs` 为 null 的用 endedAt − startedAt 补，两者都缺的不计），四舍五入成整数，没有时为 null |
| `usageToday` | 不变 |

注意：`recent` 需要最近 24 小时结束的运行都在输入里。服务层查询窗口要覆盖 24 小时（见 [调度引擎](服务层-调度引擎.md) 第二版一节），快照的苦工列表仍按 `snapshotWindowHours` 裁剪，两者互不影响。

### 快照 `buildSnapshot`

- `sharedQueued`：`worker.poolId === null` 的排队运行数。
- `live`：`slotsUsed` = 所有池 `running` 之和（含停用池里还没跑完的）；`slotsTotal` = 启用池的 `capacity` 之和；`running` = 最新运行为工作中的苦工数；`queued` = 最新运行为排队中的苦工数；`retrying` = 最新运行为工作中且 `retry` 不为 null 的苦工数。三个苦工数按全部输入记录算，不受苦工列表 300 条上限影响。

### 苦工摘要 `buildWorkerSummary`

- 新字段直接取自苦工记录：`requestedPool`、`poolId`、`model`、`channel`、`modelName`。
- `runMs`：各次运行的 `runMs` 之和；`runMs` 为 null 且 `startedAt` 不为 null 的（正在跑，或数据缺失）按 `(endedAt ?? now) − startedAt` 计。为此 `buildWorkerSummary` 增加一个参数 `nowMs: number`（放在最后），所有调用方同步改。
- `queuePosition`：照旧从 `queuePositions` 里取。

### 验证

`packages/core/test/snapshot/` 更新夹具（苦工记录的新字段、池的 `enabled`）并加用例：

- 两个池调换顺序后 `priority` 跟着变；停用池 `enabled` 为 false 且不计入 `live.slotsTotal`，但它的在跑仍计入 `slotsUsed`。
- 一个没点名的排队苦工：不出现在任何池的 `queued` 里，`sharedQueued` 为 1，摘要的 `poolId`、`model` 为 null，`queuePosition` 取自传入的 Map。
- `recent`：窗口边界（正好 24 小时前结束的不算）、取消不计、`avgRunMs` 用 runMs 或时间差补齐、没有结束的运行时为 null。
- `live` 的五个数；`runMs` 对在跑运行按 now 计。
