# 界面层 · 总览

> 模块定位：总览页——实时指标条、时间范围、统计指标条、token 分布、任务次数分布、token 趋势 · 对应代码：`apps/web/src/features/overview/`、`apps/web/src/pages/OverviewPage.tsx` · 所属里程碑：[M6 第二版控制台看板](../roadmap.md#m6)、[M7 第三版界面](../roadmap.md#m7) · 状态：第三版已实现，待用户确认 · 最近更新：2026-09-29
>
> 视觉与交互规范：[前端设计](../前端设计.md)（第三版）；实现规格：[design/总览.md](../../apps/web/design/总览.md)；共用地基：[控制台框架](界面层-控制台框架.md)。

## 1. 职责与边界

- **管：** 把快照里的实时数（`live`、`sharedQueued`）画成一条四格的实时指标条（可点）；把 `GET /api/stats` 的结果画成统计指标条、两张「环形图 + 明细表」面板和一张折线图面板；点指标或明细行时带着筛选跳到任务列表。
- **不管：** 统计口径（全部由服务端 `computeStats` 算好）；任务页怎么筛（只调 `taskFilterStore.applyFromOverview`）。

## 2. 结构与数据流

```text
OverviewPage ─▶ ViewBar(总览, right = RangeBar：分段切换；手机宽度换成下拉)
             ─▶ data-page-body（纵向滚动）
                   ├─ LiveCards（snapshotStore）──▶ MetricStrip：槽位占用（带占用条）· 工作中 · 排队中 · 重试中
                   ├─ StatCards ┐                      MetricStrip：token 用量 · 任务次数 · 总耗时 · 平均耗时
                   └─ StatsBody ┴─ 共用 useStats(overviewStatsQuery(state))，同一个查询键只发一次请求
                         ├─ 没数据：一块面板「这段时间没有任务」；出错：一块面板 ErrorState
                         └─ TokenShareCard + TasksByProjectCard（≥1280 并排）、TokenTrendCard（通栏，标题旁写粒度）
维度切换（overviewStore.dimension）同时作用于 token 分布和 token 趋势
```

## 3. 关键决策

| 决策 | 理由 |
|---|---|
| 大数字统计卡改成指标条（数字 16px 中等字重，格间 1px 细线） | 设计提炼规定不加大标题和统计卡；用户拍板保留数字、去掉卡片 |
| 点指标和明细行跳任务**列表** | 带着状态、时间、维度的筛选只有列表认；看板只管实时 |
| 两张分布并排从 ≥1024 改成 ≥1280 | 工作区比第二版窄，1024 时两张环形图挤不下 |
| 读屏用的明细表外面包一层隐藏的容器 | 表格会按内容撑开、不认 1px 宽，直接隐藏表格本身会把手机页面撑宽 |
| 分布用「环形图 + 明细表」，趋势线画实心点，选「今日」不显示今日补充，切档保留旧数据 | 沿用第二版 |

## 4. 当前实现

- 第三版（M7）总览一路（glmf）27 分钟改完：两条指标条替代八张统计卡，三张图表放进细边框面板，粒度挪到趋势面板标题旁，所有跳转改到任务列表；截图验收后修复路把趋势图的读屏明细表包进隐藏容器（手机宽度页面被撑宽 37px）。
- 第二版的实现历史见改动历史。

## 5. 验证方式

`node scripts/ui/probe.mjs` 里「总览」开头的断言（占用「23 / 40」、指标数字 16px、排队中和重试中跳列表带小标签、任务次数 806、今日档位、维度切换与图例数、明细行跳列表、无「其他」、图例开关、空场景、停用场景、手机宽度用下拉）；`node scripts/ui/shoot.mjs` 的 overview 截图。界面不写单测（全局规范）。
