# 界面层 · 任务

> 模块定位：任务页——筛选条、已选条件、任务表格（排序、滚动加载、实时刷新），右侧任务详情与过程时间线 · 对应代码：`apps/web/src/features/tasks/`、`apps/web/src/features/worker/`、`apps/web/src/pages/TasksPage.tsx` · 所属里程碑：[M6 第二版控制台看板](../roadmap.md#m6) · 状态：已实现，待用户确认 · 最近更新：2026-09-25
>
> 视觉与交互规范：[前端设计](../前端设计.md)；实现规格：[design/任务.md](../../apps/web/design/任务.md)，详情和时间线的行为沿用 [design/工作区.md](../../apps/web/design/工作区.md) R6～R8；共用地基：[控制台框架](界面层-控制台框架.md)；第一版：[工作区看板](界面层-工作区看板.md)。

## 1. 职责与边界

- **管：** 筛选条（状态、项目、池、角色、时间、标题搜索）、已选条件小标签、任务表格（八列 / 打开详情后收窄成两层一列）、`GET /api/tasks` 的无限加载、进行中行用快照实时刷新；任务详情（头部、元信息、任务书、回报、过程时间线）。
- **不管：** 查询语义（服务端 `TaskRepo.query` 和演示版同语义实现）；小标签的文字（`lib/taskFilters.ts`）。

## 2. 结构与数据流

```text
TasksPage(:id?) ─▶ TaskFilterBar ─┐
                ─▶ ActiveFilterChips ├─ taskFilterStore
                ─▶ TaskTable(compact, selectedId) ─▶ useTasks(toTasksQuery) 无限加载 + mergeLiveSummaries(快照)
                ─▶ WorkerDetail(id, onClose) ─▶ workerStore.open(id) ─▶ 数据源单苦工流（详情 + 时间线增量）
                                   └─ Timeline（合并工具调用、跟随滚动、回到最新、筛选）
```

## 3. 关键决策

| 决策 | 理由 |
|---|---|
| 第一版工作区并进任务页：默认筛「进行中」 | 需求 V3；不再单独保留工作区页 |
| 详情打开时表格收窄成「状态 + 标题」 | 对照用户挑定的示意图；详情需要大部分宽度 |
| 表格和详情各自滚动 | 看详情时不丢表格位置 |
| 耗时列：工作中显示这次运行的实时时长，结束后显示各次运行合计 | 合计里的在跑部分要实时走，单独算更简单 |
| 时间线筛选计数不含运行分隔行 | 沿用第一版口径（行数 19 = 15 条 + 4 条分隔） |

## 4. 当前实现

- 任务表格一路：第一次派给 dsf 的苦工 40 分钟一个文件没写，取消后换 luna 重派，18 分钟完成。
