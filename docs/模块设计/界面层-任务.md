# 界面层 · 任务

> 模块定位：任务页——首页看板（三列展开 + 失败、已取消收起）、历史列表（筛选、排序、滚动加载）、两者共用的视图栏和筛选栏、任务详情页（面包屑、正文、时间线、属性栏） · 对应代码：`apps/web/src/features/board/`、`apps/web/src/features/tasks/`、`apps/web/src/features/worker/`、`apps/web/src/pages/TasksPage.tsx`、`apps/web/src/pages/TaskDetailPage.tsx` · 所属里程碑：[M6 第二版控制台看板](../roadmap.md#m6)、[M7 第三版界面](../roadmap.md#m7) · 状态：第三版已实现，待用户确认 · 最近更新：2026-09-29
>
> 视觉与交互规范：[前端设计](../前端设计.md)（第三版）；实现规格：[看板](../../apps/web/design/看板.md)、[任务列表](../../apps/web/design/任务列表.md)、[任务详情](../../apps/web/design/任务详情.md)，时间线的行为最早定在第一版 [工作区](../../apps/web/design/工作区.md) R6～R8；共用地基：[控制台框架](界面层-控制台框架.md)；第一版：[工作区看板](界面层-工作区看板.md)。

## 1. 职责与边界

- **管：** 看板（按状态分列、列内排序、收起组的展开收回、三层任务卡、方向键在卡片间移动、空和加载）；列表（九列按宽度逐档隐藏、`GET /api/tasks` 无限加载、进行中的行用快照实时刷新）；视图栏（看板 / 列表切换、选了项目时的面包屑、显示弹层）；筛选栏（筛选菜单、已选条件小标签、时间范围、标题搜索）；详情页（面包屑返回与 Esc、标题和状态、失败说明、回报、任务书、时间线、属性栏）。
- **不管：** 查询语义（服务端 `TaskRepo.query` 和演示版同语义实现）；看板分列、排序、卡片小片、筛选小标签的规则（`lib/board.ts`、`lib/taskFilters.ts`，有单测）；搜索弹窗（控制台框架）。

## 2. 结构与数据流

```text
TasksPage(view = board | list)
  ├─ ViewBar：任务 [› 项目] · 看板 / 列表 · DisplayMenu（看板：卡片显示哪些信息；列表：排序方式和方向）
  ├─ TaskFilterBar(view)：筛选菜单（列表多一项状态）· 小标签 · 清除筛选 ·（列表）时间范围 · 标题搜索 ── taskFilterStore
  └─ view = board ─▶ TaskBoard：snapshot.workers → filterBoardWorkers → groupBoardColumns → boardLayout(boardStore.expanded)
                         ├─ TaskBoardColumn × 3～5（列头：状态图标、名称、数量；失败、已取消展开后有收起按钮）
                         │     └─ TaskBoardCard（链接）：编号 · 池 / 状态图标 + 两行标题 / 进度小片 · 不通过 · 项目 · 角色
                         └─ TaskBoardEnded：失败、已取消短条（失败数标红），点了展开成列
     view = list  ─▶ TaskList：useTasks(toTasksQuery) 无限加载 → 快照里同编号的摘要更新鲜，投影回接口顺序
TaskDetailPage(:id)
  ├─ ViewBar：任务 › 编号（点「任务」或按 Esc：站内来的退回上一页，直接打开的回最后停的视图）· 复制编号
  └─ WorkerDetail(id, onBack) ─▶ workerStore.open(id) ─▶ 单任务流（详情 + 时间线增量）
        左栏 #detail-scroll：标题与状态行、失败说明、（窄屏）属性块、回报、任务书、时间线
        右栏（≥1024）：TaskProperties（状态、耗时、项目、角色、池、渠道、运行、用量、目录、创建）
```

## 3. 关键决策

| 决策 | 理由 |
|---|---|
| 看板数据只用实时快照（进行中 + 最近 24 小时结束的） | 不多发请求；更早的历史由列表负责 |
| 展开排队中、工作中、已完成，失败和已取消收在右侧短条 | 用户拍板；失败数标红保证不会被忽略 |
| 列内顺序：排队按位次交错（各队第 1 位在前）、工作中最近开跑的在前、已结束最近结束的在前 | 排队位次是按各池和公共排队分别算的，按排队时间排会让位次乱跳；新开跑、新结束的放最上面最先被看到 |
| 卡片「负责人」位置放所在的池，「优先级」位置放进度小片 | fleet 没有人和优先级；池就是谁在干，小片给出排到第几、跑了多久、重试几次、为什么失败 |
| 卡片整张是链接 | 回车、中键新标签页都自然可用 |
| 列表默认「全部」、排序挪进显示弹层 | 看板承担「进行中」；列表像 Linear 一样没有表头排序按钮 |
| 列表用原生表格、按宽度逐档隐藏列 | shadcn 表格外层的横向滚动会让表头吸顶失效；窄屏宁可少列也不横向滚动 |
| 详情独占工作区，左正文右属性 | Linear 的任务页布局；时间线需要宽度 |
| 返回：站内跳来的退回上一页，直接打开的回最后停的视图 | 从槽位格子、搜索、看板、列表进来都能回到原处 |

## 4. 当前实现

- 第三版（M7）三路并行：看板一路（luna）照 [看板](../../apps/web/design/看板.md) 实现，自评里提出「看板不发请求」和共享项目标签会查项目列表的说法冲突，主控判定项目列表是全站共用的缓存查询，不算缺陷；任务页一路（luna）写视图栏、筛选菜单、显示弹层和列表，删掉第二版的表格；详情一路（luna）把详情从表格右侧的卡片改成独占工作区的两栏页面，旧的元信息网格搬进属性栏，时间线行为全部保留。
- 验收时查出第二版就有的隐患：直接打开或刷新详情链接会一直停在加载中（详情比外壳先订阅，还没拿到数据源），在启动入口提前绑定数据源后修复。
- 第二版的实现历史见改动历史。

- `node scripts/ui/shoot.mjs <标签>` 的 board、list、detail 截图（五档宽度 × 深浅）。
