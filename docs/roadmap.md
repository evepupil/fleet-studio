# fleet-studio Roadmap

> 最近更新：2026-09-24

当前进度：M0 至 M3 全部完成，`fleet` 命令已装进 PATH。M4 进行中：旧的全局派活 skill 已抽成仓库里的 fleet 系列五份并装到 Claude Code，苦工提示词也已收进仓库；等用户试用，Codex 还没装。任务看板、决策收件箱等后续里程碑待用户拍板。

## 1. 目标

依据 [需求设计](需求设计.md)、[技术设计](技术设计.md)、[架构设计](架构设计.md) 和 [前端设计](前端设计.md)，交付一个本机常驻的苦工闸门服务、给主会话用的 `fleet` 命令、以及只读的工作区看板；并用随仓库维护的 fleet 系列 skill 教各项目的主会话经它派活。

## 3. 里程碑与分层的对应

### M0

- [核心层](架构设计.md#1-总体与分层)：定死全部共享类型和接口契约（后续各路并行开发的前提）；实现配置校验、容量调度、状态流转、结局判定、pi / opencode 两套事件流解析、回报解析、快照汇总。
- 工程骨架：pnpm 工作区、严格 TypeScript、Biome、Vitest、门禁脚本、CodeGraph 初始化。

### M1

- [服务层](架构设计.md#2-两条主路径)：存储、进程托管、调度引擎、接口四个模块，按「先定接口再并行」开发。
- [命令行层](架构设计.md#1-总体与分层)：`fleet` 命令全集与自动拉起服务。
- 测试支撑：假苦工脚本，覆盖成功、重试、失败、长时间运行、崩溃几种剧本。

### M2

- [界面层](架构设计.md#1-总体与分层)：先做界面调研和视觉方向，定稿 [前端设计](前端设计.md)，再按规格实现容量条、项目列表、苦工详情三块。

### M3

- 服务层补过期清理和健康统计；界面补用量和健康展示；更新 `~/.claude/skills` 与 `~/.codex/skills` 下的派活规范。

### M4

- [接入层](架构设计.md#1-总体与分层)：六份 skill（谈设计、派活基础规矩、按里程碑开发、做界面、评审与销账、运维）和安装脚本；苦工提示词收进仓库；门禁加 skill 与命令的一致性检查。
