# fleet-studio 需求设计

> 最近更新：2026-09-23 · 状态：已定稿（用户授权主会话自行决定需求细节）

## 一、一句话定位

给同时推进多个项目的个人开发者用的「苦工闸门 + 工作区看板」。各项目的主会话通过它派出便宜模型苦工；它按模型池的全局容量排队放行，并把所有苦工的占用情况和实时输出摆在一个页面上。

## 二、背景

### 现在的干活方式

- 每个项目只开一个主会话，用户在 codeg 里直接和它对话。主会话身兼产品经理、开发负责人、测试负责人和运维。
- 主会话不自己写代码，按 pi-fleet / oc-fleet 规范直接拉起 pi 或 opencode 进程当苦工，给每个苦工一份自带全部信息的任务书，收回固定格式的回报，再验收。
- 苦工按角色分工：实现、侦察、评审、修复，信息设计另有四个专用角色。

### 痛点

1. **没有全局容量。** 同一条通道（例如 dsf，实测 20 路全过、40 路掉到 92%）被几个项目同时打满，就会大面积失败。每个主会话只知道自己开了几路，不知道别人开了几路。
2. **看不见。** 哪些苦工在跑、属于哪个项目、在干什么、卡在哪，只能去各项目目录翻输出文件。
3. **启动方式有坑。** PowerShell 下工具限制参数不加引号会静默失效；每路苦工套一个后台作业多吃约 100MB 内存；中文输出要手动设编码；用户级环境变量（通道密钥）在后台作业里读不到。

### 边界

- 主会话的对话仍然在 codeg 里进行。fleet-studio 不做聊天、不做任务收发、不替主会话做决策。
- 只管经 fleet-studio 派出的 pi / opencode 苦工。codeg 或 Claude Code 自带的子代理不在管辖范围内。

## 三、谁在用

| 谁 | 怎么用 | 要什么 |
|---|---|---|
| 用户 | 打开看板扫一眼 | 容量被谁占了；每个项目几个苦工、各在干什么；哪个失败了；点进去看它的输出 |
| 主会话 | 命令行 `fleet` | 派活、等结果、读回报、续接纠偏、取消、查容量 |
| 苦工 | 被服务拉起 | 无需任何改动，照旧按角色提示词干活 |

## 四、名词解释

| 名词 | 意思 |
|---|---|
| 模型池 | 一条通道上的一个模型，就是一份大家共用的容量。例如 dsf = mcgrox 通道的 deepseek-v4.1-flash，容量 20 |
| 槽位 | 池里的一个名额。一个苦工进程在跑就占一个，结束就还回去 |
| 项目 | 苦工归属的项目目录，看板按它分组。苦工实际干活的目录可以不同（例如临时目录），归属要单独说明 |
| 苦工 | 派出去的一份活，对应一个可以续接的 pi / opencode 会话。有标题、角色、所属项目、所在池 |
| 运行 | 苦工的一次进程执行。第一次派活是第 1 次运行；主会话追加指令纠偏会产生第 2、3 次运行，每次都要重新占槽位 |
| 角色 | 苦工的分工，决定追加哪份提示词、禁用哪些工具 |
| 回报 | 苦工收尾时按角色约定输出的几段固定格式文字，例如 SUMMARY、VERDICT |

## 五、功能需求

### F1 模型池与容量（核心）

1. 池在配置文件里登记：编号、显示名、容量、在 pi 和 opencode 下分别怎么指定模型、可选的单项目上限。
2. 同一个池里同时在跑的苦工进程数不超过容量，多出来的排队。
3. 空出槽位时按「谁占得少谁先补」放行：在有排队的项目里，挑当前在这个池占用最少的那个项目，放它最早排队的苦工；占用一样多时，谁先排队放谁。一个项目排了一长串，也堵不住后来的项目。
4. 设了单项目上限的池，一个项目占满上限后，它的排队只能等自己的苦工结束。
5. 容量可以在运行中调整（改配置文件或命令行）。调小时不打断已经在跑的苦工，只暂停放行，直到占用回落到容量以内。
6. 例子：dsf 容量 20，项目甲占了 12 个，项目乙最多还能用 8 个；甲再派的活进排队，乙的活优先补空位。

### F2 派发与生命周期

1. 状态五种：**排队中、工作中、已完成、失败、已取消**。
2. 工作中的苦工遇到通道错误自动重试时，额外标出「重试中 第 N/M 次」和错误原因。
3. 已完成指模型正常收尾。失败分几种原因，每种都要有说明文字：通道错误重试耗尽、启动失败、运行时报错（例如缺密钥）、进程异常退出、运行超时、排队超时、服务重启后接管不了。已取消指主会话主动取消。
4. 超时：单次运行默认最长 30 分钟；排队默认不限时。两者都能按池配置，也能在单次派活时指定。排队默认不限时的理由：排了半小时被踢回去重新排到队尾，比晚点开跑更亏。
5. 取消：结束整棵进程树，苦工正在跑的命令一起结束。排队中的直接撤掉。
6. 续接：对已经结束的苦工追加一句指令，在同一个会话上开一次新运行，上下文完整保留。新运行照样占槽位、照样排队。
7. 苦工由服务直接拉起，参数由服务直接交给进程，不经过 PowerShell 或 cmd 转义：多行任务、引号、中文原样送达；工具限制一定生效；用户级环境变量（例如通道密钥）自动补齐。
8. 服务重启后：排队中的继续排；工作中的苦工如果进程还活着就接着跟踪输出，接管不了的标为失败并写明原因。

### F3 角色

1. 角色在配置里登记：编号、中文名、pi 下追加的提示词文件和禁用的工具、opencode 下对应的 agent。
2. 默认角色沿用现有的实现、侦察、评审、修复和信息设计四个角色，提示词文件仍然放在 `~/.pi/agent/roles/`，只在一处维护。
3. 新增「测试」角色：只按任务书描述的行为写测试、跑测试、报告结果，不改业务代码。用途是让写测试的和写实现的不是同一个会话，避免自己出题自己答。
4. 用户可以在配置里增删角色，不用改代码。

### F4 看板：工作区视图

1. **顶部容量条。** 每个池一条，一格一个槽位。被占的格子按项目着色，同一项目颜色固定；排队数单独标出。鼠标悬浮或键盘聚焦某一格，显示该苦工所在项目目录、标题、角色、已运行时长。条上同时能看到已用/容量，以及池最近的失败和重试情况。
2. **左栏项目列表。** 按项目目录分组，每组显示项目名和各状态数量。点开是这个项目下的苦工列表，每行显示标题、角色、状态、时长；正在重试的、自评不通过的要一眼能认出来。默认显示进行中和最近结束的苦工。
3. **右侧苦工详情（只读）。** 头部是标题、状态、角色、所属项目、模型、时长、用量和费用；下面依次是任务书（默认折叠）、实时活动时间线（读了哪个文件、跑了什么命令、改了哪个文件、模型说了什么、报错和重试）、结束后的回报卡片（按段落拆开，通过/不通过醒目标出）。多次运行按时间顺序串在一条时间线上。可以切换查看原始输出。
4. **实时刷新。** 容量、状态、时间线自动更新，不用手动刷新；新输出到来时，停在底部就跟着滚，往上翻看时不打扰。
5. **只读。** 看板上不能派活、取消或改容量。
6. **各种状态都有画法：** 没有任何苦工；项目下没有苦工；时间线还没有输出；服务连接断开（自动重连）；加载失败；长标题、长路径截断并能看到全文。

### F5 命令行（给主会话用）

| 命令 | 做什么 |
|---|---|
| `fleet run` | 派一个苦工，立即返回苦工编号；可选等它结束 |
| `fleet wait` | 等一个或多个苦工结束（全部或任一），打印状态和回报 |
| `fleet ps` | 列出进行中和最近结束的苦工 |
| `fleet show` | 看一个苦工的详情和回报 |
| `fleet log` | 以文字形式看苦工的活动时间线 |
| `fleet send` | 对已结束的苦工追加指令（续接） |
| `fleet cancel` | 取消苦工 |
| `fleet pools` / `fleet pool set` | 查看容量占用 / 调整容量 |
| `fleet roles` | 列出可用角色 |
| `fleet daemon` | 启动、停止、查看服务 |
| `fleet open` | 在浏览器里打开看板 |

补充约定：

- 服务没启动时，任何命令都会自动把它拉起来。
- 默认输出给人和模型都好读的文字，加 `--json` 输出结构化数据。
- 退出码有约定：成功、有失败、等待超时各不相同，方便主会话写循环。
- 苦工归属的项目默认取当前目录所在的 git 仓库根目录；在临时目录里干活时必须显式指定。

### F6 历史、用量与健康

1. 已结束的苦工默认保留 7 天，可配置，过期的记录和输出文件自动清理。
2. 每个苦工统计 token 和费用（取自苦工输出里的用量字段），项目和池按当天汇总。
3. 池的健康：最近 10 分钟的完成数、失败数、正在重试数，在容量条上可见。通道一出问题，在大面积失败之前就能看出来。

## 六、非功能要求

- **安全：** 只监听本机 127.0.0.1。拒绝主机名或来源不是本机看板的请求，防止网页跨站调用和 DNS 重绑定。会改变状态的接口必须带本机令牌，令牌只存在用户目录里。
- **稳：** 服务重启不丢排队、尽量不丢在跑的苦工；单个苦工的输出解析出错不影响其他苦工。
- **轻：** 服务常驻内存目标 150MB 以内；100 个苦工、单个苦工上千条活动时，看板不卡。
- **干净：** 不修改任何项目文件，苦工输出统一放在用户目录下的数据目录。
- **平台：** Windows 优先，代码不写死平台。

## 七、这一版不做

- 聊天、任务收发、决策收件箱：主会话的对话留在 codeg。
- 看板上的任何写操作。
- 管理 codeg 或 Claude Code 的原生子代理。
- 多机、账号、云同步。
- 按请求精确计量通道压力：容量按进程数计。

## 八、以后可能做

- 任务看板。
- 通道熔断：连续失败时自动暂停放行，恢复后自动继续。
- 本机转发代理：按在途请求精确计量容量，按项目精确计费。
