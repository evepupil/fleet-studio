# fleet-ui-build

一句话：**页面丰不丰满，取决于规格里摆了多少东西。苦工只是转录。**

三次实测（见 `references/实测记录.md`）指向同一件事：同一档苦工，规格写满就出满页，规格写三行就出三块。所以力气全押在写规格上，后面只是搬运和验收。第三次把规模放大到 4 页 34 个区块、9 路并行，结论照样成立。

## 和别的 skill 的分工

| skill | 管什么 |
|---|---|
| `fleet-discuss` | 设计阶段：功能清单、页面清单、视觉方向和 `docs/前端设计.md` 在那里定，本 skill 照着落地 |
| `frontend-design` | 风格：颜色、字体、气质、别像模板货 |
| **本 skill** | 加法与落地：把这类站该有的全摆上、写到数字、派人做出来、验收 |
| `fleet-dispatch` | 派活规矩：苦工从哪来、fleet 命令、返工、验收、进度流水。本 skill 派的每一路都照它 |

手上没有 fleet-discuss 的产物也能用本 skill，站点层里的参照对象会替你补上骨架；有它定的页面清单，就拿来当页面和区块的底稿，页面层仍按参照站往上加满。

## 核心纪律：先扩散，再收敛

减法流程的每一道门都在删东西：「有没有必要」「装饰挤占数据就删」「编一条就登记一条」。模型在这种规则下的最优策略是少写，少写就是空。所以顺序要倒过来。

1. **先摆满。** 对着站点类型和两三个具名参照，把这类页面该有的区块全列上，每块写到元素和数字。这一步不问「有没有必要」。
2. **再删。** 满稿之后才做减法。删一个要过密度下限，并说清楚拿什么填回那块视觉重量。
3. **数据先编。** 真实的部分逐字照抄，其余编合理的，集中登记成一张「哪些是编的」清单交给用户替换。**不要把编造变成一堆待确认问题**——那会逼模型留白。

**密度下限**（写规格前先定死，写完对照）：参照站有几个区块，你不能更少；首屏必须出现这类站的核心动作（搜索站给搜索框、目录站给产品、工具站给入口）；每个区块至少三个具体元素，只有标题加一句话的区块不算数。多页站每一页都要单独过一遍。

## 界面实现与文案的硬规矩

写进站点层和每份任务书，验收时逐条核对：

- **先有设计系统再写页面。** 项目里已有令牌和基础组件就沿用；没有就先按 `docs/前端设计.md` 做出来（第 3 步的地基路就干这个）。顺序反了会留下一堆改不动的写死值。
- **只用令牌和基础组件。** 业务代码里不写死颜色、字号、间距，不重复造已有的组件，一个项目只用一套组件体系。
- **规范变更两头改**：主题配置和 `docs/前端设计.md` 同时改。
- **每个页面和组件都处理**长文本溢出、空状态、加载状态、错误状态，以及不同宽度下的自适应。这是交付标准。
- **文案按最小必要信息写。** 区块照样先摆满，每块里的文字收着写：
  - 删掉后不影响理解和操作的文案，就不加
  - 不写无意义的状态文案，例如「本地服务在线中」「一切运行正常」
  - 克制使用「主标题 + 副标题 / 描述」，能只留标题就不加描述
  - 不展示开发说明、版本规划、实现备注，例如「V1 暂不支持」「后续开放」
  - 不给每个区块都配标题、说明和提示；页面只放完成当前任务需要的信息

## 规格分两层，由同一个人写完

| 层 | 文件 | 写什么 |
|---|---|---|
| 站点层 | `DESIGN.md` | 定位与参照、**页面清单**、技术栈、设计令牌、动效、文件结构与**共享组件签名**、文案、门禁、写入边界与分路表、哪些是编的、数据 |
| 页面层 | `design/<页面>.md`，每页一份 | 这一页的底色节奏、逐区块规格、本页最重要的区块、交互检查会找的标记 |

分层的好处：页面层直接站在站点层定好的令牌、组件、数据上写，不用再争；地基路只需要站点层，可以提前开工；每路苦工只读站点层加自己那一页，不用读全站所有页。

**分层写，不拆给多人写。** 两层都由主控在同一个会话里依次写完，每一层都只做加法。早先试过把每一层拆给几十路便宜模型、各看一个节点，层与层之间还只做减法，结果越写越薄；这里要避开的正是这一点。实测四页的页面层一共写了 16 分钟，一个人写得过来。

单页站也分两层：站点层写短一点，页面层只有一个文件，模板和工具都不用变。

## 流程六步

每一路都经 fleet 派出（命令、返工、出错处理见 `fleet-dispatch`），每个检查点按它第九节记进度流水。

### 第 0 步 先定验收标准

动手前写下：全站的页面数、门禁项、真实性边界、用户的硬规矩；每一页的区块数下限、首屏核心动作、要处理的状态（空态 / 缺值 / 加载 / 错误 / 溢出）。落成一份 `测试设计.md`，或直接写进站点层第 0 章。

**为什么先写**：产物出来后人会被自己的作品说服。标准写在前面，验收时逐项对，才抓得住「其实少了一块」「手机首屏的核心动作被挤到第二屏」这种问题。

### 第 1 步 主控写站点层

照 `templates/DESIGN.md` 写。这一步不外包。几个要点：

- **页面清单**是站点层的核心：每页干什么、首屏放什么核心动作、参照哪个真站的哪一页、区块数下限、分给哪一路。先把页面定下来，页面层才有地方落。
- **共享组件签名**要写到完整参数和默认类名。各页的区块都 import 同一套组件，这是几路苦工互相看不见、产出却像一个人写的原因。
- **数据怎么交**：几十条以内、没有计算逻辑的，写进站点层附录，让地基路逐字落盘；数据多或带计算（生成器、校验规则、推算公式）的，**主控直接写成数据代码并配单测**，站点层只留一张接口索引。交互检查要核对的具体数字，从单测里算出来。
- 页面里有倒计时、「报名中 / 已截止」这类跟时间有关的状态，就在数据里定一个**演示用的固定当前时刻**，所有状态都从它算，截图和交互检查每次结果一致。

写满到什么程度，见 `references/规格怎么写满.md`。

### 第 2 步 主控写页面层（和地基同时进行）

站点层一写完就派地基路（第 3 步），然后回来按 `templates/页面规格.md` 逐页写页面层。每个区块写七项：外层、每个元素、数据来源、交互、状态、响应式、文案。选组件先看 `references/常见组件.md` 有没有现成的，别自造。每页点明最重要的区块，允许它写得最长。每页末尾列一张「交互检查会找什么」的表，把要用的 `data-*`、`id`、按钮文字定死——几路苦工互相看不见，交互检查只能靠这些标记找元素。

### 第 3 步 一路搭地基，主控核对再放行

地基路只读站点层。它做：脚手架、令牌配置、全局样式、共享组件、每页骨架、每个区块一个极简占位；数据走附录的话照抄落盘。

任务书用 `templates/任务书-地基.md`，派法：`fleet run --role worker --title "地基" --prompt-file .fleet/briefs/foundation.md`。本机有同栈项目时复制它的锁文件，先试离线安装（实测 20 秒，联网装要 8 分钟）。

**主控必须核对四样再往下派**：数据文件没被改动（走附录的就 `diff` 附录）、令牌色值与规格一致、共享组件签名与规格一致、每个占位的导出名。地基错了，后面几路一起错。

### 第 4 步 按页分路，并行转录

每路一份任务书 = `templates/任务书-公共.md` + `templates/任务书-区块.md`。

- **经 fleet 并行派出**：每路 `fleet run --role worker --title "<页面>·<区块组>" --prompt-file <拼好的任务书>`，再按 fleet-dispatch 第五节用 `fleet wait --any` 回来一路验一路。区块路是照抄活，可以用 `--thinking` 降一档：第一次实测时档位高，苦工把工具调用轮次烧在了防御性检查上。
- **每路读站点层全文 + 自己那一页**，不读别的页。
- **按页面分路**：一路 3～7 个区块；交互最重的区块（表单、查询、可交互地图、多状态组件）单独一路。实测 9 路同时写一个仓库，零冲突。
- **文件归属写死。** 公共文件谁都不准碰；每路只写自己的文件；要拆子组件，只能放在本页目录、用自己的区块名开头。
- **苦工只转录。** 规格里有的元素一个不能少，规格没写的按同一套令牌补齐，不要自己发挥。
- **自检只跑类型检查**，不跑构建、不起开发服务器。构建由主控统一跑。
- **固定五行回报**，主控机器式扫过去；但「拿不准的点」那一行要逐条看——实测苦工靠它报出了 3 处规格自己的错误。

### 第 5 步 验收，然后一轮修复

五件事，缺一件就会漏东西（用法与坑见 `references/验收.md`）。把本 skill 的 `tools/`（装好后在 `~/.claude/skills/fleet-ui-build/tools/`）整个目录复制到项目的 `.fleet/`，每个工具开头有一段「按项目改这里」；`cdp.mjs` 是三个浏览器工具共用的部分，页面会从导出目录里自动发现。

1. **门禁脚本** `tools/gate.sh`：单测、类型检查、构建、禁用项、客户端指令、图标白名单、导出名、交互检查标记是否都在。
2. **读代码**：每路交付的文件对着页面层逐项核。构建对「编译过但看着错」一律沉默。
3. **看图**：`tools/local-copy.mjs` 生成能离线打开、页面之间能互相跳的副本；`tools/shoot-cdp.mjs` 逐页做手机与桌面的设备仿真截图，并实测横向溢出。
4. **看交互状态**：`tools/shoot-states.mjs` 点出报错态、提交成功、抽屉、手机菜单再截图——静态截图拍不到这些。
5. **点一遍**：`tools/probe.mjs` 逐页真实点击并断言具体数值，顺带收集页面报错和首屏不一致告警。

发现的问题**攒成一份带位置的修复任务书**派一路修复角色（`fleet run --role fixer ...`），不要自己动手改——除非是一行的公共文件改动。修复任务书用 `templates/任务书-修复.md`，逐条写清在哪个文件、原来是什么、改成什么、为什么；同类问题要求修复路全站排查一遍。

## 已知坑（实测踩过）

**写代码时**

- **ESLint 的站内链接规则**会和「一律用原生 `<a>`」冲突，构建阶段才报。地基任务书里就把规则关掉。
- **接收回调的组件也要标客户端**。父组件给它传函数，它就得是客户端组件。
- **样式拼接函数不能放进带客户端指令的文件**。服务端组件调用客户端文件导出的普通函数会报错；这类函数单独放一个不带指令的文件。
- **Tailwind 只认完整类名**。按状态切换颜色要用对象映射写全类名，拼接出来的类名不会生成样式。
- **多页站的顶栏要知道当前页**，和「区块不接收参数」冲突。在规格里开唯一一个例外，只给顶栏一个「当前页」参数。

**布局（构建和交互检查都抓不到，只有截图抓得到）**

- **网格里放横向滚动的宽表格会撑破手机页面**。表格外面包了横向滚动，但包它的卡片是网格子项，默认最小宽度等于内容宽度，整列被撑宽。网格子项里有横向滚动区，就给子项加 `min-w-0`。
- **纵向弹性布局会把小徽标拉成整条**，徽标要 `self-start`。
- **左右两栏高度不一时卡片会被拉伸留白**，规格里写明是等高还是顶部对齐（`lg:self-start`）。
- **能用键盘聚焦的 SVG 元素**（地图标记、图表里的点）要写焦点样式，去掉默认轮廓线就得给替代样式。

**验收时**

- **一次性截图参数不可靠**。本机有其他浏览器实例在跑时，带 `--screenshot` 的无头调用会静默退出、退出码 0、不产出文件。截图一律走调试协议。
- **无头浏览器有最小窗口宽度**，直接截 375 会被裁。必须走调试协议的设备仿真。
- **延迟加载的图片在整页截图里是空白**。截整页前先把视口撑到整页高度，等两秒再拍。
- **整页截图超过约 16384 像素会失败**。长页面按段切。
- **静态导出用 `file://` 打开时绝对路径资源 404、站内链接点不通**。用 `local-copy.mjs` 生成的副本。

**写规格时**

- **位置类指令有歧义**。「在某某后面加一行」苦工可能理解成容器内部。要写「在这个 div 的闭合标签之后」。
- **规格的笔误会被忠实照抄**。同一个元素写了两个同类间距，苦工两个都保留。
- **模板里的说明文字会被当正文抄进去**。所以本 skill 的模板把说明写在 HTML 注释里。

## 规模参考

| | Tackle Atlas 首页 | 澄湾马拉松 4 页 |
|---|---|---|
| 区块 | 10 | 34 + 顶栏页脚 |
| 规格 | 单文件 46 KB | 站点层 46 KB + 页面层 120 KB；数据另写成代码 2,410 行 + 32 条单测 |
| 苦工 | 1 地基 + 4 区块 + 1 修复 | 1 地基 + 9 区块 + 1 修复 |
| 一次成功 | 6/6 | 11/11 |
| 主控介入业务代码 | 3 次，全是一行 | 1 次，一行 |
| 交互检查 | 9/9 | 29/29 |
| 墙钟 | 48 分钟 | 约 133 分钟 |
| 产出 | 2,398 行 | 约 9,500 行 |

苦工档次按 fleet-dispatch 第二节挑：区块路是照抄活，默认池就够；地基路和交互最重的区块（表单、查询、多状态组件）可以给强模型。**规格质量决定产物，苦工档次决定成功率和速度。**

## 交棒

做完页面再接 `frontend-design` 优化视觉：结构和数据已经定死在规格里，视觉只改站点层的令牌和页面层里的视觉描述，重跑区块路即可，结构一行不动。
