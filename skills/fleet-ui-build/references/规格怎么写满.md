# 规格怎么写满

这份文档回答一件事：第 1、2 步的规格，站点层和页面层各写到什么程度才算够。

判断标准只有一条：**把这一份给一个没见过这个项目的人，他做出来的东西应该和你脑子里的一样。** 做不到就是没写完。

## 先说最常犯的错

写规格的人会不自觉地做两件事，两件都会把页面做空。

**一是把判断留给苦工。** 写「这里放产品卡片」，苦工就得自己决定卡片里有什么。它会给三个字段，因为三个最安全。写成「图片区 4:3、品牌小字、型号加粗可换行、系列与年份一行、三列规格各带单位、底部左侧轮型与水域标签右侧出处标记」，它就给九个元素。同一个苦工，差别只在你有没有替它做完判断。

**二是提前节制。** 「保持克制」「不要堆砌」「装饰挤占数据就删」这类话写进规格，等于让苦工在没有页面的时候先删页面。节制是验收时的事。规格阶段只管摆满，摆完你自己删。

## 两层各写什么，按什么顺序写

| 顺序 | 写什么 | 谁在等它 |
|---|---|---|
| 1 | 站点层 `DESIGN.md`：定位、页面清单、技术栈、令牌、动效、文件结构与共享组件、文案、门禁、分路表、编造清单、数据 | 地基路：站点层一写完就派 |
| 2 | 数据层（数据多或带计算时）：主控直接写成数据代码 + 单测 | 地基路核对、交互检查的期望值 |
| 3 | 页面层 `design/<页面>.md`：逐页写，每页从首屏写到页脚 | 区块路：页面层写完、地基核对过就派 |

两层都由主控在同一个会话里依次写完，不拆给别人。实测参考：站点层约 20 分钟，四页页面层合计 16 分钟（和地基路同时进行）。

**哪些东西放站点层**：凡是两页以上都会用到的——令牌、共享组件、数据、顶栏页脚、文案规矩、门禁。**哪些放页面层**：只属于这一页的区块规格。拿不准时放站点层，页面层引用它。

## 站点层

### 第 0 章 定位与参照

最省力的一章，也最容易糊弄过去。

**参照必须点名。** 「现代简洁的数据库风格」模型没法用，「GSMArena 的 Phone Finder 面板、Reelcatalog 的目录卡、Versus 的图文规格关系」它立刻知道每一块长什么样。名字调动的是模型见过的成千上万个真实页面，形容词只能调动平均值——而平均值就是模板货。

每个参照写两栏：抄什么、不抄什么。「不抄」那栏同样重要，它挡住的是参照站里的广告位、评分体系、重复出现的赞助商墙。

**组件库也算参照。** 如果项目要用某个复制粘贴式组件库，点它的名字，模型会认出那一整套有名字的组件（聚光灯、光束背景、Bento 网格、粘性滚动），比你描述十句强。

没有现成参照时，先联网找三到五个同类站点看真实界面（可以派一路侦察 `fleet run --role scout`，要判断界面好在哪的调研给强模型，见 fleet-dispatch 第二节；要求只记实际打开看到的，打不开的写「未能访问」），或从记忆里点名并注明「凭记忆」。**禁止凭空设计**——这条和全局规范一致。

**页面清单**跟在参照后面。每页写：用户来干什么、首屏核心动作、参照哪个真站的哪一页、区块数下限、分给哪一路。区块下限按参照站对应页面的区块数定。这张表定下来，页面层才有地方落，第 8 章的分路表也照它切。

### 第 1 章 技术栈

两个容易漏的点，漏了会直接烧掉苦工的命：

- **图标白名单。** 不给名单，苦工会跑去依赖目录里 grep 确认某个图标存不存在，几轮工具调用就没了，还可能引用到已被移除的图标导致类型错误。给一份已确认存在的名单（在本机已装的版本里用一行脚本逐个检查），写明「别的形状手写内联 SVG」。
- **点名禁止的依赖。** 不禁止，动画库、UI 框架、图表库、地图库会自己长出来。

### 第 2 章 设计令牌

全部给数字。色值给十六进制，字阶给完整的类名串（包含响应式断点），间距给档位，阴影给完整的 box-shadow 值。

正文色标对比度。不标的话苦工会用更浅的灰，因为看起来更精致。写清哪些颜色只能做图形、不能做文字（亮橙、荧光绿这类在白底上对比度不够）。

### 第 3 章 动效纪律

这一章定「该不该动」，不同类型的站答案相反，所以必须写。

- 营销页、发布页：入场、视差、数字滚动、光斑跟随都可以。写清只动位移和透明度、写清缓动曲线和时长、写清无障碍降级。
- 资料站、工具站、后台：明确写「不做滚动入场、不做数字滚动、不做无限循环动画，只留 hover 和焦点态」。
- 营销加工具的混合站（赛事官网、产品官网带查询）：逐条列出能动的（hover、手风琴、抽屉、倒计时换字），加载转圈是唯一的循环例外。

**不写这一章，苦工会按营销页的默认审美加一堆动效**，资料站会因此显得廉价。

### 第 4 章 共享组件签名

每个共享组件写：文件、导出名、完整参数类型、默认类名、每个变体的完整类名串。写到这个程度，地基路照抄即可，各页区块 import 同一套，按钮、胶囊、数值、倒计时全站长一个样。

三条要写进来的硬规矩：

- 样式拼接函数单独放一个**不带客户端指令**的文件——服务端组件也要调用它，放进客户端文件会报错。
- 按参数切换颜色的组件一律用对象映射完整类名。
- 多页站的顶栏要知道当前页，这是「区块不接收参数」的唯一例外，在这里写明。

### 第 9 章 哪些是编的

这张表替代了「待确认需求表」。它是一份**交付物**：用户拿着它直接换数据，不用先回答一堆问题。

- 逐项标真实或编造，真实的写清出处，编的写清合理性依据。
- 用户拿着这张表一次换完真数据，不用回来问你哪些能信。
- 有单测校验的一致性写上（比如「名额构成之和等于总名额」），换数据时一跑就知道有没有改坏。

**不要因为「数据不真」就留白。** 编一个合理的数字，比空着更接近真实产品，也更容易被替换。

### 附录 数据

把页面要用的全部数据写成代码，理由有三：

- 几路苦工各编一套数据，横向对不上，总表和卡片会显示不同的数字。
- 数据写出来，等于逼你在写规格时就想清楚每个字段，省掉一轮返工。
- 换真数据时只改数据文件。

**两种交法，按数据量选：**

| | 数据少、没有计算 | 数据多或带计算（生成器、校验规则、推算公式） |
|---|---|---|
| 谁写成代码 | 主控写进附录代码块，地基路逐字落盘 | 主控直接写成数据代码 |
| 怎么核对 | 主控 `diff` 附录与落盘文件 | 主控配单测，地基路不准改 |
| 规格里放什么 | 完整代码 | 接口索引：每个文件的导出名和一句话用途 |

走第二种时，交互检查要核对的具体数字（结果数、名次、余量、编号）都从单测里算出来，写进页面层末尾的交互检查表。实测四页站的数据层 2,400 行、32 条单测，9 路苦工之间没有一处数字对不上。

真实数据从来源逐字抄，抄完自己核一遍。编造数据要合理：数值落在真实区间内、单位正确、枚举值来自真实的枚举表；大量记录（成绩、订单、评论）用固定种子的伪随机生成，同一份输入每次生成结果相同。

**跟时间有关的状态**（倒计时、「报名中 / 已截止」、剩余天数）：在数据里定一个演示用的固定当前时刻，所有状态从它算，页面打开后再从这一刻走秒。截图和交互检查每次结果一致，也不会出现首屏渲染与浏览器不一致的告警。

## 页面层

### 每个区块写七项

全站最重的部分，篇幅通常占规格的一大半。每个区块按这七项写，缺哪项苦工就在哪项上自由发挥：

1. **外层**：元素类型、完整类名、锚点 id、纵向留白、底色。
2. **内部每个元素**：是什么、放什么内容、什么字号颜色、怎么排。
3. **数据来源**：从哪个导出、用哪个格式化函数，期望显示成什么。
4. **交互**：点了怎样、状态存什么形状、默认值、切换时重置哪些、边界条件（选满几个禁用、点第二次取消、空结果显示什么）。
5. **状态**：空态、缺值、加载、错误、超限各显示什么。这一项最容易漏，漏了页面在真实数据下就会露馅。本次数据不会触发的状态也要写。
6. **响应式**：哪个断点换成哪套结构。
7. **文案**：直接把最终文案写进去，不要写「一句介绍」。

**每页最重要的那个区块要点明**，并明确允许它写得比别的区块长。不点明的话苦工会平均用力，首屏和页脚一样薄。每页开头再写一行「本页节奏」（从上到下的底色顺序），整页的明暗节奏就不会乱。

### 布局要写明的五件事

这几类问题构建不报、交互检查也不报，只有设备仿真截图抓得到。实测 11 处修复里有 6 处出在这里：

1. **网格子项里放横向滚动的宽表格**：子项加 `min-w-0`，否则手机上整页被撑宽。
2. **纵向弹性布局里的小徽标、小标签**：加 `self-start`，否则被拉成整条。
3. **左右两栏卡片高度不一**：写明等高还是顶部对齐（`lg:self-start`），否则短的那张被拉伸、下面空一大块。
4. **能用键盘聚焦的 SVG 元素**：写焦点样式；去掉默认轮廓线就要给替代样式。
5. **同一个元素只写一个同类间距**：写了 `mt-4` 又写 `mt-auto`，苦工会两个都保留。

### 交互检查标记

几路苦工互相看不见，交互检查只能靠事先约定的标记找元素。页面层里凡是要被检查的元素，写明 `data-*`、`id` 或按钮文字，并在每页末尾汇总成一张表：位置、操作、断言。断言写具体的值。实测 25 条断言靠这张表第一次就全过。

输入框、下拉写明必须是受控组件——交互检查用原型上的 value setter 赋值再派发事件，非受控组件感知不到。

## 写完的自查

- [ ] 页面清单里每页都有首屏核心动作、参照页、区块下限
- [ ] 每页区块数不低于下限，首屏出现这类站的核心动作
- [ ] 每个区块至少三个具体元素，没有「标题 + 一句话」的空块
- [ ] 每个区块都写了状态和响应式
- [ ] 每页点明了最重要的区块和本页节奏
- [ ] 共享组件写到了完整参数和类名；样式拼接函数不在客户端文件里
- [ ] 数据在数据文件或附录里，不在区块描述里写死；带计算的数据有单测
- [ ] 「哪些是编的」表覆盖了所有数字
- [ ] 布局五件事逐条过了一遍
- [ ] 每页末尾有交互检查表，断言写的是具体值
- [ ] 分路表和区块清单对得上，每个文件只属于一路
- [ ] 通篇没有「保持克制」「不要堆砌」这类提前节制的话
