# 验收

苦工自报 pass 不能信，构建通过也不能信——**「编译过但看着错」是这类活最常见的缺陷形态**：两层背景互相盖掉、透明度被覆写成二十倍、动画位移算错永远走不进可见区域、数字滚动实际只从 0 跳到 1、网格里的宽表格把手机页面撑宽、小徽标被拉成整条。这些构建全都不报错。

所以验收要五件事：跑门禁、读代码、看图、看交互状态、点一遍。工具在本 skill 的 `tools/` 下，**整个目录**复制到项目的 `.fleet/` 使用（`cdp.mjs` 是截图、状态截图、交互检查三个工具共用的部分，单独拷一个会报错），**每个工具开头都有一段「按项目改这里」的配置**。页面从导出目录里自动发现，不用逐页登记。

```bash
bash .fleet/gate.sh              # 1. 门禁（加 --no-build 跳过构建）
node .fleet/local-copy.mjs       # 生成能离线打开的副本，后面三个工具都用它
node .fleet/shoot-cdp.mjs v1     # 3. 逐页、手机与桌面截图 + 溢出实测
node .fleet/shoot-states.mjs     # 4. 交互状态截图
node .fleet/probe.mjs            # 5. 逐页点一遍并断言
```

## 一、门禁脚本 `gate.sh`

它做这些事：列出每个组件文件的大小（占位文件只有一两百字节，一眼看出哪一路没写）、单测、类型检查、构建并确认每页的导出文件都在、禁用项排查（any、随机数、取当前时间、十六进制色值、禁用依赖、拼接类名、占位与开发备注文案）、用了 hook 却没有客户端指令的文件、图标白名单、导出名核对、交互检查要找的标记是否都在代码里。

**项目专属的检查写在脚本底部**，比如「顶栏里不准出现某个词」「页脚必须有演示声明」。按站点层第 7 章的自查清单补。

## 二、读代码

每路交付的文件都读一遍，对着页面层逐项核。重点看四类：

- **规格里写了但代码里没有的元素**。苦工偶尔会漏掉一两个，报告里不会提。
- **层叠关系**。两个绝对定位的背景层、遮罩和被遮罩的元素、z 轴顺序。
- **边界条件**。选满时禁用了吗、空结果的文案换了吗、缺值渲染的是占位符还是 undefined、切换项目后该重置的状态重置了吗。
- **写死的业务数字**。`grep` 一遍年份、距离、人数这类字面量，应该都从数据文件取。

先看苦工回报里「拿不准的点」那一行：实测靠它发现了 3 处规格自己的错误（缺焦点样式、间距写重复、规格没写的细节被合理补齐）。

这一步没有工具能替代。构建和截图都看不出「这里本该还有一层」。

## 三、看图 `local-copy.mjs` + `shoot-cdp.mjs`

`local-copy.mjs` 遍历导出目录里的每一页，在旁边写一份 `index-local.html`：绝对路径资源按页面深度改成相对路径，站内链接改成指向对应页的本地副本。这份副本也方便用户自己双击打开逐页点看，不用起服务器——符合「不自行启动开发服务器」那条规矩。

`shoot-cdp.mjs` 自动找出所有页面，逐页做手机 375 与桌面 1440 的设备仿真截图，输出首屏一张、按段切片若干张，页面总高不超过 15000 像素时再存一张整页图；同时实测页面实际宽度并列出越界元素。

**只保留调试协议这一条路，是因为一次性截图参数不可靠**：本机有其他浏览器实例在跑时，带 `--screenshot` 的无头调用会静默退出、退出码 0、不产出文件。

**踩过的坑：**

| 现象 | 原因 | 解法 |
|---|---|---|
| 截图命令退出码 0 但没有文件 | 本机已有浏览器实例，一次性截图参数静默失效 | 走调试协议，别用 `--screenshot` |
| 375 宽的截图比实际宽 | 无头浏览器有最小窗口宽度 | 必须用设备仿真，不能靠窗口尺寸参数 |
| 整页截图里图片全是空白 | 延迟加载的图片没进过视口 | 截整页前先把视口撑到整页高度，等两秒再拍 |
| 长页面整页截图失败或花屏 | 超过约 16384 像素的纹理上限 | 按段切片（工具已处理） |
| 页面样式全丢、站内链接点不通 | `file://` 下绝对路径资源与链接都指向磁盘根目录 | 用 `local-copy.mjs` 生成的副本 |
| 滚动入场动画全停在初始态 | 无头环境下视口内交叉检测不触发 | 分段真实滚动再截，或在验收版里关掉入场动画 |

**判读**：越界元素列表已经排除了处在横向滚动容器里的元素；页面整体 `scrollWidth` 等于 `clientWidth` 才是没溢出的真判据。手机上溢出，第一个怀疑网格子项缺 `min-w-0`。

看图时逐页对照页面层的「本页节奏」和每个区块的元素清单，留意三类布局问题：卡片被拉伸留白、小徽标被拉长、文字互相压住。

## 四、看交互状态 `shoot-states.mjs`

静态截图只拍得到页面初始的样子。报错提示、提交中与提交成功、详情抽屉、手机菜单、筛选后的空结果，都要先点一下才会出现。这个工具在无头浏览器里按脚本点出这些状态，再按元素或视口截图。

每个项目在工具的「按项目改这里」段落里写几条状态，一般五到十张：表单报错态、表单成功态、抽屉或弹层（桌面与手机各一张）、手机菜单、一个带筛选的空结果、一个计算器的越界结果。

## 五、点一遍 `probe.mjs`

截图看不出交互对不对。探针在无头浏览器里逐页真实点击并断言，几十秒跑完。每打开一页都会收集运行时异常和 console.error（含首屏渲染与浏览器不一致的告警），有就记一条失败。

**每个项目要自己写断言**，照页面层末尾的「交互检查表」写，一页两到七条：

- 筛选器：点两个条件，结果数应该等于从单测算出的那个具体数字
- 受控输入：填入一个值，输入框和联动字段应该变成对应的值
- 多选上限：选满后第 N+1 个应该禁用
- 排序与翻页：翻到第 2 页，范围应该是「21–40」
- 表单：空表提交的错误数、某个格式错误的原文、走完全流程的成功编号
- 分支状态：条件不同，结论文案应该是规格写好的那几句之一

断言要写**具体的值**，不要写「有内容」。`187` 和 `58` 这种数字能验出公式算错，「非空」验不出。

给受控输入赋值要用原型上的 value setter 再派发 input 与 change 事件，直接改 `value` 属性框架感知不到。给 SVG 元素派发点击用 `dispatchEvent(new MouseEvent("click", { bubbles: true }))`。

## 修复

发现的问题**攒成一份带位置的修复任务书派一路**，不要边看边自己改。同类问题可能散在多个文件（比如网格子项缺 `min-w-0`），就在那一条里要求修复路全站排查，并限定只准加哪一个类。

例外是一行的公共文件改动（关一条 lint 规则、给某个共享组件补一个类），自己改比写任务书快，但要记进实验记录的「主控介入」计数——这个数字一直高，说明规格写得不够细。

修完重跑五件事。实测修复一轮后门禁、29 项交互检查、四页双端溢出实测全部通过。
