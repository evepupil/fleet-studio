# 实测记录

三次真实跑通的记录，用来判断这套流程值不值、规模大概多大。

## 一、Gemini 4 Pro 发布页（2026-09-21）

**输入**：一句提示词，点名一个组件库 + 「写个大模型发布 landing page，要求炫酷」+ 「你只负责需求、设计和验收，别自己写代码」。

**做法**：主控（顶级模型）3 分钟后开始写规格，96 秒写完 15.7 KB 的 DESIGN.md，一行代码没写；9 路外包苦工并行实现 9 个区块；主控读代码验收。

**结果**：用户满意。墙钟 82 分钟。

| 事项 | 数字 |
|---|---|
| 派活 | 22 次，13 次有效产出 |
| 第一波 | 9 路死 7 路（苦工把工具调用轮次烧在防御性检查上，被服务端掐断） |
| 收紧后 | 7 路成 6 路 |
| 主控介入 | 5 次，其中 3 次是改任务书而非改代码 |
| 验收抓到 | 4 处「编译过但看着错」的缺陷 |

**第一波为什么死**：苦工跑去依赖目录里确认图标存不存在、反复列目录、最后还要自己跑类型检查和构建。修法三条——把要查的东西提前写进任务书（图标白名单、颜色类名、动画类名）、收走自检权只留类型检查、降低推理档位。

**一致性数据**（9 个互相看不见的会话，产出像一个人写的）：

| 指标 | 数字 |
|---|---|
| 同一条缓动曲线出现的文件数 | 17 |
| 入场动画统一参数出现次数 | 18 |
| 区块标题统一模式出现次数 | 8 |
| 品牌色 | 4 个 |

## 二、Tackle Atlas 渔轮参数库首页（2026-09-23）

**背景**：同一个产品的首页曾经用减法流程做过一版，用户打 1 分——「装饰挤占数据就删」「不做大图 Hero」，页面规格只有三行，做出来只有三块。这次用加法配方重做，控制变量是同一批真实数据。

**结果**：10 个区块，门禁全过，真实浏览器里交互 9/9 全对。

## 三、澄湾马拉松官网 4 页（2026-09-23，规模放大实测）

**背景**：前两次都是单页、10 个区块以内。这次故意放大：虚构的城市马拉松官网，首页、赛道、报名、往届成绩 4 页，页面类型混合（首页偏营销、赛道偏数据图、报名偏表单、成绩偏查询工具）。记录在 `C:\code\ui-studio\_实验记录\ui-build大场景-2026-09-23\`，产物在 `C:\code\chengwan-marathon`。

**做法**：Sonnet 调研员先实际打开 5 个真实马拉松官网；主控写数据层（代码 + 单测）和站点层，站点层一写完就派地基；地基跑的同时主控逐页写页面层；9 路按页面分路并行；验收后一轮修复。

**结果**：34 个区块 + 顶栏页脚，11 路苦工全部一次成功、零冲突；29 项交互检查首跑全过；看图抓出 11 处问题（两处手机横向溢出），一轮修完。用户看截图的评价是「看着还行」。

| 事项 | 数字 |
|---|---|
| 数据层 | 主控直接写 2,410 行数据代码 + 32 条单测（含 3 届约 6.8 万条成绩的生成器、配速推算、报名校验），约 30 分钟 |
| 规格 | 站点层 46 KB 约 20 分钟；四页页面层 120 KB 共 16 分钟，与地基路同时进行 |
| 装依赖 | 复用锁文件离线安装 20 秒 |
| 派活 | 11 路：1 地基（18 分钟）+ 9 区块并行（10.1～26.5 分钟）+ 1 修复（5.2 分钟），一次全成 |
| 苦工 token | 地基 21 万 + 区块 181 万 + 修复 16 万，另有调研 16 万 |
| 主控介入业务代码 | 1 次，一行（共享圆点缺 `inline-block`） |
| 修复轮 | 1 轮 11 项：2 处网格子项缺 `min-w-0` 导致手机溢出、地图边缘硬线、两张卡被拉伸留白、徽标被拉长、坐标轴末端标签被截、两个标签重叠、SVG 缺焦点样式、两处写死的数字、窄色块被内边距撑宽 |
| 墙钟 | 实际工作约 133 分钟（中间会话暂停约 2 小时不计） |
| 产出代码 | 组件 6,874 行 + 数据层 2,410 行 |
| 导出 HTML | 首页 326 KB、赛道 364 KB、报名 209 KB、成绩 200 KB |

**放大后必须改的四处**（事前预测，全部应验）：规格拆成站点层 + 页面层；数据多且带计算时主控直接写代码加单测；地基与页面层并行；验收工具换成多页版。

**苦工回报里「拿不准的点」抓到的规格错误**：地图标记去掉了默认轮廓线却没给焦点样式；同一元素写了两个同类间距；几处没写对齐方式的地方被合理补齐。

## 三次都成立的结论

1. **产出丰不丰满，取决于规格里摆了多少东西。** 三次的苦工档次和规模不同，产出的丰满程度都由规格决定。
2. **苦工不会自己发挥，也不会漏元素。** 三次都没有出现苦工按自己审美删减的情况，前提是任务书里明写「规格里写了的元素一个都不能少」。反过来，规格里的笔误也会被照抄。
3. **一致性来自单一事实来源加写入边界。** 9 路互相看不见的会话，靠同一份站点层和文件归属表，产出零冲突且风格统一；数字一致靠数据写成代码。
4. **验收必须看图和点一遍。** 三次抓到的缺陷全部是构建不报错的类型；布局类问题只有设备仿真截图抓得到。
5. **主控介入次数是规格质量的体温计。** 介入多，说明规格没写细，问题不出在苦工身上。
6. **规格可以分层，但要由同一个人写完。** 分层让地基提前开工、让每路只读自己那页；拆给多人写会各写各的。

## 什么时候不适用

- 单个小组件、改一行样式：直接改，不用这套。
- 页面类型完全没有参照可循的新形态：先找参照或先做视觉探索，参照缺位时站点层第 0 章就立不住。
- 需求还没定：先走 `info-design`，别用满稿规格去替用户决定产品该有什么。
