# 前端设计：怎么定方向、文档写什么

有界面的项目，第一次写界面之前做。纯后端、命令行工具、库跳过。

## 第一轮：调研，然后挑方向

1. **禁止凭空设计。** 先看三到五个同类产品、竞品或公认做得好的站点的真实界面（派侦察苦工或强模型子代理，只记实际打开看到的，打不开的写「未能访问」）。每个都要说得出名字和好在哪：版式怎么分区、留白多大、用几个颜色、字体什么调性、刻意没做什么。凭感觉设计出来的一定是模板货。
2. 调研结论先给用户看一次，用户砍掉不想要的。
3. 用 `imagegen` skill 出**同一个核心页面**的 2～3 个不同视觉方向，每张配一句「借鉴了谁、这一版赌的是什么」，让用户挑。一次出五张同一风格的不同页面没有意义：用户只能回答行或不行，挑不了方向。

## 第二轮：铺开

- 方向定了，把选中那版的视觉描述逐字复制，批量生成其余主要页面，每页一张，通常三到五张够用。这一轮是验证同一套视觉在各类页面上都立得住，不再挑方向。
- 示意图放 `docs/前端设计/示意图/`。

## 然后写 `docs/前端设计.md`

示意图定调性，文档定能照着做的规格，两者不能互相替代。用户挑定方向后才写。

顶部写：一句话视觉方向、参考来源（站点名 + 借鉴了什么）、对应代码目录、当前状态、最近更新。

正文至少覆盖，目标是不看代码也能照着还原出界面：

- **设计令牌**：主色、中性色阶、语义色（成功 / 警告 / 错误）、字族和字号阶梯、间距阶梯、圆角、阴影。**必须给具体值**，写成 `#0B0C0E`、「4px 为基准的间距阶梯」、`14/16/20/28` 这种能直接落地的数字；「偏冷的克制风格」等于没写。
- 明暗两套主题的色值对应
- 布局与响应式断点（页面在哪些宽度切换排版）
- 基础组件的六种状态：默认、悬停、按下、禁用、加载、错误
- 空状态、加载状态、错误状态的统一画法
- 动效：时长与缓动
- 无障碍底线：正文对比度不低于 4.5:1、键盘能操作、焦点看得见
- 落地方式：令牌放在哪（CSS 变量、Tailwind 配置或主题文件），并列出实现它的前端模块文档，两边互相链接

之后改令牌、加组件、换主题、调断点，同步改这份文档；文档和代码对不上时以代码为准，立即修正。界面实现和文案的硬规矩见 `fleet-ui-build`。
